# F10 基础播放控制与真实播放服务

## Goal

让用户能够在浏览器工作台与 Tauri 桌面端真实试听当前支持的乐谱内容，并通过同一播放会话使用可停靠传输控件、空格键和独立谱面播放头。

## Requirements

- 播放必须来自权威 Core 快照，不得从 VexFlow DOM、谱面几何或 React 显示状态反推音乐数据。
- 浏览器 TypeScript 宿主与 Tauri/Rust 宿主必须从同一次文档读取生成等价、带文档版本的播放源投影。
- 第一版支持单谱表、单声部、单音、休止符、基础与单附点时值、初始 BPM 和乐器移调。
- 播放计划使用精确分数累计音乐时间，只在音频调度边界换算为秒。
- 不足拍小节保留名义静音；超拍小节按实际时值延长，不丢弃或重叠后续事件。
- 播放、暂停、继续、停止和定位由一个可订阅的播放会话管理；旧调度在停止、重播、换文档或版本变化后不得继续回调。
- 第一版使用 Web Audio 真实发声，并允许以后替换为原生执行端而不修改 UI 插件合同。
- 传输控件提供停止、上一事件、播放／暂停、下一事件与紧凑时间位置；没有真实服务的循环、节拍器、试听速度和音量不得以假按钮出现。
- 播放组件与其他工作台组件使用同一布局服务，可移动到上、下、左、右共享停靠区并持久化。
- 播放会话只依赖可替换的输出后端合同；内置合成器、采样音源／SoundFont 与 MIDI Out 后端不得反向污染 UI 插件或乐谱 Core。
- `Space` 与按钮调用同一命令；文本输入、菜单和对话框拥有焦点时不得触发播放。
- 播放头拥有独立的视觉语义，不复用编辑方框、选择框、悬停反馈或规则警告。
- 音频激活、设备不可用、计划不支持等情况使用准确的本地结构化诊断，不出现“网络中断”。
- 文档编辑、撤销、重做、打开或新建乐谱时，旧版本播放必须停止并失效。
- 第一版不实现和弦、多声部、连音线、反复、速度变化、力度、奏法、音色库、混音、循环、节拍器和音频导出。

## Acceptance Criteria

- [x] 浏览器和桌面宿主针对同一文档生成语义等价、版本一致的播放源投影。
- [x] 播放计划测试覆盖基础与附点时值、休止、移调、不足拍、超拍和文档版本变化。
- [x] 实际扬声器能够听到当前支持内容，不以计时动画冒充播放。
- [x] 暂停后从当前位置继续；停止后立即取消声音，旧回调不能恢复播放状态或推动播放头。
- [x] 当前选择或编辑位置可以成为播放起点，停止后编辑状态保持可用。
- [x] 传输按钮和 `Space` 始终操作同一播放会话，并且在输入框、菜单和对话框中不误触发。
- [x] 播放期间操作音符控制、缩放、停靠区和窗口焦点不会让音频时钟假性暂停。
- [x] 播放头在缩放、滚动和重新排版后仍对应正确事件，并与编辑光标清楚区分。
- [x] 正常和窄窗口中，高频传输控件保持可见、可点击且没有多余文字；时间位置可以在空间不足时收起。
- [x] 播放组件可以移动到四边共享停靠区，位置入口始终可用，移动后布局保持完整。
- [x] 音频失败进入可恢复状态并生成明确诊断码；UI 不显示网络相关文案。
- [x] Workbench 测试、生产构建、桌面 Rust 检查及浏览器真实交互回归全部通过。
