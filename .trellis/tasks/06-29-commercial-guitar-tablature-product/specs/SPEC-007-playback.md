# SPEC-007 播放校对

## 状态

- 状态: 已确认 MVP 最小播放校对。
- 来源需求: `REQ-005-playback-practice.md`。
- 适用范围: 第一阶段 4 小节标准 6 弦吉他 riff 的播放校对。

## 目标

播放系统必须让用户在写谱后检查基础节奏、音高和输入错误。MVP 不追求真实音源、练习系统或 DAW 能力。

## MVP 能力

- 从 `ScoreDocument` 快照生成播放事件。
- 播放 4 小节标准 6 弦吉他单轨谱面。
- 支持 4/4、固定 tempo、单 voice、四分/八分/十六分、基础休止和单音播放。
- 支持开始、暂停、继续和停止。
- 支持播放光标或当前 beat/note 高亮。
- 支持节拍器开关。
- 支持基础速度控制。第一阶段可使用 50%、75%、100% 或等价倍率集合。
- 使用基础合成音色或占位吉他音色。
- 带有 3 个 Core Loop 技巧的谱面可以播放，技巧音色可简化。

## 强制规则

- 播放层只读文档快照，不得直接修改 `ScoreDocument`。
- 播放层读取谱面必须遵守 `SPEC-014-kernel-snapshot-events.md`，通过只读 snapshot 或 selector 生成播放事件。
- 播放、暂停、继续、停止、速度变化和节拍器开关不得创建 undo/redo 命令。
- 播放事件必须从领域模型生成，不得从 SVG、VexFlow 对象或 React 组件状态反推音乐语义。
- 播放光标必须通过稳定领域 ID 或布局 primitive ID 映射，不得依赖 VexFlow 内部对象作为唯一真相。
- 播放失败不得导致文档脏状态变化。
- 文档在播放期间被编辑时，MVP 可以停止播放并要求重新播放，不要求热更新播放队列。
- Core Loop 技巧第一阶段可以近似播放或无特殊音色差异，但不得丢失、删除或改写技巧数据。

## 播放事件字段

每个播放事件至少包含:

- `id`: 稳定播放事件 ID。
- `sourceId`: 来源领域对象 ID，例如 note、beat、measure 或 metronome tick。
- `trackId`: 轨道 ID。
- `startTime`: 事件开始时间。
- `duration`: 事件持续时间。
- `kind`: `note`、`rest`、`metronome` 或 `sync`。
- `pitch`: 音高信息；休止或同步事件可为空。
- `displayTargetId`: 可选显示同步目标 ID。

## MVP 不做

- 不做真实采样音色。
- 不做音频轨、录音或视频同步。
- 不做音频导出。
- 不做多轨混音。
- 不做 track mute/solo 作为第一阶段验收门槛。
- 不做循环、count-in、虚拟指板播放显示作为第一阶段阻塞项。
- 不做 DAW、VST 或第三方音源宿主。
- 不做附点、三连音、跨小节延音线、多声部同轨、变拍号或小节级 tempo 变化作为第一阶段播放验收门槛。
- 不做同 slot 多音、和弦、扫弦或琶音播放作为第一阶段验收门槛。

## 测试要求

- 给定 4 小节标准 6 弦吉他 fixture，播放事件生成结果必须稳定。
- 同 slot 多音或和弦输入必须先被验证器拒绝，不得进入第一阶段播放事件生成。
- 带有 `slide`、`bend`、`vibrato` 的 fixture 必须能生成播放事件。
- 播放事件生成不得修改输入文档快照。
- 速度倍率变化后，播放事件相对节奏必须保持一致。
- 节拍器开关必须只影响 metronome 事件或播放输出，不得修改谱面文档。
- 播放光标映射必须能从播放事件回到稳定的领域对象或布局 primitive。
