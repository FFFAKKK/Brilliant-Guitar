# 原生文件格式候选对比

## 当前路线注记

用户已确认近期先全部做开源，不做商业化、闭源增强、收费功能、许可证校验、订阅或付费插件。本文中关于商业曲库、文件锁、授权内容包和商业保护层的内容只作为历史方案对比，不是当前需求或近期路线。

## 决策背景

用户希望原生文件体验类似 Guitar Pro 8。这里需要区分两个层面:

- 用户体验层: 像 Guitar Pro 一样是一个可双击打开、可分享、可备份的专属单文件。
- 工程实现层: 是否采用私有、不透明、接近二进制的内部格式。

官方资料能确认 Guitar Pro 把 `.gp`、`.gpx`、`.gp5` 等文件格式作为导入导出能力的一部分，但没有公开 GP8 内部文件结构规范。因此，本项目不应以“照搬 GP8 内部格式”为需求，而应决定是否采用“GP8 式单文件体验”。

## 候选 A: GP8 式私有单文件格式

定义:

- 文件对用户表现为一个专属扩展名，例如 `.bgp` 或 `.brguitar`。
- 内部结构不公开，可能是二进制、压缩包、数据库、protobuf、自定义块格式或混合格式。
- 用户和第三方工具默认不能直接读写内部结构。

优点:

- 商业软件感强，用户感知更接近 Guitar Pro。
- 更容易把文件视为应用专属资产，减少普通用户误改内部文件。
- 二进制或块结构可以更紧凑，读取局部数据和缓存可能更快。
- 便于未来做文件锁、授权内容包、商业曲库和防篡改校验。
- 可以隐藏内部模型演进，避免早期 schema 被外部生态过早绑定。

缺点:

- 调试困难，AI 生成、单元测试、golden file 对比和人工排查成本更高。
- 文件损坏后的恢复能力较弱，用户资产安全风险更高。
- 插件生态和第三方工具更难发展，和“更可扩展、更开放”的产品差异化有冲突。
- 迁移成本高，早期模型设计错误会被私有格式放大。
- 导入导出兼容报告更难做细，因为内部数据不可读不可解释。
- 如果试图兼容或模仿 GP8 私有结构，会引入逆向、法律和维护风险。

适合场景:

- 产品主要靠封闭商业曲库、授权内容、格式壁垒和官方软件体验变现。
- 插件生态不作为早期核心差异化。
- 团队有足够工程资源维护格式解析、迁移、恢复和诊断工具。

## 候选 B: GP8 式单文件体验 + 开放包结构

定义:

- 对用户仍然是一个专属扩展名单文件，例如 `.bgscore`、`.bgp` 或 `.brguitar`。
- 物理形态建议为 zip 包或等价容器。
- 内部包含 `manifest.json`、`score.json`、`assets/`、`preview/`、`extensions/` 等结构。
- 核心谱面语义使用版本化 JSON 或未来可迁移的结构化格式。

优点:

- 用户体验仍然像 GP8: 一个文件、双击打开、可分享、可备份。
- 内部结构可验证、可迁移、可调试，适合当前 AI 辅助开发。
- 容易做 schema version、迁移器、文档验证器和兼容报告。
- 文件损坏时更容易部分恢复，例如只恢复 `score.json` 或资源目录。
- 天然支持图片、音频、缩略图、插件私有数据和未来资源包。
- 插件生态更容易设计，未知插件数据可按命名空间保留。
- 不需要逆向 GP8 私有结构，法律和工程风险更低。

缺点:

- 如果不做签名、校验和严格验证，用户或第三方工具可能改坏文件。
- JSON 体积通常大于紧凑二进制，需要压缩、缓存或后续二进制块优化。
- 早期需要更认真设计 schema，否则开放结构会暴露模型不稳定。
- 商业曲库和文件锁需要额外设计加密、签名或授权层。
- 大文件场景下需要避免每次保存都全量重写导致性能问题。

适合场景:

- 产品差异化是模块化、插件、AI 友好、可迁移和长期可扩展。
- MVP 阶段需要高可测试性、高可恢复性和快速迭代。
- 后续仍希望保留商业文件体验和专属扩展名。

## 候选 C: 双层策略

定义:

- 第一阶段采用候选 B，文件体验像 GP8，但内部是开放包结构。
- 后续商业版本可以增加可选保护层，例如签名、加密内容包、只读发行谱、授权资源包。
- 高性能数据可逐步从 JSON 拆出为二进制缓存或增量块，但核心语义仍以可迁移 schema 为准。

优点:

- 同时保留商业产品感和工程可控性。
- 不把 MVP 绑死在过早私有格式上。
- 后续如果确实需要付费曲库、文件锁、商业内容分发，可以在包层增加保护，而不是重写核心模型。

缺点:

- 需要在 spec 中明确哪些内容是核心语义，哪些只是缓存或商业保护层。
- 比纯 JSON 文件复杂，比纯私有格式更克制，团队必须坚持边界。

## 用户决策

已确认选择候选 B: GP8 式单文件体验 + 开放包结构。

产品表述:

> 原生文件采用 `.bgp` 扩展名和 GP8 式单文件体验，但内部使用可验证、可迁移的开放包结构。第一阶段不追求照搬 Guitar Pro 私有格式，也不做私有黑盒文件。项目先开源验证效果，开放包结构优先服务测试、迁移、插件生态和社区反馈。

扩展名已确认采用 `.bgp`，含义为 `Brilliant Guitar Project`。产品名暂定 `Brilliant Guitar`。

## 已解决决策

- 原生扩展名: `.bgp`。
- 产品名: `Brilliant Guitar`。
