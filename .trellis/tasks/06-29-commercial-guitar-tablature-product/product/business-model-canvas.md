# 开源产品画布

## 状态

- 状态: 草案
- 作用: 用产品经理视角约束 PRD，不让功能清单脱离用户价值、开源采用和长期维护目标。
- 当前确认: MVP 优先服务基础创作、编辑、编曲工作流。
- 相关文档: `product/product-manager-workflow.md`, `product/value-proposition-canvas.md`

## 1. 客户细分

### MVP 核心客户

- 专业/半专业吉他手: 需要高效记录 riff、solo、练习段落和完整作品。
- 吉他教师: 需要制作课程谱、练习谱、分级材料和学生作业。
- 编曲者: 需要多轨结构、乐队排练材料和可播放的编曲草案。
- 内容创作者: 需要输出可发布的谱面、图片、PDF、视频素材或互动材料。

### 暂不作为 MVP 核心客户

- 零基础练琴用户。
- 只消费谱库的用户。
- DAW 重度制作用户。
- 交响乐/出版级全乐器制谱师。

## 1.1 早期采用者

推荐第一批验证对象:

- 每周持续写谱或改谱的吉他教师。
- 有原创/改编需求的半专业吉他手。
- 经常制作 Bilibili/YouTube 吉他内容的创作者。
- 需要乐队排练材料的编曲者。

不推荐第一批验证对象:

- 只找谱练歌、不写谱的人。
- 只需要 DAW 音频制作的人。
- 只需要移动端碎片练习的人。

## 2. 价值主张

- 更快的吉他谱输入: 键盘优先、命令面板、批量编辑和鼠标辅助定位；指板输入后置。
- 更清晰的编曲模型: 多轨、段落、重复、速度、调弦和技巧结构化。
- 更开放的扩展能力: 插件、命令、导入导出、脚本化工作流。
- 更可靠的文件资产: 本地离线、可迁移、可验证、可恢复。
- 更适合专业交付: 可导出、可打印、可教学、可长期维护。

## 2.1 价值主张优先级

MVP 价值主张排序:

1. 创作编辑效率。
2. 谱面结构准确性。
3. 六线谱与基础五线谱同步。
4. 吉他功能完整度。
5. 文件可靠性。
6. 播放校对能力。
7. 导入导出互操作。
8. 内部扩展点。
9. 后续插件生态。

解释:

- 第一版必须先让用户愿意把它当作主编辑器。
- 第一版先证明“吉他谱能写得准、看得清、改得快、存得稳”。
- 插件生态是战略差异化，但不能替代基础编辑体验。
- 产品吸引力应先围绕“更高效、更可靠、更可扩展”。

## 3. 渠道

- 独立官网: 下载、文档、路线图、更新日志。
- 内容渠道: Bilibili、YouTube、小红书、抖音等演示工作流。
- 教师渠道: 吉他教师、培训机构、课程创作者。
- 开发者渠道: 插件文档、示例插件、GitHub 社区。
- 乐队/编曲渠道: 编曲案例、排练材料模板、谱面模板。

## 3.1 开源优先验证策略

- 第一阶段先开源验证产品方向、编辑体验、文件格式、插件边界和社区兴趣。
- 开源协议采用 Apache-2.0。
- 外部贡献治理采用 DCO。
- 开源内容应包含核心编辑器、原生文件 spec、测试谱库、导入导出报告机制和内部插件示例。
- 近期不规划商业化、闭源增强、收费功能、许可证校验、订阅或付费插件。
- 开源不等于放弃品牌治理；需要从第一天区分代码许可证、品牌商标、官网、官方构建和 fork 命名边界。

## 4. 客户关系

- MVP: 本地软件 + 文档 + 示例谱 + 反馈渠道。
- 开源阶段: GitHub issue、讨论区、路线图、贡献指南、公开文件格式 spec。
- 毕业设计阶段: 演示脚本、测试报告、用户手册和可复现样例。
- 社区阶段: 插件开发文档、内部插件示例、问题模板和诊断包。

## 5. 可持续性来源

当前顺序:

- 第一阶段: 开源免费版本 + 毕业设计交付 + 真实用户反馈。
- 第二阶段: 社区贡献、issue、示例谱、插件示例和文档改进。
- 第三阶段: 长期维护声誉、作品集价值、技术沉淀和开源影响力。
- 后续商业化: 当前不规划；如未来重新评估，必须作为独立新阶段重新设计。

## 5.1 MVP 开源验证

推荐验证路径:

- 发布可运行 Windows MVP。
- 提供示例谱、测试谱库、用户手册和演示视频。
- 访谈教师、创作型吉他手、编曲者和内容创作者。
- 用 issue、讨论、演示反馈和真实谱面样例验证产品价值。
- 云同步、AI 转写、插件市场、付费插件和授权系统不进入近期路线。

第一版不做收费:

- 本项目当前最重要的是开源验证、毕业设计和长期维护基础。
- 收费、订阅和许可证校验会增加账号、支付、隐私、发行和支持复杂度。
- 核心编辑器未成熟前，不应让商业系统干扰文件格式、命令系统、插件 API 和质量门禁。

## 6. 关键资源

- 领域模型和文件格式。
- 谱面编辑器和渲染引擎。
- 播放和练习引擎。
- 导入导出能力。
- 插件 API 和命令系统。
- 竞品迁移路径。
- 高质量示例谱和测试谱库。

## 7. 关键活动

- 打磨核心编辑体验。
- 建立文件格式和迁移策略。
- 建立自动化测试谱库。
- 建立导入导出兼容矩阵。
- 建立插件 API 版本策略。
- 建立开源发布、版本号、更新日志、诊断和 Windows 打包流程。

## 7.1 产品验证活动

- 访谈 5 到 10 名吉他教师。
- 访谈 5 到 10 名创作型吉他手。
- 收集 20 个真实谱面样例，覆盖 riff、solo、完整歌曲、教学练习、乐队编曲。
- 用竞品完成同样任务，记录输入步骤、痛点和导出结果。
- 形成 MVP 验收谱库。

## 7.2 毕业设计验证活动

- 将第一阶段范围控制为可答辩的 `Guitar Core Loop`。
- 输出需求分析、总体设计、详细设计、测试报告、用户手册或演示说明。
- 演示重点放在新建谱面、六线谱输入、基础五线谱同步、P0 技巧、保存打开、PDF/PNG 导出。
- 论文论证重点放在领域模型、命令系统、开放文件格式、模块化架构和测试验证。

## 8. 关键伙伴

- 吉他教师和课程创作者。
- 专业吉他手和编曲者。
- 音色/采样资源提供方。
- 开源制谱、音频、MIDI 生态。
- 插件开发者。

## 9. 成本结构

- 核心编辑器研发成本。
- 跨平台桌面打包和签名成本。
- 音色、采样或字体授权成本。
- 测试谱库和兼容性维护成本。
- 客服、文档、教程和社区维护成本。
- 未来云服务和账号系统成本当前不纳入近期计划。

## 开源产品画布验收标准

- [ ] 每个 MVP 功能都能映射到至少一个价值主张。
- [ ] 每个非 MVP 后置能力都能映射到明确客户细分。
- [ ] 不把云同步、曲库、AI 转写、插件市场提前塞入 MVP，除非它们服务基础创作编曲主线。
- [ ] 第一版不做收费、登录、许可证校验、订阅或闭源增强。
- [ ] 早期验证对象能覆盖教师、创作型吉他手、编曲者和内容创作者。
