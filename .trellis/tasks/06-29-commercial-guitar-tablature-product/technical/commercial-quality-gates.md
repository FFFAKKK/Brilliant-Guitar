# 商业级工程流程与质量门禁

## 状态

- 状态: 草案
- 作用: 将“开源项目按商业软件流程建设”转化为实现前、实现中和发布前的工程门禁。
- 相关需求: `REQ-010`, `REQ-013`, `REQ-014`, `REQ-015`, `REQ-016`

## 核心原则

- 开源是发布与协作方式，不是降低质量的理由。
- 长期维护是项目原则，必须从始至终一直执行。
- 毕业设计版本是长期产品的第一个可维护版本，不是一次性 demo。
- 商业级软件首先保护用户作品，其次才是功能数量。
- 每个核心能力必须可测试、可诊断、可恢复、可维护。
- 质量门禁必须写进实现计划，不能只停留在口号。

## 阶段流程

### 1. 需求门禁

通过条件:

- 功能能映射到 `REQ-xxx` 文档。
- MVP 必做、后置、不做边界明确。
- 有验收标准和失败场景。
- 有用户价值和质量属性映射。

不得进入实现的情况:

- 只有功能名，没有行为契约。
- 未声明数据安全、错误处理或回滚方式。
- 与第一阶段范围冲突，例如提前暴露 7/8 弦、云账号或第三方插件安装。

### 2. 设计门禁

通过条件:

- 模块边界明确。
- 数据流明确。
- 失败路径明确。
- 测试策略明确。
- 与文件格式、命令系统、领域模型和插件边界兼容。
- 明确长期维护影响，包括 schema、fixture、迁移、版本兼容和废弃策略。

必须覆盖:

- 文件打开、保存、迁移、自动保存和崩溃恢复。
- 编辑命令、undo/redo 和命令回放。
- 渲染、播放、导入导出和 i18n。
- 诊断包、安全边界和依赖许可。

### 3. 实现门禁

通过条件:

- TypeScript strict 模式通过。
- lint/format 通过。
- 单元测试通过。
- 核心集成测试通过。
- 新功能有 fixture 或 golden file。
- 错误消息可读。
- 关键路径没有绕过领域模型或命令系统。
- 没有以 MVP、毕设或演示为理由绕过长期维护规则。

### 4. 安全门禁

检查项:

- 外部谱面文件按不可信输入处理。
- 导入器不执行外部脚本或任意路径引用。
- 插件 manifest 不获得默认高权限。
- 诊断包默认不包含用户谱面正文。
- 第三方依赖许可证与 Apache-2.0 和开源分发兼容。
- 文件路径处理避免目录穿越和覆盖非目标文件。

### 5. 性能门禁

第一阶段至少建立以下基准:

- 打开示例谱。
- 保存示例谱。
- 连续输入和撤销重做。
- 播放光标跟随。
- PDF 导出。
- PNG 导出。

基准必须记录:

- 测试平台。
- 谱面规模。
- 操作步骤。
- 结果时间或体验结论。
- 是否阻塞发布。

### 6. 发布门禁

发布前必须完成:

- 版本号。
- 更新日志。
- 已知问题。
- 兼容性说明。
- schema version 和迁移说明。
- 第三方许可清单。
- Apache-2.0 license。
- DCO 贡献说明。
- 安装、启动、保存、打开、导出演示检查。
- 回滚或恢复说明。

## 质量矩阵

| 质量属性 | 主要风险 | 验证方式 |
| --- | --- | --- |
| 健壮性 | 非法谱面、损坏文件、异常命令导致崩溃 | 验证器测试、损坏文件测试、命令回放 |
| 安全性 | 外部文件、插件、诊断包泄露或越权 | 安全检查、权限测试、诊断包检查 |
| 高效性 | 编辑卡顿、导出假死、播放光标不稳 | 性能基准、端到端演示 |
| 可靠性 | 保存失败损坏用户作品 | 原子保存测试、自动保存恢复测试 |
| 可维护性 | 模块耦合导致后续扩展困难 | 架构评审、依赖方向检查 |
| 可测试性 | 核心逻辑只能靠 UI 手测 | 单元测试、fixture、golden file |
| 可发布性 | 缺少许可、版本、诊断、安装验证 | 发布清单 |
| 可演进性 | 升级后打不开旧谱或破坏扩展边界 | schema fixture、迁移测试、兼容矩阵 |

## 第一阶段最低发布准入

- 完成 `Guitar Core Loop` 演示闭环。
- 完成 Apache-2.0 + DCO 开源仓库基础文件。
- 完成原生开放文件格式 spec。
- 完成 schema version、1.x 兼容承诺和至少一个文件兼容 fixture。
- 完成保存、打开、自动保存和损坏文件处理测试。
- 完成 P0 技巧最小测试谱库。
- 完成 PDF + PNG 导出验证。
- 完成 Windows 平台安装、启动、文件关联、保存、打开、自动保存恢复、PDF/PNG 导出和诊断包导出演示验证。

## 后续需要细化

- 性能阈值具体数字。
- CI 平台和检查命令。
- 发布版本命名规则。
