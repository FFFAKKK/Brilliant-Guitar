# REQ-013 开源协议、贡献治理与品牌边界

## 决策状态

- 状态: 开源协议、贡献模式和不商业化路线已确认
- 合并目标: 最终 PRD 的开源发布、社区治理和品牌边界要求
- 已确认决策: 第一阶段采用 Apache-2.0
- 已确认决策: 第一阶段采用 DCO，不使用复杂 CLA
- 已确认决策: 先全部做开源，近期不做商业化、闭源增强、收费功能、许可证校验、订阅或付费插件

## 用户价值

项目先全部开源验证效果，能更快获得真实吉他手、教师、开发者和插件作者反馈。开源策略必须服务产品验证和长期维护，而不是让项目变成授权边界混乱、难以协作的代码堆。

## 产品原则

- 开源优先验证: 第一阶段用开源降低试用、反馈和贡献门槛。
- 品牌边界清晰: 代码开源不等于品牌、商标、官方构建和官网身份自动开放。
- 用户资产自由: 当前不做商业授权；未来任何授权机制也不得锁死用户自己的本地谱面文件。
- 贡献权属清楚: 在接受外部代码前，必须明确贡献声明、版权归属和许可兼容方式。
- 依赖合规: 第三方库、字体、音色、示例谱、图标和测试资源必须有可追踪许可证。

## MVP 必须满足

- REQ-013-F01: 仓库根目录必须包含 Apache-2.0 `LICENSE` 文件。
- REQ-013-F02: 仓库必须包含版权声明，明确项目方、年份和许可。
- REQ-013-F03: 仓库必须包含 `NOTICE` 或等价第三方声明文件，用于记录需要保留声明的依赖与资源。
- REQ-013-F04: 仓库必须包含 `CONTRIBUTING.md`，说明如何提交 issue、PR、测试文件和插件示例。
- REQ-013-F05: 仓库必须包含品牌/商标边界说明，避免外部 fork 混淆为官方版本。
- REQ-013-F06: 原生文件格式 spec 必须公开，保证开源阶段用户和开发者可以验证文件结构。
- REQ-013-F07: 当前路线不得引入闭源商业增强能力、付费功能、许可证校验、订阅或付费插件。
- REQ-013-F08: 第三方依赖引入前必须检查许可证是否与 Apache-2.0 和开源分发兼容。
- REQ-013-F09: 外部贡献采用 DCO，贡献提交必须包含 `Signed-off-by`。
- REQ-013-F10: 第一阶段不要求贡献者签署 CLA；CLA 可作为未来公司化、双许可或大型生态阶段的后置策略。

## 建议开源仓库文件

- `LICENSE`: Apache-2.0 正文。
- `NOTICE`: 需要保留的版权、声明、第三方资源信息。
- `README.md`: 项目定位、状态、安装、开发、路线图入口。
- `CONTRIBUTING.md`: 贡献流程、代码风格、测试要求、issue/PR 模板。
- `DCO.md` 或 `CONTRIBUTING.md` 中的 DCO 章节: 解释 `Signed-off-by`、提交方式和检查规则。
- `SECURITY.md`: 漏洞报告方式和支持版本。
- `CODE_OF_CONDUCT.md`: 社区行为准则，若项目进入公开社区阶段再启用。
- `TRADEMARKS.md`: 项目名称、logo、官方构建和 fork 命名边界。
- `THIRD_PARTY_LICENSES.md`: 依赖、字体、图标、音色、示例谱的许可证清单。

## 品牌与不商业化边界

可以保留为项目方控制资产，用于避免外部 fork 混淆为官方版本:

- 项目名称、logo、官网域名和官方社区。
- 官方构建签名和应用商店发布权。

不得作为第一阶段策略:

- 通过私有文件格式锁死用户作品。
- 通过强 DRM 阻止用户打开自己的本地文件。
- 通过登录、付费、许可证校验、订阅、闭源模块或付费插件限制核心编辑能力。
- 未声明许可证就引入音色、字体、图标或示例谱。
- 接受外部贡献但不说明贡献许可。
- 第一阶段要求贡献者签复杂 CLA，抬高早期社区参与门槛。

## 验收标准

- [ ] AC-013-01: 仓库根目录存在 Apache-2.0 `LICENSE`。
- [ ] AC-013-02: `README.md` 明确项目当前全部开源，近期不规划商业化、闭源增强、付费功能、许可证校验或订阅。
- [ ] AC-013-03: `CONTRIBUTING.md` 说明贡献流程、测试要求和贡献许可。
- [ ] AC-013-04: `THIRD_PARTY_LICENSES.md` 或等价文件列出第三方依赖和素材许可。
- [ ] AC-013-05: `TRADEMARKS.md` 或等价说明区分官方版本与 fork。
- [ ] AC-013-06: 引入新依赖、字体、音色或示例谱时，必须在 PR 中说明许可证。
- [ ] AC-013-07: `CONTRIBUTING.md` 说明 DCO sign-off 规则，并给出 `git commit -s` 示例。
- [ ] AC-013-08: PR 检查或维护者检查能发现缺失 DCO sign-off 的提交。

## 开放问题

- 无。第一阶段开源协议采用 Apache-2.0，外部贡献治理采用 DCO。
