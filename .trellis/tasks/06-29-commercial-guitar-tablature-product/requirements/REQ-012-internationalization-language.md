# REQ-012 国际化与语言切换

## 决策状态

- 状态: 已确认方向和默认语言策略
- 合并目标: 最终 PRD 的国际化、本地化和语言切换要求
- 用户决策: 后续要支持切换语言；目前阶段可以先做中文和英文。
- 用户决策: 按商业软件方式处理默认语言，首次启动跟随系统语言；中文系统使用 `zh-CN`，其它系统使用 `en-US`；用户手动选择后保存偏好并优先于系统语言。

## 用户价值

本产品面向中文用户起步，但吉他术语、谱面生态、插件 API、导入导出格式和教学资料大量使用英文。第一阶段需要同时支持中文和英文，后续可以扩展更多语言，避免 UI 文案、技巧名称和错误提示在代码中硬编码。

## 第一阶段必须做

- REQ-012-F01: 应用必须有语言切换机制。
- REQ-012-F02: 第一阶段至少支持简体中文 `zh-CN` 和英文 `en-US`。
- REQ-012-F03: UI 文案不得直接硬编码在组件里，必须通过 i18n key 获取。
- REQ-012-F04: 吉他技巧名称必须支持中文显示名和英文术语。
- REQ-012-F05: 技巧 UI 第一阶段默认可以中文主显示，英文作为括号或 tooltip 辅助显示，例如 `推弦 (bend)`。
- REQ-012-F06: 菜单、命令面板、设置、错误提示、导入导出报告必须进入国际化资源。
- REQ-012-F07: 用户语言偏好必须可保存，并在下次启动恢复。
- REQ-012-F08: 插件 manifest 和内部命令必须支持可本地化标题和描述。
- REQ-012-F09: 默认语言解析顺序必须为已保存用户偏好、受支持系统语言、`en-US` fallback。
- REQ-012-F10: 自动化测试、导出 smoke test 和截图验证必须能显式指定 locale。

## 第一阶段不做

- 不做除 `zh-CN` 和 `en-US` 以外的其它语言包。
- 不做在线翻译。
- 不做社区翻译平台。
- 不做运行时远程下载语言包。
- 不把谱面内容自动翻译。

## 后置能力

- 更多语言包，例如日语、韩语、西班牙语。
- 社区翻译工作流。
- 插件语言包。
- 对教学模板和帮助文档做完整本地化。

## 行为契约

- 所有用户可见字符串必须有稳定 i18n key。
- i18n key 必须按功能域分组，例如 `menu.file.open`、`technique.bend.name`。
- 英文术语必须可独立于中文显示名保存，不能只拼接字符串。
- 文档模型中的技巧类型必须使用稳定技术枚举，不随 UI 语言变化。
- 导出谱面时，用户可见技巧名称使用当前语言；内部结构仍使用稳定枚举。
- 缺失翻译时必须有可预测 fallback，推荐回退到英文。
- 首次启动没有保存偏好时，应用读取系统语言；如果系统语言以 `zh` 开头则使用 `zh-CN`，否则使用 `en-US`。
- 用户在设置中手动切换语言后，保存的用户偏好必须优先于系统语言。

## 验收标准

- [ ] AC-012-01: 用户可以在设置中切换中文和英文。
- [ ] AC-012-02: 切换语言后，菜单、命令面板、技巧选择器和错误提示显示对应语言。
- [ ] AC-012-03: 技巧 `bend` 在中文界面显示为 `推弦 (bend)` 或等价中英组合，在英文界面显示为 `Bend`。
- [ ] AC-012-04: 保存文件后切换语言，不改变文档中的技巧枚举和音乐数据。
- [ ] AC-012-05: 缺失中文翻译时，系统回退到英文且不显示空白。
- [ ] AC-012-06: 首次启动且系统语言为中文时默认进入 `zh-CN`，非中文系统默认进入 `en-US`。
- [ ] AC-012-07: 用户手动选择语言并重启后，应用使用已保存偏好，而不是重新跟随系统语言。
- [ ] AC-012-08: 自动化测试可以显式指定 locale，避免因系统语言不同导致快照不稳定。

## 开放问题

- 无。第一阶段默认语言解析顺序为已保存用户偏好、受支持系统语言、`en-US` fallback。
