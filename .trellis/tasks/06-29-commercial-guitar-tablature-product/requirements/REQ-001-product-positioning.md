# REQ-001 产品定位、目标用户与开源切入点

## 决策状态

- 状态: 草案
- 合并目标: 最终 PRD 的产品目标、用户画像、范围和开源验证路径
- 关键决策: MVP 目标用户已确认；主工作流已确认

## 用户价值

目标用户需要在一个可靠、快速、专业的工具中完成吉他谱创作、修改、播放、练习材料制作和分享。产品必须让用户感觉它不是玩具编辑器，而是可以持续管理作品、教学材料和长期创作资产的生产工具。

## 推荐定位

MVP 推荐定位为:

> 面向专业/半专业吉他手、吉他教师、编曲者和内容创作者的桌面优先吉他谱创作工具。

这个定位比“面向初学者的练琴 App”更贴近用户提出的工业化、专业化打谱软件，也更容易形成稳定的文件格式、编辑器内核和扩展系统。

## 已确认主工作流

MVP 先服务基础创作、编辑、编曲。教学、练习、内容发布、云同步、谱库和插件市场都应围绕这个主线分阶段扩展，不能喧宾夺主。

## 目标用户

### MVP 主用户

- 严肃吉他手: 需要记录 riff、solo、编曲和练习段落。
- 吉他教师: 需要快速制作课程谱、练习谱、分级材料和学生作业。
- 编曲者/乐队成员: 需要多轨谱面、结构标记、排练材料和导出。
- 内容创作者: 需要把谱面导出为 PDF、图片、视频素材或可分享互动材料。

### 非 MVP 主用户

- 零基础纯练琴用户: 他们更需要课程、跟练、评分和反馈。
- 全乐器专业制谱师: 他们更需要交响乐、排版和出版级雕版能力。
- DAW 用户: 他们更需要音频录制、混音、插件宿主和工程混音。

## 核心 Jobs To Be Done

- JTBD-001: 当我听到或想到一段吉他乐句时，我想快速把它写成准确的六线谱和节奏。
- JTBD-002: 当我要教学时，我想快速生成学生能看懂、能播放、能循环练习的谱面。
- JTBD-003: 当我要和乐队协作时，我想创建多轨结构清晰、可导出、可回放的排练材料。
- JTBD-004: 当我已有 Guitar Pro、MusicXML、MIDI 或文字谱素材时，我想尽量低损导入并继续编辑。
- JTBD-005: 当软件默认功能不够时，我想通过插件、脚本或扩展格式补齐工作流。

## MVP 必须满足

- REQ-001-F01: 产品必须以“编辑和生产吉他谱”为主，而不是以“消费曲库”或“练习游戏化”为主。
- REQ-001-F02: 产品必须支持本地离线创作，打开软件后不依赖账号或网络才能编辑文件。
- REQ-001-F03: 产品必须能解释为什么比 Guitar Pro 类产品更方便: 输入效率、扩展性、开放文件结构、自动化和现代工作流至少占两项。
- REQ-001-F04: 产品必须在 PRD 中明确 MVP 用户、非 MVP 用户和后置能力。

## MVP 不做

- 不做完整在线曲库市场。
- 不做版权乐谱交易平台。
- 不做全功能 DAW。
- 不做以视频课程为中心的练琴平台。
- 不把移动端作为第一编辑平台。

## 开源验证方向

- 第一阶段全部开源，采用 Apache-2.0 + DCO。
- 先验证核心编辑体验、文件格式、渲染/导出质量和长期维护能力。
- 插件生态先做内部扩展点和 API 边界，不做插件市场或付费插件。
- 云同步、团队协作、谱库、AI 转写和在线分享后置，近期不作为商业化能力设计。

## 验收标准

- [ ] AC-001-01: 文档中明确一个 MVP 主用户群，且不超过两个主用户群。
- [ ] AC-001-02: 文档中明确至少三个不做的用户群或场景。
- [ ] AC-001-03: 文档中明确产品相比 Guitar Pro 类工具的差异化不是泛泛而谈。
- [ ] AC-001-04: 后续每个功能需求都能追溯到至少一个 JTBD。

## 开放问题

- 无。后续如果用户改变目标用户，需要重新评估开源产品画布、功能优先级和技术架构。
