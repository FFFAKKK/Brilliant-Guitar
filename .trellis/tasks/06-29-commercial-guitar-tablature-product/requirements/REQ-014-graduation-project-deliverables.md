# REQ-014 毕业设计交付边界、论文材料和答辩验收

## 决策状态

- 状态: 草案
- 合并目标: 最终 PRD 的毕业设计范围、交付物和验收边界
- 已确认决策: 本项目将作为用户的毕业设计
- 已确认决策: 暂无学校/学院特殊硬性要求，先按软件工程类毕业设计交付包准备
- 已确认决策: 长期维护是项目原则，必须从始至终一直执行；毕业设计只是第一个里程碑，不按一次性 demo 标准建设

## 用户价值

本项目既是一个长期维护的开源产品构想，也是一个必须按期完成、可演示、可写论文、可答辩的毕业设计。毕业设计范围必须可控，能体现软件工程完整流程，而不是追求 Guitar Pro 8 的全量复刻；同时它不能被做成一次性 demo，必须成为后续长期维护和产品化演进的第一个稳定基础。

## 毕业设计定位

推荐题目方向:

> 基于 Tauri 与 TypeScript 的可扩展吉他打谱软件设计与实现

可选题目方向:

- 基于开放文件格式的吉他谱编辑系统设计与实现。
- 面向吉他教学与创作的 Windows 桌面打谱软件设计与实现。
- 支持六线谱与五线谱同步的吉他打谱编辑器设计与实现。

## 毕设最小可答辩范围

毕业设计第一版应聚焦 `Guitar Core Loop`:

- 标准 6 弦吉他谱创建。
- 六线谱基础编辑。
- 基础五线谱同步显示。
- P0 高频吉他技巧结构化保存与显示。
- 原生开放包文件保存、打开和基础迁移能力。
- 播放校对的最小闭环，包括播放光标、开始/暂停和基础速度。
- PDF + PNG 导出。
- Apache-2.0 开源仓库和 DCO 贡献规则。

## 毕设不应承诺的范围

- 不承诺复刻 Guitar Pro 8 全量能力。
- 不承诺 7/8 弦吉他。
- 不承诺贝斯、鼓、键盘和完整乐队编曲。
- 不承诺云同步、账号、插件市场和 AI 自动扒谱。
- 不承诺完整 Guitar Pro 文件兼容。
- 不承诺出版级雕版排版。

## 论文材料要求

建议论文结构:

- 选题背景与意义: 吉他谱创作、教学、内容制作和现有工具痛点。
- 需求分析: 目标用户、用例、功能需求、非功能需求、范围边界。
- 系统总体设计: Tauri 桌面架构、领域模型、模块划分、数据流。
- 详细设计: 谱面文档模型、命令系统、六线谱编辑、五线谱同步、文件格式。
- 系统实现: 核心模块、关键算法、UI 工作流、导入导出、开源治理。
- 系统测试: 单元测试、集成测试、示例谱测试、导出测试、用户场景测试。
- 总结与展望: 已完成能力、不足、后续开源维护和插件生态路线。

## 演示验收脚本

答辩演示建议按以下顺序:

1. 启动应用并新建标准 6 弦吉他谱。
2. 输入 4 小节基础 riff，包含休止、单音和不同基础时值。
3. 添加 3 个 Core Loop 高频技巧: slide、bend、vibrato。
4. 展示六线谱与基础五线谱同步。
5. 播放谱面并展示播放光标。
6. 保存为原生文件，关闭后重新打开。
7. 导出 PDF 和 PNG。
8. 简要展示文件包结构、schema version、测试报告和开源协议。

## MVP 必须满足

- REQ-014-F01: 毕设实现范围必须与 `REQ-011` 的 `Guitar Core Loop` 对齐。
- REQ-014-F02: 每个核心功能必须能映射到需求文档、设计说明和测试用例。
- REQ-014-F03: 项目必须保留可答辩演示脚本，避免演示时临时组织流程。
- REQ-014-F04: 架构设计必须能解释模块化、可扩展和文件格式开放性的技术价值。
- REQ-014-F05: 论文不得把后置功能写成已实现功能。
- REQ-014-F06: 毕设答辩版本必须优先保证稳定性，而不是堆叠未完成功能。
- REQ-014-F07: 毕设交付必须体现商业软件流程，包括需求、架构、实现、测试、质量门禁、发布说明和用户文档。
- REQ-014-F08: 毕设版本的架构、文件格式和测试体系必须支持毕业后继续维护，不得为了答辩演示、进度压力或短期展示写死临时代码路径。
- REQ-014-F09: 论文可以把长期维护策略作为工程创新点之一，包括开放文件格式、版本迁移、模块化架构和质量门禁。
