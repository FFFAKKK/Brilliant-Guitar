# REQ-008 编辑器交互、快捷键与效率工作流

## 决策状态

- 状态: 已确认键盘优先方向与输入模型
- 合并目标: 最终 PRD 的核心 UX 和交互契约
- 当前结论: 第一阶段采用键盘优先输入，输入模型为“谱面光标 + 时值键 + 数字品号输入 + 弦间/拍间方向键移动 + 技巧快捷键/命令面板”；鼠标选择辅助；MIDI、虚拟指板点选输入和其它外部演奏输入后置；轨道管理不进入第一阶段。
- 关键开放问题: 无。MVP 节奏、复音、技巧数量和轨道管理边界已收敛。

## 用户价值

打谱软件的商业价值很大程度来自输入效率。用户需要在灵感、转写和教学材料制作时快速完成大量重复动作。

## 推荐编辑器布局

- 顶部: 菜单、主工具栏、播放控制、当前速度。
- 左侧: 当前唯一吉他轨道、乐器、调弦；多轨列表和 mute/solo 后置。
- 中央: 谱面编辑区域。
- 右侧: 属性检查器，显示当前选区可编辑属性。
- 底部: 状态栏、错误提示、可选时间线或缩略导航。
- 浮层: 命令面板、快捷搜索、技巧选择器；和弦选择器后置。

## MVP 交互能力

- REQ-008-F01: 支持完整 undo/redo。
- REQ-008-F02: 支持命令面板。
- REQ-008-F03: 支持用户可配置快捷键。
- REQ-008-F04: 支持鼠标选择音符、小节、范围。
- REQ-008-F05: 支持键盘扩展选区。
- REQ-008-F06: 支持多选后批量设置技巧。
- REQ-008-F07: 支持鼠标辅助定位和选择；虚拟指板点选输入后置。
- REQ-008-F08: 和弦输入、和弦选择器和和弦图编辑器后置；第一阶段相关命令不得作为可执行 MVP 命令。
- REQ-008-F09: 第一阶段不支持轨道添加、删除、重命名和排序；只显示当前唯一标准 6 弦吉他轨道，未来多轨管理后置。
- REQ-008-F10: 支持错误和警告定位。
- REQ-008-F11: 支持应用语言切换入口，第一阶段至少支持简体中文和英文。

## 键盘优先契约

- 常见音符输入、时值切换、休止、删除、复制、粘贴、撤销和播放必须有默认快捷键；循环快捷键后置到循环播放能力进入范围时再启用。
- 第一阶段必须能只靠键盘完成 4 小节 riff 的核心编辑闭环。
- 谱面光标必须能定位到小节、beat、弦和音符槽位。
- 时值键、数字品号输入、方向键移动、技巧快捷键和命令面板都必须触发稳定 command id。
- MIDI 输入、MIDI 录入、MIDI 导入和虚拟指板点选输入不进入第一阶段快捷键契约。
- 自由文本谱解析不作为第一阶段主输入。
- 命令面板必须能搜索所有注册命令。
- 快捷键冲突必须被检测。
- 用户修改快捷键后，命令面板和菜单展示必须同步。

## 状态反馈

- 文件未保存状态必须清晰。
- 当前轨道、当前小节、当前拍位置必须清晰。
- 非法输入必须即时反馈，不能等保存时才发现。
- 导入导出、保存和渲染等长任务必须有进度和取消机制。

## MVP 不做

- 不做营销型首页作为主屏幕。
- 不做过度装饰的卡片式 UI。
- 不把移动端触摸交互作为第一优先级。
- 不做 MIDI 设备输入、实时 MIDI 录入或 MIDI 文件导入作为第一阶段验收门槛。
- 不做虚拟指板点选输入作为第一阶段验收门槛。
- 不做和弦输入、和弦选择器、和弦图编辑器或和弦名自动识别。
- 不做轨道添加、删除、重命名、排序、多轨列表或 track mute/solo。

## 验收标准

- [ ] AC-008-01: 用户打开应用后能直接进入最近文件或新建谱面，而不是先经过营销页。
- [ ] AC-008-02: 用户能通过命令面板执行添加技巧、移调、导出和打开设置。
- [ ] AC-008-03: 用户可只用键盘完成新建标准 6 弦吉他谱、输入 4 小节、添加 Core Loop 技巧、播放校对、保存。
- [ ] AC-008-04: Guitar Domain 发现非法品号或技巧 payload 时，UI 在原位置给出明确错误；Core 只验证 WrittenPitch、Fraction/NoteValue、Part/Staff/Voice/Event/Note 引用和 ExtensionBlock 信封。
- [ ] AC-008-05: 第一阶段核心路径不依赖 MIDI 设备、虚拟指板或移动端触摸输入。
- [ ] AC-008-06: 第一阶段 UI 不提供轨道添加、删除、重命名或排序入口；用户始终编辑一个标准 6 弦吉他轨道。

## 开放问题

- 无。第一阶段只做单轨，不暴露轨道添加、删除、重命名和排序 UI。
