# REQ-011 MVP 第一实现阶段范围

## 决策状态

- 状态: 已收敛；非 Pure Core Kernel V1 细节后续阶段拆分，不阻塞当前内核实现规划
- 合并目标: 最终 PRD 的 MVP 范围、阶段计划和验收边界
- 用户决策: 先把六线谱、五线谱的基本功能和标准 6 弦吉他功能做好；第一阶段暂不支持 7 弦吉他，再做别的。
- 用户补充决策: 当前最重要的是先把 MVP 跑通，不优先追求第一版功能广度。

## 用户价值

第一版必须先证明它是一个可用、可靠、专业的吉他打谱工具。用户要能完成从新建吉他谱、输入六线谱、查看基础五线谱、添加常见吉他技巧、播放校对、保存、重新打开、导出的完整闭环。

## MVP 执行原则

- 第一实现阶段不以功能数量取胜，而以闭环可运行、可保存、可重开、可导出、可测试为第一目标。
- 第一条纵向切片必须跨越 UI、领域模型、命令系统、谱面渲染、播放校对、`.bgp` 文件、PDF/PNG 导出和自动化测试。
- 后续能力只有在不破坏该闭环的前提下扩展；任何不能保存、不能重开、不能回归测试的功能不得计入 MVP 完成。
- 文档、设计和实现计划都要围绕 `Guitar Core Loop` 收敛，避免提前进入插件市场、全乐器编曲、DAW 音频、云同步或 AI 扒谱。

## 第一阶段目标

第一实现阶段命名为 `Guitar Core Loop`。

目标:

- 先做标准 6 弦吉他的核心打谱闭环。
- 先做六线谱编辑体验。
- 同步做基础五线谱显示与同步。
- 先做高频吉他技巧。
- 先做保存、打开、播放校对和基础导出。
- 架构保留多轨、多乐器、插件和复杂编曲扩展点。
- 第一阶段不暴露轨道管理，只编辑一个默认标准 6 弦吉他轨道。

## 第一阶段必须做

- REQ-011-F01: 新建标准 6 弦吉他谱。
- REQ-011-F02: 设置基础歌曲信息，包括标题、作者、固定 tempo 和 4/4 拍号。
- REQ-011-F03: 输入小节、四分/八分/十六分、基础休止和单音；每个 `RhythmSlot` 只能包含一个 note 或一个 rest。
- REQ-011-F04: 在六线谱中输入弦号和品号。
- REQ-011-F05: 根据调弦从弦/品推导五线谱音高。
- REQ-011-F06: 显示基础五线谱，包括音高、节奏、休止、小节线。
- REQ-011-F07: 六线谱和五线谱共享同一音乐事件模型。
- REQ-011-F08: 第一条编码闭环通过 3 个 K1 测试技巧定义验证技巧框架的结构化存储和后续显示派生能力: `test.slide`、`test.bend`、`test.vibrato`；用户可见名称由 i18n/UI 映射为 slide、bend、vibrato；`hammer-on`、`pull-off`、`palm mute` 保持为 P0 后续增强，不阻塞第一条闭环验收。
- REQ-011-F09: 支持播放校对，包括播放光标、节拍器、开始/暂停、基础速度。
- REQ-011-F10: 支持保存、打开、自动保存和基础导出，第一阶段导出至少包含 PDF + PNG。

## 第一阶段明确不做

- 不做贝斯专有编辑体验。
- 不做 7/8 弦吉他创建、编辑或验收。
- 不做鼓谱编辑。
- 不做键盘谱编辑。
- 不做完整乐队编曲工作站。
- 不做轨道添加、删除、重命名、排序、多轨列表或 track mute/solo。
- 不做附点节奏、三连音、跨小节延音线、多声部同轨、变拍号或小节级 tempo 变化。
- 不做同一 slot 多音、和弦图、和弦名自动识别、和弦库、扫弦或琶音节奏细节。
- 不做 DAW 级音频录制和混音。
- 不做第三方插件安装。
- 不做插件市场。
- 不做云同步和账号体系。
- 不做 AI 自动扒谱。
- 不做 Guitar Pro 格式完整兼容作为第一阶段阻塞项。
- 不做 SVG 导出作为第一阶段阻塞项。
- 不追求出版级雕版排版。

## 第二阶段候选

第二阶段需要在第一阶段闭环稳定后再排优先级:

- 7/8 弦吉他。
- 贝斯轨。
- 鼓轨。
- 基础键盘/伴奏轨。
- 更完整导入导出。
- SVG 导出。
- 更高级播放练习。
- 用户脚本或受限插件。
- 音频轨或真实录音同步。

## 行为契约

- Pure Core Kernel K1 不预留 `tracks` 数组、多轨字段、多乐器字段或多弦数字段作为核心 schema；未来多轨、多乐器和多弦数必须作为后续模型演进或外部模块能力单独规划。
- 第一阶段产品上下文只接受一个标准 6 弦吉他谱；UI、播放、导出和测试围绕该产品上下文验证，不把轨道实体写入 Core Kernel K1。
- 测试和验收优先围绕标准 6 弦吉他谱。
- 所有第一阶段功能必须可保存、可重新打开、可撤销、可被测试。
- 五线谱基础显示不得成为独立数据副本，必须从同一音乐事件生成。
- 后置能力不得成为第一阶段实现的阻塞依赖。

## 验收标准

- [ ] AC-011-01: 用户能新建标准 6 弦吉他谱，输入 4 小节 riff，并保存为原生文件。
- [ ] AC-011-02: Pure Core Kernel V1 重新打开核心数据后，音高、节奏、测试技巧和元数据不丢失；六线谱弦品位置持久化由后续吉他谱模块单独验收。
- [ ] AC-011-03: 后续吉他谱模块修改六线谱品号后，必须转换为核心绝对音高变更并让五线谱派生显示同步更新；该能力不属于 Pure Core Kernel V1 schema。
- [ ] AC-011-04: 用户能播放 4 小节谱面，并看到播放光标跟随。
- [ ] AC-011-05: 用户能导出一份可读的 PDF 文件和 PNG 图片。
- [ ] AC-011-06: 第一条 Pure Core Kernel V1 纵向切片能保存并重开 3 个测试技巧定义: `test.slide`、`test.bend`、`test.vibrato`。
- [ ] AC-011-07: 第一阶段验收不要求 7/8 弦吉他、贝斯、鼓、键盘、云同步、第三方插件或 AI 自动扒谱。
- [ ] AC-011-08: 第一阶段验收不要求附点、三连音、跨小节延音线、多声部同轨、变拍号或小节级 tempo 变化。
- [ ] AC-011-09: 第一阶段验收不要求也不暴露轨道添加、删除、重命名、排序、多轨列表或 track mute/solo。

## 开放问题

- 无。第一条编码闭环已收缩为 `test.slide`、`test.bend`、`test.vibrato` 三个测试技巧定义；用户可见 slide、bend、vibrato 名称由 i18n/UI 映射；第一阶段弦数范围已确认: 只支持标准 6 弦吉他，暂不支持 7 弦吉他。
