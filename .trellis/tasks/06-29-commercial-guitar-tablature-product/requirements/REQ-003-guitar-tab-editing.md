# REQ-003 吉他六线谱编辑能力

## 决策状态

- 状态: 已确认核心输入范围
- 合并目标: 最终 PRD 的核心编辑能力
- 当前结论: 第一实现阶段优先完成标准 6 弦吉他六线谱基础编辑；输入方式先做键盘优先，并采用“谱面光标 + 时值键 + 数字品号输入 + 弦间/拍间方向键移动 + 技巧快捷键/命令面板”的 Guitar Pro 式高效输入模型；节奏范围只做 4/4、单 voice、固定 tempo、四分/八分/十六分、基础休止和单音输入；第一条编码闭环只验收 3 个 `Core Loop` 技巧: `slide`、`bend`、`vibrato`；暂不支持 7 弦吉他，也不扩展到其它乐器专有编辑。
- 关键开放问题: 无。技巧命名和语言切换已移交 `REQ-012`。

## 用户价值

用户选择这类软件的第一原因是快速、准确地写出吉他能弹的谱。六线谱编辑必须比通用制谱软件更顺手，且必须覆盖吉他常见技巧。

## 编辑对象

- 单音。
- 和弦，后置。
- 多声部同轨段落，后置。
- 休止。
- 节奏符干和节奏斜杠，后置。
- 和弦图，后置。
- 指法标注。
- 演奏技巧。
- 小节级结构和段落标记。

## MVP 输入方式

- REQ-003-F01: 支持在六线谱网格中直接输入弦号和品号。
- REQ-003-F02: 支持键盘优先输入，第一条 4 小节 riff 的常见操作不依赖鼠标。
- REQ-003-F03: 支持选中音符后修改时值、弦号、品号、力度和技巧。
- REQ-003-F04: 支持选区复制、粘贴、删除、移调、升降八度、重复小节。
- REQ-003-F05: 支持鼠标点击定位和选择音符、小节或范围；鼠标不是 MVP 主输入路径。
- REQ-003-F06: 支持按当前调弦自动推导音高。
- REQ-003-F07: 支持从音高反推可用弦/品，并允许用户选择指法。
- REQ-003-F08: 第一实现阶段必须支持标准 6 弦吉他默认调弦，且必须逐弦保存为明确音高: `6=E2, 5=A2, 4=D3, 3=G3, 2=B3, 1=E4`；不得把 `EADGBE` 作为核心数据。
- REQ-003-F09: 第一实现阶段必须支持创建空白吉他谱、输入小节、输入节奏、输入品号、保存并重新打开。
- REQ-003-F10: MIDI 输入、MIDI 录入、MIDI 导入、虚拟指板点选输入不作为第一阶段验收门槛。
- REQ-003-F11: 键盘输入模型采用谱面光标、时值键、数字品号输入、方向键移动弦/拍、技巧快捷键和命令面板；自由文本谱解析不作为第一阶段主输入。
- REQ-003-F12: 第一阶段节奏输入只支持四分、八分、十六分和等长休止。
- REQ-003-F13: 第一阶段不支持同一 slot 上多个弦/品；相关输入必须返回 `unsupported-multiple-notes-in-slot`，并保持文档不变。

## 吉他技巧分类与优先级

第一条编码闭环只做 3 个 `Core Loop` 技巧。其它常见技巧可以保留模型扩展空间，但不得成为第一条闭环的阻塞项。

### Core Loop: 第一条编码闭环必须覆盖

#### 连接与连奏

- slide: 普通滑音，第一阶段只要求 note-to-note 的基础显示和结构化保存。

#### 音高变化与表情

- bend: 基础推弦，第一阶段只要求半音、全音等离散目标，不做复杂曲线编辑。
- vibrato: 颤音，第一阶段只要求标记和基础显示。

### P0 Follow-up: 第一阶段后续增强，不阻塞第一条闭环

- hammer-on: 从前一个音连到当前音。
- pull-off: 从前一个音勾弦到当前音。
- palm mute: 手掌闷音，可作用于单音或范围。

### P0 Extended: 第一阶段后续候选，不阻塞第一条闭环

这些技巧仍属于高频技巧，但不作为第一条 MVP 纵向切片的完成条件:

- release: 推弦释放，和 bend 组合显示。
- let ring: 延音标记，可作用于单音或范围。
- dead note: 死音，表示有节奏但无明确音高。
- ghost note: 弱化音/幽灵音，表示音符存在但弱化演奏。
- accent: 重音。
- staccato: 断奏。
- pick stroke: 上拨/下拨方向。
- natural harmonic: 自然泛音。
- arpeggio: 琶音扫过和弦。

### P1: 第一阶段可选，建议第二批实现

- pre-bend: 预推弦。
- grace note: 装饰音。
- tremolo picking: 轮拨/快速重复拨弦。
- artificial harmonic: 人工泛音。
- legato slide: 连滑，若普通 slide 模型已能稳定表达可提前支持。

### P2: 后置技巧

- tapping。
- pinch harmonic。
- tapped harmonic。
- whammy bar 细节曲线。
- sweep picking 标记。
- rasgueado。
- 古典吉他右手指法 p/i/m/a。
- 多层 bend 曲线编辑。

## 技巧数据契约

- 每个技巧必须有 `category`、`priority`、`target`、`displaySemantics`、`playbackSemantics`。
- `category` 必须来自固定枚举，不能由 UI 临时拼字符串。
- `priority` 必须是 `P0`、`P1` 或 `P2`。
- `target` 必须明确作用于 note、beat、range 还是 measure；chord target 为后续能力预留，第一阶段不得作为可执行目标。
- Core Loop 技巧必须至少支持结构化保存、重新打开、显示和导出降级说明。
- 第一阶段播放可以对部分技巧做简化处理，但不能丢失技巧结构。

## 行为契约

- 技巧必须绑定到具体音符或范围，不能只作为不可解析文本；和弦目标后置。
- 每个技巧必须声明它是否影响显示、播放、导出和验证。
- 同一音符上的技巧冲突必须有校验规则。
- 技巧选择 UI 必须按分类呈现，不能只给一个无序长列表。
- Core Loop 技巧必须在 `Guitar Core Loop` 测试谱库中至少出现一次。
- 所有编辑操作必须进入统一 undo/redo 历史，并且必须通过语义命令表达用户意图。
- 第一阶段 undo/redo 必须采用细粒度历史模型: 一个成功可撤销语义命令对应一个历史条目；`undo` 和 `redo` 一次只移动一个历史条目，不做复杂智能合并。
- 粘贴时必须保留音乐语义，并按目标轨道调弦重新验证弦/品合法性。

## MVP 不做

- 不做 AI 自动扒谱作为核心编辑前置条件。
- 不做所有民族弹拨乐器的专有技巧。
- 不做音频波形级编辑。
- 不做 MIDI 设备输入、实时 MIDI 录入或 MIDI 文件导入作为第一阶段验收门槛。
- 不做虚拟指板点选输入作为第一阶段验收门槛。
- 不做附点节奏、三连音、跨小节延音线、多声部同轨、变拍号或小节级 tempo 变化作为第一阶段验收门槛。
- 不做同一 slot 多音、和弦图、和弦名自动识别、和弦库、扫弦或琶音节奏细节。
- 不做贝斯、鼓、键盘的专有编辑体验。
- 不做 7/8 弦吉他的创建、编辑、复制目标或专用 UI。
- 不做完整 Guitar Pro 生态兼容作为第一阶段阻塞项。

## 验收标准

- [ ] AC-003-00: 用户可以新建一个标准 6 弦吉他谱，输入 4/4 拍 4 小节基础 riff，保存后重新打开内容不丢失。
- [ ] AC-003-01: 用户可以输入 4 小节含 `slide`、`bend`、`vibrato` 的 riff。
- [ ] AC-003-01A: 用户可以只用键盘完成 4 小节 riff 的时值、弦号、品号、休止、移动、删除、撤销/重做和 Core Loop 技巧输入。
- [ ] AC-003-01B: 用户可以输入四分、八分、十六分和等长休止；输入三连音、附点、变拍号、多 voice 或同 slot 多音时得到明确 unsupported 提示。
- [ ] AC-003-02: 用户复制、粘贴和移调标准 6 弦谱段后，系统能保留合法指法，并在品号、弦号或调弦不合法时给出明确错误。
- [ ] AC-003-03: 任意一个 Core Loop 技巧都能在数据模型中找到结构化字段，而不是只作为文本。
- [ ] AC-003-04: 连续撤销 20 次编辑后，谱面回到准确的历史状态。
- [ ] AC-003-05: 技巧选择 UI 至少按第一阶段实际 P0 分类呈现，例如连接与连奏、音高变化与表情、延音/闷音/噪音；触弦力度、泛音、和弦与节奏动作分类可后置到对应技巧进入范围时再暴露。
- [ ] AC-003-06: 测试谱库包含所有 Core Loop 技巧的最小样例。
