# REQ-010 开源发布、安装、质量与支持

## 决策状态

- 状态: 已确认开源优先，不做近期商业化
- 合并目标: 最终 PRD 的非功能、开源发布和质量交付要求
- 已确认决策: 先全部做开源，商业化遥遥无期且近期不做

## 用户价值

工业级开源软件不只要功能能跑，还要安装可靠、升级清晰、性能稳定、数据安全、文档可用，并能支撑用户长期维护和社区贡献。

本项目第一阶段作为开源项目验证效果，但工程流程和质量标准必须按商业级软件对待。开源版本也必须保护用户谱面资产，具备可诊断、可测试、可恢复、可维护的工程基础。

## MVP 开源交付

- REQ-010-F01: 有明确产品名称和文件扩展名。
- REQ-010-F02: 有 Windows 安装包。
- REQ-010-F03: 有示例谱面。
- REQ-010-F04: 有首次启动的新建谱面流程。
- REQ-010-F05: 有基础帮助文档或内置引导。
- REQ-010-F06: 有错误报告机制，至少能导出本地诊断包。
- REQ-010-F07: 有版本号和更新日志。
- REQ-010-F08: 有明确隐私策略，尤其是谱面文件、插件和崩溃日志。
- REQ-010-F09: 有商业级质量门禁清单，至少覆盖测试、安全、性能、文件安全、诊断和发布准入；这里的“商业级”只表示质量标准，不表示商业化收费。
- REQ-010-F10: 第一阶段发布门禁以 Windows 桌面为准，必须覆盖 Windows 安装、启动、文件关联、保存、打开、导出和诊断。
- REQ-010-F11: 第一阶段不得实现登录、付费、许可证校验、订阅、闭源授权系统、付费插件或商业增强模块。

## 开源发布策略

- 全部核心产品能力按 Apache-2.0 开源。
- 仓库包含核心应用代码、原生文件格式 spec、测试谱库、贡献指南和内部插件示例。
- 第一阶段不做任何收费、试用、买断、订阅、教育授权或许可证校验。
- 后续如果重新考虑商业化，必须作为独立新阶段重新评估，不得污染当前开源核心和 `.bgp` 文件访问权。

推荐 MVP 验证方式:

- 开源验证产品效果、编辑体验、文件格式和插件边界。
- 通过真实用户试用、issue、讨论、示例谱、测试谱库和毕业设计演示验证价值。
- 云服务、AI 转写、谱库、团队协作和商业授权不进入近期路线。

## 开源与品牌边界

- 第一阶段项目先开源，降低早期验证成本，吸引开发者、吉他教师和内容创作者反馈。
- 开源协议采用 Apache-2.0。
- 外部贡献治理采用 DCO。
- 开源仓库应包含核心应用代码、原生文件格式 spec、测试谱库、贡献指南和基础插件示例。
- 品牌、商标、官网、官方构建签名和应用商店发布权可以保留为项目方控制资产，用于避免 fork 混淆为官方版本。
- 当前路线不规划闭源商业版本；如果未来重新评估，也不得破坏用户访问自己本地谱面文件的权利。
- 外部提交必须通过 DCO sign-off 表明贡献者有权按项目协议提交贡献。

## 性能要求

初始建议:

- 打开 5 分钟、多轨、约 200 小节谱面应在可接受时间内完成。
- 常见编辑操作应近似即时反馈。
- 播放光标移动不能明显卡顿。
- 保存中大型文件时 UI 不应假死。
- 导出 PDF/PNG 时必须有进度或忙碌状态，不能让用户误以为应用崩溃。

具体数值需要在技术设计阶段按平台设定。

## 质量要求

- 核心文档模型必须有自动化测试。
- 导入导出必须有样例文件回归测试。
- undo/redo 必须有行为测试。
- 文件迁移必须有测试。
- 播放和渲染至少需要可重复的集成测试或快照测试。
- 商业级质量属性由 `REQ-015-commercial-quality-attributes.md` 约束；它约束质量，不约束收费模式。

## 安全与隐私

- 默认本地离线可用。
- 用户谱面不得默认上传。
- 崩溃日志上传必须可选择。
- 插件权限必须可见。
- 当前不做商业授权；未来任何授权机制也不能阻止用户访问自己的本地文件。
- 打开外部文件、插件包、导入文件和资源文件时必须按不可信输入处理。

## MVP 不做

- 不做复杂企业账号系统。
- 不做云谱库版权交易。
- 不做强 DRM 锁死用户文件。
- 不做移动端商店内购作为第一商业路径。
- 不实现登录、付费、许可证校验、订阅、闭源授权系统、付费插件或商业增强模块。

## 验收标准

- [ ] AC-010-01: 用户可以在目标平台安装、启动、新建、保存、关闭、重新打开。
- [ ] AC-010-02: 产品能显示版本号、更新日志和诊断导出入口。
- [ ] AC-010-03: 用户不登录也能使用核心编辑能力。
- [ ] AC-010-04: 崩溃日志或诊断包不会包含用户未授权上传的谱面内容。
- [ ] AC-010-05: 开源仓库包含 Apache-2.0 license、版权声明、贡献指南和第三方依赖许可说明。
- [ ] AC-010-06: 外部贡献流程要求提交包含 DCO `Signed-off-by`，并在贡献指南中说明原因。
- [ ] AC-010-07: 发布前必须通过商业级质量门禁，至少包括类型检查、单元测试、核心集成测试、文件打开保存回归、导出回归和安全检查。
- [ ] AC-010-08: Windows 桌面版本能完成安装、启动、新建、保存、重新打开、PDF/PNG 导出和诊断包导出。
- [ ] AC-010-09: 应用核心编辑能力不依赖登录、付费、许可证校验、订阅或远程授权服务。
- [ ] AC-010-10: README 和路线图明确当前阶段全部开源，不规划近期商业化实现。

## 开放问题

- 无。第一阶段和近期路线先全部开源，不做商业收费、授权系统或闭源增强模块。
