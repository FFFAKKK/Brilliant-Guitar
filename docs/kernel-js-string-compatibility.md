# Lossless JavaScript string compatibility

## Confirmed gap and scope

At `a1eca90`, a live TS/native comparison found that isolated UTF-16 units D800
and DC00 are accepted by TypeScript in metadata, a Staff ID with a matching Voice
reference, and unknown extension payload values and keys. The native create
boundary rejects all eight cases with `codec.invalid-json`. A metadata command
commits and retains the exact unit through TS undo/redo; native submit rejects,
then undo/redo have no history. A valid surrogate pair and literal U+FFFD are
successful controls. This is an S1 compatibility defect, not invalid user data.

Reproduce after the usual native build and `npm run build`:

```powershell
node dist/test/core-kernel/rust-migration/js-string-native-probe.js
```

The tracked probe compares 28 observations and exits 1 on any gap. The current
report has 14 mismatches; its raw result is `target/js-string-native-gap.json`.
The probe is a diagnostic executable, separate from passing regression tests;
its failure remains visible until the full native migration closes the gap.

The strict TS string checks accept JavaScript strings without a Unicode-scalar
restriction. Contracts strict JSON and Foundation DTOs currently use Rust String
and serde_json::Value, which cannot retain isolated surrogate units. The behavior
also agrees with serde_json's documented distinction between UTF-8 string types
and its WTF-8 byte deserialization route:
[serde_json Deserializer](https://docs.rs/serde_json/1.0.151/serde_json/struct.Deserializer.html).
Accepting the bytes alone cannot repair a DTO or output path that loses the units.

## Selected representation and boundaries

Read-only GPT-6 review and main-session review selected an explicit `JsString`
value with immutable shared UTF-16 code units. Equality, hashing and ordering use
those units. Unicode normalization, U+FFFD replacement and opaque marker text are
not permitted. Empty strings remain valid text; StableId will separately retain
its nonempty constraint. A valid UTF-8 conversion is explicit and fallible.

The first representation is Arc<[u16]> and is not yet live Score storage. It
keeps cloning constant in retained text size, but uses two bytes per ASCII unit.
This does not inherit the existing Arc<str> memory measurements. A future compact
representation must retain the same value/hash/order semantics and independently
prove its allocation and memory behavior before qualification.

The seven-crate structure and public JSON protocol stay unchanged. Core Types
owns the string value. Foundation owns token parsing, exact JSON output and
wire-length calculation. Core Types does not acquire a JSON parser dependency.
No Serde implementation currently claims that arbitrary JsString can pass through
serde_json::Value or an ordinary UTF-8 String without loss.

## Implemented foundation

Core Types provides `JsString::from_utf16`, shared clones, borrowed `code_units`,
code-unit length, empty/ASCII checks and a fallible `to_utf8`. It has no lossy
Display/as_str view. Foundation adds an exact quoted-string token decoder and a
streaming JSON writer. Parsing starts from valid UTF-8 text, accepts all JSON
escapes and retains each escaped u16 without requiring a pair. It rejects extra
trailing tokens, raw control characters, incomplete or invalid escapes and
missing quotes. Surrounding whitespace belongs to the future document parser.

The writer emits valid UTF-8 JSON with isolated units escaped as `\uXXXX`; valid
pairs encode their scalar value. Control/quote/backslash escaping equals the JS
JSON.stringify oracle. Exact wire-byte counting visits the same fragments without
allocating output. Writer failures propagate; the caller must discard partial
output. Token decoding uses ordinary Vec/Arc allocation and has no process-wide
allocation-failure guarantee. Input limits and strict failure precedence still
belong to the existing top-level codec until integration.

The independent checked-in oracle is generated by
`test/core-kernel/rust-migration/js-string-oracle.ts` and verified against its
fixture by the TS suite. It contains 82 samples: every isolated surrogate,
all controls, pair boundaries, reversed/mixed pairs, U+FFFD, real private-use text,
literal backslash escapes and seeded arbitrary units. It also carries 20 rejected
string tokens and JS sort order. Ten Rust tests cover the value and token codec,
including all 65,536 individual units, exact JS bytes/lengths, semantic duplicate
keys, shared clones and a failing writer at every byte boundary. Three TS tests
pin regeneration and the reference document/history acceptance contract.

Validation for this foundation: 257 Rust tests passed, 1 ignored; strict
all-target clippy `-D warnings`, fmt and Rust 1.88.0 all-target check passed.
The Windows x64 addon was rebuilt from this source; its SHA-256 is
`D50B0382D8CE98BC0FEF89B4B07BA45ADC1B69E6825EB1D628ED0428443D8113`.
Full TS/native regression on that artifact passed 708 tests, with 2 skipped and
0 failed (78.407 seconds). The separate native string probe still exits 1 with
14 mismatches on that same artifact. Logs are
`target/js-string-foundation-rust-tests.log` and
`target/js-string-foundation-npm-tests.log`. Scoped self-review checked escape
parsing, UTF-8 character boundaries, code-unit semantics, shared storage,
writer-error propagation and the unchanged production routing. These checks
establish the primitive's behavior, not the pending DTO/native integration.

## Remaining migration sequence

1. Extend the bounded JSON value model to lossless string values and object keys.
   Preserve duplicate-key detection after escape decoding, exact number behavior,
   depth/property limits, canonical order and bounded retention after overflow.
   A temporary parsing escape adapter, if needed, must be bijective and disappear
   immediately into JsString; encoded markers must never enter domain objects.
2. Migrate StableId, raw candidate/journal IDs, Foundation text fields, references,
   opaque extensions and diagnostic/path values that echo input. Replace uses of
   as_str with explicit code-unit or validated ASCII operations. Audit namespace
   validation against original units, not an encoded surrogate placeholder.
3. Connect Contracts strict capture, command decoding, assessment, Store/history,
   selectors, replay and every native output to the lossless model together.
   Avoid a second whole-document fallback and retain the typed local-edit path.
   Verify accepted/rejected behavior and exact errors for bad namespaces,
   duplicate IDs, controls, malformed UTF-8, malformed JSON and resource edges.
4. Preserve distinct accounting for original request bytes, serialized response
   bytes, logical history data and retained storage. Requalify memory and latency;
   do not silently change the limits to pay for a new string representation.
5. Require the tracked native probe to return zero mismatches; extend it to all
   input/output surfaces and long histories. Then run the full public differential
   and native qualification gates before any production switch.

The candidate operation journal remains part of S1 and continues after this
string representation dependency is closed. No live DTO/native route uses the
new primitive yet. Current primitive tests do not resolve the native gap and
do not qualify the kernel for commercial use.
