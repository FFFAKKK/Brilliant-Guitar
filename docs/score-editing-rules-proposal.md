# 谱面编辑规则提案（待审核，未实施超拍编辑）

本文件先固定用户可观察的行为，再决定是否调整内核。范围是第一版单谱表、单声部的五线谱编辑；吉他谱等输入插件只负责产生统一的音高、时值与编辑意图，不各自实现节拍规则。

## 设计依据与边界

- 用户需要在满 4/4 小节末尾先加一拍，再删去中间一拍并收拢后续内容。这个过程要能显示、选择、撤销、保存，不能因为暂时 5/4 就拒绝第一步。
- 成熟软件对“覆盖”和“插入并推动后续内容”采用不同语义。[Dorico 的 Insert mode](https://www.steinberg.help/r/dorico-elements/6.1/en/dorico/topics/write_mode/write_mode_insert_mode/write_mode_insert_mode_c.html) 会推动后续音符，缩短或删除则可收拢时间。[MuseScore Studio 手册](https://handbook.musescore.org/en_gb/notation/rhythm-meter-and-measures/pickup-and-non-metered-measures) 明确有长度不同于拍号的小节，并在小节上显示 `+` / `−` 提示。我们借鉴“明确编辑语义＋可见诊断”，不照搬其内部数据模型。
- 当前项目内核最终语义校验把 `semantic.sequence-exceeds-measure` 作为拒绝事务的错误；浏览器和桌面宿主的插入、属性编辑也各自限制容量。VexFlow 渲染、页面宽度、光标命中、自动创建下一小节都假定事件总时值不超容量。因此允许超拍存在不是只去掉一条前端 `if`。

## 1. 谱面规则警告、结构错误与操作冲突

“已用时值”是当前声部事件（**包括休止符**）时值的精确总和；“标称容量”由拍号决定。例如 4/4 小节只有一个四分音符时，已用 1 拍、标称 4 拍，称为**未满**，并不是窗口尺寸不足。刚创建的空白小节也是未满：它允许继续输入，且不需要凭空画出休止符。

| 状态 | 判定 | 编辑与撤销 | 提示 | 原生保存／打开 |
| --- | --- | --- | --- | --- |
| 结构错误 | 例如时值为零或不受支持、音高数据无效、事件 ID 重复、声部／小节引用缺失，导致文档无法可靠解释 | 拒绝整个事务，保留旧谱 | 定位到原因；属于需要修复的操作错误 | 不写入无效数据 |
| 操作冲突 | 例如选中的事件已被删、编辑锚点过期、请求版本与当前文档不符；文档本身未损坏 | 拒绝这次操作并允许重新定位或重试 | 给操作级反馈，不把整个谱面标成坏数据 | 原有文档可正常保存 |
| 节拍未满 | 已用时值小于标称容量；空白新谱也属此类 | 允许，空白尾部不自动画休止符 | 空白小节不提示；已有内容时可给轻量的“未满”提示 | 允许保存与打开 |
| 节拍超出 | 已用时值大于标称容量，但每个事件及其引用仍有效 | **拟允许**继续插入、修改、删除、撤销；不自动改拍号或吞掉音符 | 对应小节持续显示轻量警告和超出量；不阻断画面 | **拟允许**保存与打开，警告仍可恢复 |

超拍确实**不符合该小节当前拍号**，属于需要提醒用户的轻度谱面规则问题；它可以长期存在，直到用户主动调整，不应因这个警告停止编辑、渲染或原生保存。它不等于结构错误，也不自动表示用户想要变拍号、延音线或把音符移到下一小节。真正的结构错误仍由内核拒绝。

## 2. 第一版操作判定表

| 操作意图 | 默认建议行为 | 可配置或必须禁止的自动行为 |
| --- | --- | --- |
| 修改已选音符音高、升降号 | 原地更新，同一事件 ID 与起点、时值不变；休止符不能直接改成音符，需明确“替换”意图 | **禁止**暗中删除再插入、移动后续事件 |
| 修改已选音符或休止符时值：变短 | 当前默认补等长休止符，保持后续起点；若位于尾部，释放尾部时间 | **以后可配置**为“自动收拢”：后续事件左移，不补休止符；只影响本声部、本小节 |
| 修改时值：变长 | 优先消耗**紧邻**的休止符；仍不够则把后续事件向右推。即使因此超拍也接受并标记本小节 | **禁止**删除后续音符、消耗非相邻的明确休止符、静默搬到下一小节 |
| 在空位或明确插入锚点加音符／休止符 | 插在指定位置，后续事件向右推；满小节末尾仍可显式选择当前小节的末尾插入 | **禁止**把已选音符意外改成新事件，或在拍号边界偷偷改写下一小节 |
| 对已选音符按普通删除 | 清除音高，原起点与时值变成休止符（现有语义） | 若未来允许“删除后自动收拢”，必须是用户明确选择的偏好，不能悄悄改变旧行为 |
| 执行“删除时间／收拢” | 删除所选事件及其时长，后续事件左移；不自动生成补位休止符。它与普通删除必须是两个明确命令 | **禁止**波及别的声部或小节 |
| 修改休止符 | 与音符使用同一时值增减规则；选中后可编辑、删除。暂不支持“改类型”暗中重建事件 | **禁止**让休止符覆盖后续音符 |
| 撤销／重做 | 每次用户动作是单个原子历史项，包括它引起的休止符变化及小节诊断变化 | 中途只撤销一半，或丢失选择目标 |

同一小节内部的操作以事件有序序列及精确时值计算，不依赖屏幕像素。时值变化不按“当前占用是否等于拍号”判断合法性；这只能决定是否产生节拍诊断。默认不跨小节自动搬移事件。跨小节流式重排、跨线延音、多声部同步属于后续单独规则，不能用当前单声部规则推断。

自动行为按影响分级：补休止符、消耗紧邻休止符等**可预期且可撤销**的整理可作为默认；改变后续事件起点的“自动收拢”虽然有用，但属于用户可设置的编辑偏好，默认沿用当前补休止符行为。偏好只影响之后的操作，不回头改旧谱；每次操作先由应用层把偏好解析为明确的编辑命令，再由内核原子执行并记录历史。覆盖或丢弃已有音符、私改拍号、跨小节或跨声部搬移等会造成明显数据或语义损失的行为，一律不能在后台隐式执行。

### 用户例子

在一个已有四个四分音符的 4/4 小节：

1. 明确定位在**本小节末尾**，再插入一个四分音符。小节临时有五拍；第五音仍属于本小节，显示 `+1 拍`，前四音不变。
2. 选中中间一个四分音符，执行“删除时间／收拢”。第五音及中间之后的事件前移一拍，小节回到四拍；提示消失。
3. 两步各能独立撤销和重做；在第一步和第二步之间保存、关闭、重新打开，五拍状态不丢失。

如果用户执行的是普通删除，中间音符改成四分休止符，总量仍是五拍；此时 `+1 拍` 保留。这是两种不同编辑意图，不能靠后台猜测。

## 3. 显示与文件规则

- 渲染要按实际事件总时值给小节分配宽度，拍号仍显示原值；超出的事件留在该小节可视区域，不能堆到末尾一条线上或画进下一小节。命中框、键盘导航、焦点与 `+` 标记必须指向同一小节。
- 持续的节拍警告和“刚才命令被拒绝”的短暂反馈分开。**重新计算警告**是指每次编辑、撤销或打开文件后，根据实际音符与休止符的时值总和再与拍号比较：相等则清除警告，超出则显示超出量。保存的是乐谱数据，而不是一个可能过期的红框或警告标志。
- 原生 `.bgp.json` 必须能保存和重新打开有超拍警告的谱面；警告状态由乐谱数据再次得出。视觉导出不得因警告白屏或丢失音符。
- 播放和 MusicXML／MIDI 等时间语义导出的具体策略留到对应功能设计时讨论；本轮不预设禁止播放，也不把未来功能的限制强加给当前编辑与保存。

## 4. 分层与实施顺序（均未在本提案中实施）

1. **内核规则审核**：把 `sequence-exceeds-measure` 从阻断性结构校验中分离为可查询的**警告**，同时保持时值、引用、ID、原子事务等硬校验。审核文档编码、解码、打开、增量校验、历史回放是否都接受同一状态；不要在工作台维护一份与内核不同的“临时真相”。此项必须先出独立改动方案再修改内核。
2. **应用操作合同**：新增明确的“普通删除”和“删除时间／收拢”意图，并预留“缩短后自动收拢”的偏好入口。浏览器与 Rust 桌面宿主调用同一语义测试集合；容量由警告计算，而不是两边各自拒绝。版本冲突等仍为拒绝。
3. **谱面投影与显示**：投影包含每小节实际时值、标称时值及诊断；修正页面布局、VexFlow 非满拍模式、光标末尾锚点、选中命中与反馈归属。超拍渲染失败不能造成白屏。
4. **回归矩阵**：空／未满／刚好满／超拍；首／中／尾事件；音符／休止符；变长／变短；紧邻休止符／非紧邻休止符；后续事件／下一小节存在；撤销／重做／保存／重开。必须覆盖“C5 八分、B4 八分、A4 二分，延长 B4 合法”以及“五拍→收拢→四拍”。

### 与当前版本的差异

目前音高原地修改、普通删除变休止符、时值缩短补位和合法范围内的后续事件右移已有实现。C5／B4／A4 的合法延长已修复并进入回归测试，但当前版本仍以小节容量作为硬上限。满拍后继续插入、超拍显示与原生保存、明确的“删除时间／收拢”命令都**尚未实现**。当前渲染器也不能直接接收超拍事件序列。实施时应按上面四层逐层验证，不应先去掉宿主容量判断造成不可显示或无法重开的数据。

核心待审核决定是：第一版将**超拍定义为内核可保存的谱面编辑状态，并给出持续、轻量的规则警告**；保持小节归属不变，跨小节搬移另设操作。此决定通过后才修改内核及其接口。
