# F16 速度记号方案

## 当前结论

截至 2026-09-18，浏览器工作台已经完成文档基础速度的闭环：统一“乐谱属性／音乐结构”分区负责编辑 BPM，Host 将 `document.metadata.tempo.bpm` 投影到五线谱视图，分页布局把同一个 BPM 传给刻谱层，VexFlow 在第一页首个系统绘制节拍器记号。

这项能力不创建独立停靠组件。基础速度是低频的乐谱结构属性；播放组件中的试听速度属于播放会话，不改写乐谱文档。

## 数据和界面边界

- 文档基础速度：`document.metadata.tempo.bpm`，保存、撤销和重做均通过既有 Core 元数据事务完成。
- 谱面显示：`NotationView.tempoBpm` 是只读投影，不能成为第二份速度状态。
- 播放来源：播放投影读取同一个文档 BPM，保证乐谱显示与默认播放速度一致。
- 临时试听速度：以后由播放会话单独保存，不反向覆盖文档速度记号。

## 绘制规则

1. 仅在全局第一小节且该小节位于系统开头时绘制基础节拍器记号。
2. 后续系统、第二页及以后页面不重复绘制文档基础速度。
3. 第一页首系统为速度记号预留顶部空间；后续页面使用正常系统顶部位置。
4. BPM 必须是大于零的有限数，非法传输投影在进入刻谱层前被拒绝。
5. 修改乐谱属性后，新的文档投影驱动谱面和播放来源共同更新，不在组件内维护镜像状态。

## 暂不实现

中途速度变化需要 Core 提供带音乐位置的速度时间线、写入命令、校验和撤销语义。合同完成后，再增加从小节或已有速度记号进入的上下文编辑入口，并处理渐快、渐慢等后续能力。当前前端不使用只存在于界面的临时数据模拟这些文档内容。

## 验证基线

- `NotationView` 投影包含文档 BPM，并拒绝零、`NaN` 和无穷大。
- 分页布局在第一页首系统保留记号空间，分页后的系统恢复正常顶部位置。
- 五线谱测试、TypeScript 检查和 Vite 生产构建通过。
- 浏览器控制通道可用时，最终视觉验收检查谱号、拍号、速度记号和第一小节之间没有裁切或重叠。
