# 工作台基础能力审计

审计日期：2026-09-16。

本轮范围是工作台框架的逻辑基础，不重新设计配色或具体组件外观。审计依据包括当前浏览器实际界面、工作台源码、宿主桥接、Native/Core 编辑链路与自动化回归。

边界采用“机制归工作台，呈现归组件”：工作台负责异步任务、命令路由、问题分发、焦点、布局、插件权限和故障隔离；文件／编辑／视图菜单、快捷键设置页、命令面板以及某种错误应该画成什么样，分别由导航栏或具体业务组件决定。

## 本轮已经补齐

### 结构化问题与视觉适配

编辑问题现在按以下链路传递：

```text
Core / 编辑命令 / 宿主
  → WorkbenchIssue（代码、来源、严重程度、精确目标、是否可重试）
  → HTTP 或桌面宿主桥接
  → Workbench 视觉反馈适配器
  → 小节脉冲、对象拒绝反馈、组件状态或全局状态
```

Core 和宿主不再直接指定 CSS 动画。组件也不需要解析错误字符串来猜测应该提示哪个小节。编辑请求建立时会保存目标上下文，宿主返回的精确目标优先，因此光标后来移动也不会让错误提示跑到下一个小节。

### 空谱面和精确光标

- 空小节不再绘制伪造的整小节休止符。
- 4/4 空小节暴露第 1、2、3、4 拍四个纯 UI 编辑位置，方向键可以逐拍移动。
- 在后续空拍输入时，宿主以真实休止符补齐前面的静默时间；补休止符与落音符属于一次原子编辑和一次撤销历史。
- 光标位置由 `measureId + offsetUnits` 标识，不再依赖多个虚拟位置共用的序列锚点。

### 不破坏后续节拍

延长一个休止符时，如果后面已经存在另一个休止符或音符，命令会拒绝覆盖并返回 `editor.rest-would-overwrite-next`。文档保持原状，反馈目标固定在原小节和原事件。

### 统一问题、异步状态与诊断

初始会话、音符编辑、文件保存／打开／导出与组件生命周期问题现在都可以进入统一 `WorkbenchIssue` 通道。工作台维护有界的内存诊断记录和无视觉占位的 `aria-live` 通道；各组件仍自行决定可见反馈。

统一操作状态机覆盖 `running / blocked / failed / recovering`，按操作 ID 和拥有者去重。会话加载、音符编辑和文件操作已经接入；具体组件仍可保留便于自身渲染的局部状态，但不再各自发明异步生命周期。

### 命令路由机制

工作台已有可动态注册／注销的命令路由器，统一命令 ID、作用域、启用状态和平台无关快捷键。文件、撤销重做、谱面缩放和布局操作已经完成首批接入：导航菜单、组件按钮和键盘入口执行同一个命令 ID。路由器不生成菜单，导航栏只决定“文件／编辑／视图”的具体呈现。

### 正式运行时门面

`WorkbenchRuntimeProvider` 现在统一提供命令、异步操作、问题、焦点和组件生命周期。应用服务只接收收窄后的运行时接口，不再分别接收或创建多套全局能力。内置组件的逻辑定义和 React 视图贡献已经拆开，工作台按注册贡献装配内容，不再按组件 ID 硬编码具体渲染分支。

React 组件通过 `UiComponentHost` 获得布局、焦点和受权限约束的 `executeCommand`，不能直接复制全局快捷键或绕过命令路由。编辑历史与谱面缩放已迁移到这条接口；旧工作台实现及其独立全局键盘监听已经移除。

五线谱、音符控制、编辑历史和谱面缩放不再由工作台硬编码注册，而是由四份第一方 `UiPluginManifest` 在启动期安装。插件管理器会先验证 API 版本、所需宿主能力、组件绑定、组件和命令的唯一归属以及视图声明，再原子写入组件目录。编辑历史与谱面缩放的五个命令由插件编译绑定贡献，工作台只保留文件、设置和布局等宿主命令。当前运行时限定为随应用编译的 `internal-module`，不支持运行时热插拔。

### 组件运行时隔离

- 插件上下文只暴露声明过的只读投影和命令权限；越权命令被拒绝并形成结构化问题。
- `mount / update / dispose` 生命周期失败被运行时隔离。
- React 组件各自拥有错误边界，一个组件渲染失败不会让整个工作台白屏。

### 渲染、焦点和布局恢复

- 新谱面绘制会取消已过期的绘制任务，缩放或停靠区调整不会让旧结果覆盖新结果。
- 停靠区显示、隐藏、移动和重置通过统一焦点服务恢复到原目标；目标消失时回到谱面工作区。
- 持久化布局在进入工作台前完成版本验证、迁移和非法项清理；恢复原因保留在当前会话诊断中。
