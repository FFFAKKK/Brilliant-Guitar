# Native 工作负载诊断 · 2026-09-13

后续更新：本文件保留 `828ba76` 及当时 guest 的测量记录。新的共享 guest
读取工具已使 64 小节编辑通过，256 小节仍失败；现在默认脚本使用新 guest，
前后对照和原始 guest 身份见 [后续容量报告](kernel-wasm-guest-capacity-2026-09-13.md)。

结论：重复读取完整文档的路径已优化；当前测试 Wasm 插件在 64／256 小节样本上
因单次燃料耗尽而拒绝编辑。不能把读取优化或全量回归通过解释为商业容量通过。

## 可复现范围

构建 TypeScript 后运行：

```powershell
node --expose-gc scripts/profile-native-integrated.mjs
```

脚本使用当前 Wasm 原生产物、真实公开 SDK 和已编译测试 guest，创建 16、64、256
小节的单分部乐谱，每小节四个音符。安装 score／part 两个测试贡献者，执行 score
命令；不是完整吉他产品插件或多分部编曲负载。每个规模包含一次创建、六次 Core
元数据编辑、十二次稳定读取、六次插件编辑尝试和三次撤销／重做组合。
返回结果和历史深度均断言；插件拒绝被明确记录，不能作为成功编辑耗时使用。

本机为 Windows x64、Node 24.15.0、i9-13900HX、release Native。前后分别在新进程
执行；计时包含观测包装成本，host 时间包含 guest 时间，两者不能相加。
这不是冻结 CVN-7 的正式资格运行，不改变已有性能阈值。

## 重复读取结果

| 小节／音符 | 修改前单次中位数 | 修改后单次中位数 | 12 次 Native 回复字节（前 → 后） |
|---|---:|---:|---:|
| 16／64 | 0.729 ms | 0.034 ms | 165,048 → 4,116 |
| 64／256 | 2.462 ms | 0.020 ms | 638,256 → 4,116 |
| 256／1024 | 12.043 ms | 0.022 ms | 2,540,700 → 4,116 |

每次仍发起 Native 查询，未将状态全部缓存在 JS。集成私有 `read` 请求可附带
`knownSnapshotVersion`（首次为 null）；Rust 使用已有 `read_stage4`，保留检查点调度、
history／dirty 和可用性查询。版本相同且已有物化快照时省略 document；版本变化时
返回完整文档。TS 仅在身份／schema／版本匹配时复用已经深冻结的快照，冻结新状态时
不再次遍历整份文档。公开结果形状、快照身份语义和 Node 导出集合不变。

旧产物不认识增量请求时，仅对已知的旧请求拒绝路径探测一次，随后继续使用同一
Rust 会话的完整读取。实际读取错误和重入错误不重试、不返回旧缓存冒充新状态。
新的 V2 已构建至 `target/integrated-v2-next/brilliant_kernel_node.node`，常规 V2 文件
被其他进程占用，因此本轮没有覆盖或停止该进程。新 Wasm 产物已更新并用于上述测量。
实际切换 V2 应在使用者退出后进行；不能在 Native 测试／应用运行时覆盖文件。

## 明确未解决的规模问题

16 小节插件编辑六次成功。64 和 256 小节插件编辑均六次拒绝，错误发生在
`commandPrepare`；同一输入脱离操作总预算后仍失败，Native 私有错误明确为
`wasm.execution-failed:FuelExhausted`，输入分别为 53,257／211,794 字节。
因此这不是 128 MiB 累计传输预算导致的拒绝。这里只证明该测试 guest／工作负载
在当前单次燃料合同下受限，不能泛化为所有 Wasm 实现的相同容量。

私有 Wasm 错误现在附带封闭的 Rust 错误种类，不附带输入、用户内容或堆栈。
公开命令／迁移的错误合同仍保持原样，产品级资源诊断仍需收口。
本轮没有提高燃料上限，没有改测试 guest 来绕过问题。下一步应减少整文档传输、
视图构建和客体解析成本，并结合实际插件确定可验证的容量及燃料配置。

## 内存与进度边界

脚本记录阶段前、阶段后和主动 GC 后的 RSS／heap／external／ArrayBuffer 快照。
256 小节场景 GC 后 RSS 约 148 → 144 MiB，heap 约 8.75 → 8.76 MiB。
这些只是进程瞬时观测，没有监测峰值，也没有长期循环、会话释放或泄漏资格验证，
因此不声明内存稳定性改善。UI／排版／播放成本不在本次测量中。

商业发布准备仍按约 65% 的粗略工程判断汇报，不因局部读取加速而上调。
主要未决项是插件实际容量、完整宿主资源／执行边界、长期稳定性、目标平台性能、
默认入口及发布升级流程。数字不代表剩余工期比例。
