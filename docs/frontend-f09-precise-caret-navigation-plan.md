# F09 精确光标与键盘导航方案

日期：2026-09-16。

状态：F09-A 与 F09-B 的首个可用切片已完成浏览器验收。

本文展开 [第一版前端交付清单](frontend-v1-delivery-checklist.md) 中的 F09。F09 不是一个可停靠、可缩放的普通 UI 组件，而是五线谱视图中的核心交互系统。用户看到的光标只是一层指示图形；真正的功能还包括语义位置、选择关系、键盘命令、鼠标命中、自动滚动和焦点协调。

## 一、成熟软件采用的共同结构

### Guitar Pro 8

- 编辑光标落在具体节拍；点击谱面只重新定位，不立即写入音符。
- 左右方向键移动到前后节拍，退格删除当前音符；上下与 Tab 用于谱行、谱表或记谱法之间的导航。
- 编辑光标按当前声部着色；播放光标是另一种状态和行为。
- 范围选择单独显示，不拿编辑光标冒充选择范围。

### MuseScore Studio

- 普通选择与音符输入光标是两个概念；进入音符输入后，光标表示下一次写入的位置。
- 鼠标输入前显示影子音符，让用户预判音高落在哪条线或间上。
- 键盘和鼠标都可以确定输入起点；选择已有对象与继续输入具有不同视觉反馈。

### Dorico

- caret 是一条表示节奏位置的插入线，位置由节奏网格控制。
- 左右方向键按当前节奏网格或相邻事件移动，`Ctrl/Cmd + ←/→` 跨小节。
- caret、普通选择、鼠标指针和播放头是不同状态。
- 不同输入模式、声部和谱表会改变 caret 的附加标记，但基础位置来源保持一致。

三者视觉不同，但共同点非常稳定：**光标代表音乐语义位置，不保存屏幕像素；选择、输入光标、悬停预览和播放头必须分开。**

## 二、我们对 F09 的定位

F09 不注册为 `UiComponentDefinition`，不出现在上下左右共享停靠区，也没有标题栏、关闭按钮和独立尺寸。

它由三个内部模块组成：

```text
ScoreNavigationSession（无界面状态与命令）
  ↓
ScoreInteractionGeometry（语义位置与谱面坐标映射）
  ↓
ScoreInteractionOverlay（光标、选择、悬停和以后播放头的绘制层）
```

键盘入口由 `ScoreKeyboardRouter` 接入同一套导航命令。音符控制、谱面视图和以后播放组件只能读取公开的编辑位置，不能各自保存另一份“当前小节／拍位”。

## 三、必须区分的四种视觉状态

| 状态 | 表达内容 | 第一版视觉建议 |
|---|---|---|
| 空位焦点 | 下一次输入发生的真实可写节奏位置 | 按谱间距缩放的小方框；只出现在空小节或未填满小节的尾部 |
| 对象焦点 | 当前要查看、修改或删除的音符／休止符 | 以音头或休止符原点为中心的小方框，不再同时画空位焦点 |
| 悬停预览 | 鼠标落下可能选择的位置或音高 | 低透明度影子音头／轻微命中高亮，不提交文档 |
| 播放头 | 当前正在发声的时间位置 | 独立颜色和运动方式；F10 实现，绝不复用插入光标 |

范围选择由 F11 扩展为独立的半透明范围，不属于插入光标本身。

## 四、语义位置模型

当前 Core 的事件没有持久化 tick 或屏幕位置。事件开始时间由 Voice 的精确 `Fraction` 起点和前序事件时值推导，插入命令使用稳定 ID 锚点。因此第一版光标也应使用稳定语义锚点：

```ts
interface ScoreEditPoint {
  readonly partId: string;
  readonly staffId: string;
  readonly measureId: string;
  readonly voiceId: string;
  readonly anchor:
    | { readonly kind: "start" }
    | { readonly kind: "after-event"; readonly eventId: string };
  readonly preferredPitch: InputPitch | null;
}
```

- `anchor` 是当前位置的权威来源，直接兼容 Core 的 `SequenceAnchor`。
- 当前拍位由小节拍号、Voice 起点和前序事件时值以精确分数推导，不使用浮点像素反推音乐时间。
- `preferredPitch` 只服务鼠标预览和连续输入，不属于乐谱文档。
- 页面号、系统行号、SVG 坐标和缩放比例全部是临时布局结果，不写入编辑会话。
- 文档提交后用稳定 ID 重新解析光标；锚点事件被删除时采用明确的相邻回退规则，不能让光标悄悄跳到任意小节末尾。

第一版合法插入点只包括 Voice 起点和真实事件边界。`start` 仍是 Core 的内部插入锚点，但有事件的小节不会把它绘制成第一个音符前的可选空框；“在第一个事件前插入”以后由明确的插入命令承担。未来加入任意拍位插入、三连音和不完整声部时，再用 Core 的精确 `Fraction` 与拆分／补休止命令扩展；当前不能让焦点停到一个业务层无法真正写入的位置。

## 五、鼠标规则

### 单击已有音符或休止符

1. 选择该事件。
2. 同步保存它开始位置对应的编辑锚点，但插入线暂时隐藏，以选择反馈为主。
3. 音符控制立即显示所选事件属性和准确位置。
4. 再次点击空白节奏位置时清除选择，恢复插入光标。

### 单击谱面空白位置

1. 根据横向坐标选择最近的真实事件；只有小节为空或尾部仍有容量时，才允许选择尾部空位。
2. 根据纵向坐标计算预期音高，作为 `preferredPitch`。
3. 清除对象选择，移动插入光标。
4. 单击只定位，不修改文档，避免在没有输入模式开关的情况下误写音符。

### 双击

当前实现会双击直接写入音符。这个行为暂时不在 F09 中自动删除，但不把它视为已经批准的长期规则。F09 视觉方案通过后，需要单独决定：保留双击快速输入，还是以后用明确的鼠标输入工具承载。单击定位的行为先固定。

### 悬停

- 悬停事件时只轻微强调可选对象。
- 悬停空白谱位时显示当前时值对应的影子音头和音高位置。
- 离开谱面立即消失；不进入撤销历史，不改变音符控制值。

## 六、键盘导航建议

| 按键 | 无选择时 | 有单事件选择时 |
|---|---|---|
| `←` / `→` | 前一个／后一个合法节奏位置，跨越小节边界 | 选择前一个／后一个事件；到末端后可转为相邻插入点 |
| `Ctrl/Cmd + ←/→` | 前一个／后一个小节起点 | 跳到前一个／后一个小节的第一个可选事件或起点 |
| `Home` / `End` | 当前小节起点／末端合法位置 | 当前小节第一个／最后一个事件 |
| `Ctrl/Cmd + Home/End` | 乐谱起点／末端 | 乐谱第一个／最后一个事件 |
| `Esc` | 取消未完成的音名草稿，保留当前位置 | 取消未完成的音名草稿并保留对象焦点 |
| `Backspace` | 建议删除光标前一个事件并回到其起点 | 删除所选事件 |
| `Delete` | 只在光标正好对应可删除事件时执行，否则不猜 | 删除所选事件 |
| `Shift + ←/→` | F11 中扩展范围选择 | F11 中从锚点扩展范围选择 |
| `Space` | 预留给 F10 播放／暂停 | 预留给 F10 播放／暂停 |

现有 `A–G → 组号`、`R`、`+ / -`、`.` 等输入规则继续使用。上下方向键在第一版单谱表中不急于绑定；多谱表、六线谱和打击乐进入后，再统一决定它用于跨谱表导航还是音高移动，避免现在占掉未来最重要的方向键。

Backspace 在无选择时删除前一事件并回到其起点，已经纳入第一版；Delete 仍只处理明确选中的事件，不猜测光标附近对象。

## 七、光标视觉和动画

第一版不照搬 Guitar Pro 的大色块，也不照搬 Dorico 跨越整个谱表的长线。结合用户已经否决过的大光标，采用：

- 使用约 `1.45` 个谱间距的小方框；事件方框以音头或休止符原点为中心，空位方框以真实插入锚点为中心。
- 所有位置和尺寸从当前 `staffSpace`、SMuFL 字形原点和排版几何推导；缩放纸张时同比例变化，边线保持可读。
- 键盘或鼠标移动后的约 300ms 内保持常亮，随后以约 1.1s 周期进行低幅度透明度闪烁。
- 点击音符控制、缩放或菜单时，编辑位置继续存在并继续动画；DOM 焦点变化不能把音乐编辑会话误判为停止。
- 应用窗口失活时可以变暗并暂停动画，但返回后恢复原位置。
- 关闭动画或系统启用 `prefers-reduced-motion` 时显示稳定的常亮细线，不直接消失。
- 不给焦点框增加文字标签、外层卡片或大面积背景色。

当用户只输入了音名、尚未输入组号时，因为音高还不完整，不猜测八度，也不画假的音头；可以在光标附近短暂显示紧凑的 `A·` 草稿。鼠标悬停已有完整纵向坐标时才显示影子音头。

## 八、自动滚动

- 光标移动本身不强制居中，避免每按一次方向键页面都晃动。
- 仅当光标离开视口内部安全区域时，滚动最小距离使其重新可见。
- 用户用滚轮或中键手动浏览谱面时，不改变编辑位置。
- F10 的播放跟随是独立策略；手动滚动可以暂停播放自动跟随，但不暂停播放或移动编辑光标。
- 停靠区显隐不得改变编辑位置；布局重新计算后只重新解析坐标。

## 九、渲染与性能边界

当前 `vexflowRenderer` 把 `.input-cursor` 和事件命中矩形一起写进整页 SVG，`EngravedPage` 又把光标状态放进 VexFlow 重绘依赖。F09 应调整为：

1. VexFlow 只绘制谱号、拍号、五线、音符、休止符和其他乐谱正文。
2. 排版层输出一份只读的 `ScoreInteractionGeometry`，记录事件 ID、编辑锚点与当前页面坐标。
3. 单独的 `ScoreInteractionOverlay` 在正文上方绘制光标、选择和悬停状态。
4. 移动光标只更新覆盖层，不重新创建整页 VexFlow SVG。
5. 闪烁只使用 CSS opacity 动画，不用 React 定时器持续触发渲染。
6. 文档改变或页面重新排版时更新几何映射；普通光标移动不触发排谱。

这样可以避免用户操作其他组件时谱面看起来冻结，也为 F10 播放头和 F11 范围选择提供同一套坐标映射，但三种状态仍分别管理。

## 十、焦点和可访问性

- 音乐编辑位置属于编辑会话，不属于某一个 DOM 元素的临时焦点。
- 当焦点位于文本框、菜单或对话框时，字母和方向键由该控件处理，不能误写谱。
- 音符控制完成一次参数修改后，可以把键盘控制权归还谱面，同时保持原编辑位置。
- 键盘移动时用无障碍状态文本播报“第 2 小节，第 3 拍”等位置；连续快速移动需要合并播报，避免噪声。
- 谱面拥有明确焦点轮廓，但焦点轮廓与音乐光标不是同一视觉元素。

## 十一、建议实施切片

### F09-A：位置基础

- 建立 `ScoreEditPoint` 和无界面的导航会话。
- 从文档事件顺序和精确时值推导合法位置与拍位。
- 点击横向位置映射到最近合法锚点。
- 完成左右、跨小节、起点和终点导航。
- 文档编辑、撤销、删除和重新排版后稳定恢复位置。

### F09-B：独立覆盖层

- 将光标和选择反馈移出 VexFlow 正文重绘。
- 落实紧凑光标、移动常亮、闪烁、动画关闭和失焦状态。
- 落实最小自动滚动和停靠区变化后的坐标恢复。

### F09-C：悬停与扩展接口

- 增加鼠标影子音头和精确命中反馈。
- 为 F10 播放头和 F11 范围选择提供坐标接口，不提前实现它们的业务。
- 记录任意拍位插入需要的 Core／应用服务能力，无法真实写入的位置不在第一版中伪装可用。

每个切片完成后都在本地浏览器验证正常窗口、窄窗口、缩放、停靠区显隐、连续按键和操作音符控制时的光标表现。

### 当前实现进度

- 已建立 `ScoreEditPoint`，使用 part、staff、measure、voice 与 Core `SequenceAnchor` 表示编辑位置。
- 已让插入命令携带真实锚点；在已有音符之间输入时，新音符写入光标位置，不再总是追加到小节末尾。
- 已完成左右移动、跨小节移动、Home/End 与全谱首尾导航的基础命令。
- 已完成无选择时 Backspace 删除前一事件并回到其起点。
- 已把插入光标和选择反馈移到独立 SVG 覆盖层；普通光标移动不重新创建 VexFlow 正文。
- 已验证点击第一个事件之前会选择该事件，不再暴露 Core 的 `start` 假空位；真实尾部空位仍可输入。
- 已验证直接修改所选音符后稳定 ID 与对象焦点会保留，不会异步退回输入状态。
- 已验证上下方向键在第一版单五线谱中保持未绑定，不会误切谱线或改变音高。
- 尚未实现影子音符、任意节奏网格位置、范围选择和播放头；这些分别留给 F09-C、F11 和 F10。

## 十二、验收标准

- 点击小节不同横向位置，光标能落在不同且真实可操作的节奏边界。
- 左右键连续移动时位置顺序稳定，可跨小节且不会跳回小节末尾。
- 选择音符、清除选择和恢复输入位置之间没有状态混淆。
- 操作音符控制、缩放和导航菜单时，光标不会冻结、消失或丢失位置。
- 光标移动不触发完整 VexFlow 页面重绘。
- 缩放、滚动和停靠区变化后，光标仍对应同一个音乐位置。
- 插入光标、选择、悬停和以后播放头的颜色与形状不会相互冒充。
- 动画关闭或减少动态效果时仍可清楚识别当前位置。
- 所有键盘操作在文本框、菜单和对话框中不会误作用到谱面。
