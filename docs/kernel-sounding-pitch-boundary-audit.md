# 派生发声音高边界审计与迁移合同

状态：2026-09-17 完成边界审计；尚未迁移阻塞规则。

## 结论

当前 `semantic.sounding-pitch-invalid` 不能直接改名为 `rule.sounding-pitch-out-of-range`。它检查的是移调后音高能否重新表示成 Core 的 `WrittenPitchV1`，其中八度只允许 0–8、变音只允许 -2–2；它没有检查播放器使用的 MIDI 0–127 范围。

这两个边界并不相同：

- B8 上移一个半音得到 C9。当前 Core 因派生八度为 9 而拒绝，但对应 MIDI 120，仍可正常播放。
- C0 下移一个半音得到 B-1。当前 Core 因派生八度为 -1 而拒绝，但对应 MIDI 11，仍可正常播放。
- 某些移调会得到三重升降号。该拼写超出 `WrittenPitchV1` 的 -2–2 表示范围，但其半音位置仍可能位于 MIDI 0–127。
- 极大的合法移调分量可能使半音位置落在 MIDI 范围外；播放器必须静音或报告限制，不能截断、取模或夹到 0／127。

因此，文档完整性、派生拼写能力和播放能力必须分开判断。

## 保持阻断的规则

以下状态仍是文档或命令错误：

- 存储的 `writtenPitch` 本身不是合法 `WrittenPitchV1`；
- `writtenToSounding` 分量不是有限的安全整数；
- `core.range.transpose-written-pitch` 等命令试图把结果写回 `writtenPitch`，但结果不能表示为合法 `WrittenPitchV1`；
- 身份、引用、事务、版本或资源边界错误。

范围移调命令修改的是持久化书面音高。它的目标音高不可表示时必须继续原子拒绝，不能与“已有合法书面音高的派生发声音高不可表示”混为一谈。

## 建议的非阻断告警

每个音符最多返回一个派生音高告警，按以下优先级决定：

1. `rule.sounding-pitch-out-of-playback-range`

   移调后的半音位置不在 MIDI 0–127。播放器将该音的 `soundingMidi` 投影为 `null`，不调度声音，并报告结构化播放限制。

2. `rule.sounding-pitch-spelling-unrepresentable`

   半音位置仍在 MIDI 0–127，但移调后的八度或变音不能表示为 `WrittenPitchV1`。播放可以继续；需要显式发声音高拼写的导出器必须保留书面音高与移调关系，或报告导出限制，不能伪造等音拼写。

告警应定位到 `partId`、`measureId`、`voiceId`、`eventId` 和 `noteId`，并携带稳定的原因码。派生半音位置可能超出 JavaScript 安全整数，告警合同不能把它无条件编码成 JSON number；可以省略数值并由书面音高、移调和原因精确重算，或在新合同中使用明确的十进制字符串表示。

## 规则告警合同升级

现有 `readRuleWarningPage` V1 是时间告警专用结构，固定包含 `nominalDuration`、`actualDuration` 和 `overflow`。把音高塞进这些字段会产生错误语义。

迁移前应增加 V2 联合类型，同时保留 V1 的现有字节和调用方：

- 时间变体：沿用小节、声部与三个精确时值字段；
- 音高变体：增加事件、音符、原因和可选的精确派生位置；
- 变体由 `code` 和明确的 `details.kind` 共同封闭；
- 分页、文档 ID、文档版本、陈旧版本拒绝和诊断上限继续沿用现有规则。

工作台当前只消费 V1 超拍时间告警，可以继续保持不变。播放计划和未来的诊断界面应读取 V2；桌面与浏览器宿主不得把未知 V2 变体投影成超拍提示。

## 播放与导出策略

播放计划按以下公式计算半音位置，只在最终比较后转换成播放器可用的小整数：

`12 × (writtenOctave + 1) + naturalSemitone(step) + alter + chromaticSemitones`

- 结果在 0–127：输出 `soundingMidi`；派生拼写不可表示不影响播放。
- 结果不在 0–127：输出 `soundingMidi: null`，跳过该音并保留计划中的事件、时值和定位信息。
- 计算使用足够宽的整数；任何层都不得使用 8 位转换、取模或夹值来“修复”越界。

未来 MIDI 导出必须显式报告被省略的音符；MusicXML 等需要音高拼写的导出器必须选择“保留书面音高与移调”或“拒绝该导出项”，不能静默生成不同音高。

## 实施顺序

1. 增加规则告警 V2 联合合同和精确编解码回归，保持 V1 完全兼容。
2. 从整谱 assessment、增量校验和 typed codec 中移除派生发声音高的阻断判定，同时保留书面音高与移调分量校验。
3. 从当前文档推导两个音高告警，并覆盖创建、导入、事务、撤销／重做、保存重开和版本绑定读取。
4. 更新 Rust 迁移预言机，只过滤退役的 `semantic.sounding-pitch-invalid`；其他音高错误继续精确对齐。
5. 播放计划按上述策略输出 `soundingMidi` 或 `null`，并用越界、可播放但拼写不可表示、普通可播放三组边界回归验证无截断。
