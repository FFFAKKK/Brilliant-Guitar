# 独立插件编辑复用已提交的 K1 功能分类

2026-09-14，改动前基线 `31196a4`。

## 行为与边界

独立模块命令现有写入类型只有音高和扩展数据。K1 功能分类依赖声部、
谱表、小节、拍号、时值、序列与和弦数量，不依赖音高或扩展内容。
因此，V3/V4 在当前提交版本已有完整分类报告时，复用该报告，避免
再次扫描全篇生成相同的功能分类。首次编辑仍生成完整报告。

复用前有两层约束：

- `module_net_changed` 检查实际 overlay，仅允许音高与扩展相关写入；
  其他记录、结构、顺序与引用变更导致拒绝。未来扩展模块写入类型时，
  必须重新检查该约束与 K1 分类依赖是否仍匹配。
- 缓存绑定当前已提交的 documentVersion，只在提交或 no-op 成功后更新。
  预评估、插件失败、语义失败、提交失败均不发布候选报告。

每次仍执行完整候选字节/深度/属性预算、Core 语义校验、可用性检查、
模块验证/分类与响应预算。特别是合法书写音高经过乐器移调后可能非法，
缓存不能代替这些语义检查。

Core 命令、纯 Core Batch、混合 Batch、撤销与重做仍完整生成 Core 报告，
成功后刷新缓存。旧宿主回调路径保持完整评估。缓存只保存派生报告，
不引入另一份文档状态；公开接口和报告内容不变。

## 诊断上限问题

冻结压力文档有 6,401 条 K1 不支持提示：1 条 part-count、6,400 条
voice-count。它们不是语义错误，但当前提交协议要求完整报告，而 Rust
报告上限是 4,096 条。这个矛盾仍使压力编辑回滚。

本轮没有截断、伪造 supported、调整冻结样本或提高上限来掩盖问题。
后续需要把编辑有效性与功能报告交付方式明确分离，并定义有完整性标识、
资源预算和稳定顺序的报告协议；不能无说明地给旧的完整报告附加截断语义。
当前压力回归继续要求明确超限失败且状态、历史和事件不变。

## 验证内容

- Rust 定向计数证明：首次独立模块编辑扫描分类一次，后续重复/失败尝试
  复用分类但继续调用验证器；不匹配版本会重新扫描。
- 构造语义非法候选，确认缓存的 supported 不会使其通过。
- 构造结构变化后被插件拒绝的候选，确认新分类不污染已提交版本。
- 真实 Native/Wasm 与 TS 对照覆盖：首次编辑、no-op、拍号导致的
  supported/unsupported 转换、混合 Batch、撤销/重做、结构失败、
  移调导致的非法发声音高、失败后继续编辑，以及完整结果和事件。

本轮仍保留完整语义/预算扫描、最终文档投影与完整报告复制。它只是减少
分类重复工作的增量，不是完整增量内核，也不是商业性能资格通过。
