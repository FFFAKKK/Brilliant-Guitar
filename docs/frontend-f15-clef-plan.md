# F15 谱号能力方案

日期：2026-09-18。

## 实现状态

浏览器端“初始谱号”闭环已经完成。现有 Core 的 `StaffDefinition.defaultClef` 和 `core.staff.set-definition` 足以保存谱表初始谱号，因此乐谱属性的“音乐结构”分区现在支持高音、低音、中音和次中音谱号，并可撤销／重做。

工作台 Projection、VexFlow 音符绘制、谱面垂直空间、鼠标音高换算、悬浮音符预览和页面无障碍描述均使用同一个谱号上下文。浏览器已实际验证高音谱号切换为低音谱号，333 项工作台测试通过。

中途谱号变化尚未实现。当前 Core 只有谱表默认谱号，没有带位置的谱号时间线；前端不增加无法保存的上下文控件。

## 组件归属

- 初始谱号：统一“乐谱属性／音乐结构”分区。
- 中途谱号：以后从目标小节、现有谱号或记谱弹窗进入。
- 谱号不创建常驻停靠组件，也不放入音符控制器。
- 吉他六线谱、打击乐谱表等特殊谱式由对应记谱插件声明自己的谱号或谱表语义。

## 当前支持

| UI 名称 | Core `Clef` | VexFlow |
|---|---|---|
| 高音谱号 | `{ sign: "G", line: 2 }` | `treble` |
| 低音谱号 | `{ sign: "F", line: 4 }` | `bass` |
| 中音谱号 | `{ sign: "C", line: 3 }` | `alto` |
| 次中音谱号 | `{ sign: "C", line: 4 }` | `tenor` |

不支持的 G／F／C 谱号线位继续产生明确的 unsupported Projection，不静默改成高音谱号。

## 中途谱号变化所需 Core 合同

建议增加带音乐位置和谱表作用域的实体：

```typescript
interface ClefChange {
  readonly id: string;
  readonly staffId: string;
  readonly position: {
    readonly measureId: string;
    readonly offset: Fraction;
  };
  readonly clef: Clef;
}
```

- 数据合同保留小节内位置，第一版 UI 可以先限制在事件边界或小节起点。
- 新谱号从变化位置持续生效，直到同一谱表的下一次谱号变化。
- 系统开头是否重复显示有效谱号属于派生排版。
- 系统末尾预告谱号属于派生排版，不生成额外音乐实体。
- 修改谱号只改变音高的垂直解释和显示，不改变已有书写音高。
- 删除变化后恢复前一个有效谱号，并形成一笔可撤销事务。

## 后续验收

1. 四种初始谱号保存、重开、撤销和重做正确。
2. 同一书写音高在四种谱号中落在符合规范的线位。
3. 鼠标点击同一几何线位时，输入音高随谱号正确变化。
4. 中途谱号变化在变化位置和后续系统正确显示，删除后恢复上一谱号。
5. 桌面宿主在全部前端能力完成后统一接线和验收。
