# 第一版操作频率地图

日期：2026-09-16。

本文是第一版前端功能取舍、入口位置和组件优先级的当前依据。它回答“用户要做什么、使用频率如何、功能应该以什么方式出现”，不直接规定每个组件的最终视觉稿。具体实施进度见 [第一版前端交付清单](frontend-v1-delivery-checklist.md)。

此前的 [工作台最小闭环组件审核清单](workbench-mvp-component-review.md) 保留已经完成的组件边界和实现历史；如果其中的早期组件名称、默认小节数或装配建议与本文冲突，以本文和交付清单为准。

## 一、第一版用户闭环

第一版围绕单文档、单谱表、单声部的基础五线谱编辑，固定主流程为：

```text
进入工作台并看到一小节空白谱
  → 定位输入位置
  → 连续输入音符或休止符
  → 选择并修改、删除、复制或移动内容
  → 撤销或重做
  → 试听与检查
  → 保存
  → 重新打开并继续编辑
```

功能只有进入这条闭环，或明确负责支撑这条闭环时，才进入第一版默认界面。六线谱、MIDI、音色、波形和吉他技巧由后续插件能力提供，不借第一版的名义提前占用工作区。

## 二、频率分级

频率描述用户在核心编谱流程中的操作次数，不代表功能的重要性。

| 级别 | 判断标准 | 默认呈现方式 |
|---|---|---|
| 高频 | 连续编辑时反复执行，一分钟内可能使用多次 | 常驻、紧邻谱面、单步可达、必须支持键盘 |
| 中频 | 一次编辑会话中偶尔执行数次 | 紧凑工具、上下文操作、可折叠或可固定 |
| 低频 | 通常每份乐谱或每次会话只执行零到两次 | 菜单、弹出编辑器、属性页或对话框，默认不占停靠区 |

三级频率是呈现策略，不是新的 UI 组件类型。现有 `view`、`tool`、`inspector`、`status` 仍表示技术职责；`inline`、`panel`、`popover`、`dialog` 仍表示呈现方式。

## 三、频率以外的三个判断维度

不能仅因为两个功能都是低频，就把它们塞进同一个面板。每项功能还要标明：

1. **操作对象**：应用、文件、乐谱、谱表、小节、选区、音符、视口或播放会话。
2. **作用范围**：全局、整份文档、从当前小节开始、当前小节、当前选区或临时输入状态。
3. **操作后果**：是否修改音乐文档、是否进入撤销历史、是否需要确认、是否只改变显示。

只有操作对象、工作阶段、作用范围和用户心理预期接近的功能，才适合合并展示。

## 四、呈现规则

### 1. 高频操作

- 默认常驻，但保持紧凑，不用标题、说明文字和重复边框占据空间。
- 鼠标、键盘和菜单入口必须调用同一项命令。
- 切换到其他控件时，谱面光标、播放和非阻塞动画不能假性暂停。
- 窄窗口中优先缩为图标入口或弹出完整内容，不把内部控件压坏。

### 2. 中频操作

- 默认可发现，不一定持续展开。
- 与当前对象密切相关的操作放到上下文工具或选区附近。
- 需要连续使用的中频工具允许固定到共享停靠区。
- 不因增加一个命令就增加一个永久面板。

### 3. 低频操作

- 默认通过导航菜单、对象上下文菜单、属性页或命令弹窗进入。
- 同一领域的低频命令可以共享入口，但内部仍保持独立命令和校验。
- 专业用户以后可以把低频命令固定到自定义工具栏；第一版不因此预留空面板。

### 4. 频率之外的例外

- **高后果状态**可以常驻。例如保存操作不是每分钟发生，但未保存／保存中／保存失败需要在文件入口附近持续可见。
- **恢复性操作**必须容易到达。撤销、重做和取消不能藏进深层菜单。
- **破坏性操作**可以低频，但需要明确目标、结果和撤销能力，不能只依赖一个无说明图标。
- **初学者可发现性**由合理默认布局、菜单命名、工具提示和快捷键提示解决，不用把所有能力同时铺开。

## 六、拍号功能的固定归属

拍号是一项独立的乐谱结构能力，但第一版不为它创建默认常驻组件。

- `L04 初始拍号`：放入乐谱属性或新建乐谱的高级设置，因为它描述乐谱开始时的结构。
- `L05 中途拍号变化`：作为拍号功能的子流程，在用户选中某个小节或已有拍号时打开紧凑弹窗，明确显示“从第几小节开始生效”。
- 两个入口调用同一个拍号命令和校验，不分别维护拍号状态。
- 拍号变化涉及已有小节容量、重排、拒绝条件和撤销边界；这些细节等进入 `L04/L05` 设计阶段时单独审核，不在当前阶段仓促决定。
- 后续可以允许专业用户把常用拍号固定到自定义工具栏，但第一版不为空面板预留位置。

调号、谱号和速度记号采用同一组织原则：能力独立，默认入口按作用范围分为初始设置和上下文修改，不能因为低频而全部混成一个无边界的“总属性”表单。

## 七、合并与拆分规则

### 可以合并展示

- 同时影响下一次输入和当前所选音符的音高、组号、时值、附点、休止与变音，统一由音符控制承载，并明确显示当前操作对象。
- 播放、暂停和停止属于同一个高频传输控制；循环、节拍器和试听速度可以作为它的展开内容。
- 标题、作者、版权等整份乐谱元数据可以放在同一个乐谱属性页面。

### 不应合并展示

- 乐谱速度记号与临时试听速度：前者写入音乐文档，后者只改变播放会话。
- 音符占小节比例与谱面当前位置：前者是事件时值，后者是编辑位置，即使视觉上相邻也必须分清标签和层次。
- 文件保存状态与输入／选区状态：信息来源和用户任务不同，应靠近各自入口。
- 初始拍号与中途拍号变化：底层能力共享，入口和作用范围必须区分。

## 八、后续校准

当前频率分级是基于第一版核心流程的设计假设，不是假装已经拥有用户遥测。每完成一组能力，验收时记录：

- 完成核心任务时的操作次数和路径长度；
- 用户是否能在没有解释的情况下找到入口；
- 是否频繁在菜单和停靠区之间往返；
- 窄窗口中是否仍可完成同一任务；
- 是否存在长期不使用却持续占据空间的控件。

如果实际流程与分级冲突，先更新本文，再调整组件位置；不能让现有界面反过来绑架操作分类。

## 九、参考原则

- [Microsoft Windows 应用命令设计](https://learn.microsoft.com/windows/apps/design/controls/commanding-basics)：持续完成核心场景所需的命令应靠近内容，偶尔使用的命令适合菜单或上下文菜单。
- [Apple Human Interface Guidelines：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：工具栏优先容纳常用和重要操作，次要操作进入更多菜单，并为需要的场景提供定制。
- [MuseScore Studio：Palettes](https://handbook.musescore.org/en_gb/basics/using-the-palettes)：按音乐类别组织可折叠、可搜索、可停靠的记号入口，避免把全部记号永久铺开。
- [MuseScore Studio：Time signatures](https://handbook.musescore.org/notation/rhythm-meter-and-measures/time-signatures)：新建时的初始拍号与编辑中的拍号应用具有不同入口和作用范围。
