# M3.1：真实文本读取工具与反馈闭环方案 v1

日期：2026-10-08。基线：M3.0提交`8cf0103`。状态：用户批准后已实现并完成M31-A1–A4本地验收；Runtime23/23、应用53/53、Workbench Agent222/222及类型/隔离构建/边界/独立打包/实际浏览器通过。证据见任务research/m31-verification.md。未提交；M31-A5/M30-A5真实回答质量与A10两轮/停止仍独立待验收。

## 1. 目标与使用效果

让独立Agent真实使用用户提供的资料，完成“模型提出调用 → Controller校验与执行 → 返回对应结果 → 模型回答”，并让用户看见执行状态。

第一版推荐在输入框旁增加“添加文本”按钮，用户选择UTF-8 `.txt`或`.md`文件。页面显示文件名、大小和移除入口。用户提交“读取这份练习记录，列出问题并给出安排”后，工具卡片显示正在读取、已完成、失败或已停止，回答使用实际读取的内容。

添加资料和发起模型请求是两个操作。添加本身不发起模型通信；只有手动启用并提交消息后，Agent才可能调用工具。

## 2. 资源与权限

- 浏览器读取用户主动选择的文件，严格解码UTF-8后上传到Node宿主。宿主保存本次选择的不可变文本快照，工具读取该快照；不是按模型给出的磁盘路径读取文件。
- 一个活动会话最多3个文本快照，每个原文件及解码后的文本均不超过32KiB。仅接受`.txt`/`.md`、有效UTF-8和有界文件名，拒绝二进制、错误编码及超限输入，不静默截断。
- 接受后由宿主产生不透明`resourceId`和`version=1`，绑定当前`sessionId`。文件名只是展示信息，不是资源身份、路径或执行指令。
- 公共快照只给出资源ID、版本、名称、字节数和字符数。正文进入下一次模型输入的时机是实际工具读取成功之后；上传不代表全文已经进入上下文。
- 模型知道当前资源目录以及读取工具的参数说明，不能自行授予资源访问权限。执行器再次核对会话、资源ID和取消状态；其他会话ID、未知ID及已移除ID均不读取。
- 活动Run期间禁止添加或移除，防止模型看到的资源目录与执行时不同。添加/移除请求携带会话ID，迟到上传不能落到新会话。
- 第一版资源仅在当前会话的宿主内存中保存；切换/新建会话或退出宿主释放它们。刷新页面可从仍运行的宿主恢复目录。界面提示“本次会话临时资料”，历史聊天恢复不重新授权读取。
- 快照不跟踪磁盘文件后续修改。用户需要新版资料时先停止任务、移除旧快照并重新添加；新快照取得新ID。

这解决当前任务的资料一致性。以后真正修改乐谱时，仍使用原有文档版本、ChangeSet和冲突检查，不能把本次文本快照设计当作乐谱写入锁。

## 3. 第一个工具

候选能力ID：`resource.read-text`，合同版本1，query、constant、无需乐谱、无写入或网络副作用。它通过`AgentToolRegistry`注册，由同一个Controller执行，Pi不接触处理器。

```ts
// 参数草案；严格校验，拒绝未知字段。
{ resourceId: string, start: number, maxCharacters: number }

// 成功data草案；由真实快照生成。
{
  resourceId: string, version: 1, name: string,
  start: number, nextStart: number, totalCharacters: number,
  text: string, eof: boolean, contentTrust: "user-provided"
}
```

- `start`从0开始，按Unicode字符而非UTF-16半个代理对计数；`maxCharacters`为1–4096。使用返回的`nextStart`继续读取，不靠模型猜下一页位置。
- 每页完整JSON结果限制为12KiB，包含转义和元数据；可返回比请求更少的字符，`nextStart`和`eof`必须反映实际内容。预算内的内容不截断后冒充完整文件。
- 文件包含`system:`、提示词或工具调用文字时仍为用户资料。工具确实执行与资料正文可信度是两件事；执行来源和`contentTrust`分别保留。
- 未授权资源、非法范围或取消走明确失败/取消语义。沿用现有Controller“能力失败结束Run”的行为；第一版不同时实现自动重试或自我修复。
- 仍受每轮4个工具、每Run最多16次决策、工具结果大小及M3.0最终模型输入预算限制。资源可以上传不表示全部正文一定能同时放进模型上下文。

## 4. 真正的调用反馈

现有Controller已存执行记录，但`capability-result`主要是结果正文，缺少可直接回放的原始模型callId关联。单独注册工具不能补足这部分。

推荐增加通用、可选的内部执行反馈记录，包含：来源turnId、模型callId、宿主invocationId、capabilityId、contractVersion、已校验参数、真实结果及来源。它由Controller在真实执行路径中建立，不根据任意资料正文拼造，也不让插件修改执行事实。

- 每组模型调用与对应全部结果形成一个单元。成功后才进入后续决策；多调用组必须保持顺序和ID对应。缺失、重复或错配结果不能投影成成功回放。
- Pi第一轮仍用`prompt()`。读取后的决策从已恢复的当前任务消息继续，形成`user → assistant(tool calls) → tool results → assistant`；复用已安装Pi 1.0.3的`continue()`，不重复发送当前问题。
- Model Host为本次请求的工具声明及合法历史工具名建立同一别名表。历史名称加入映射只用于回放，不能使它重新成为可调用工具；新的调用仍按当前toolset和Controller权限校验。
- Pi投影避免把已经回放的同一结果正文又复制进普通资料。外部Agent v1仍从既有来源明确的context接收反馈，不增加v1未知字段；增强的内部记录不会成为第二条执行链。
- 完整调用/结果组纳入最终预算，不能只删结果留下悬空调用。先省略可选聊天历史；本Run必需反馈仍超限时停止模型通信并报告预算错误，不重读文件来掩盖它。
- 第一版增强回放作用于本次新执行Run。旧持久记录若没有真实callId关联，继续原有资料投影；不从聊天文本重建或自动重放工具。完整持久执行回放另行设计。

## 5. 最小执行界面与宿主合同

界面保持当前独立聊天布局，增加资料列表和本次Run的折叠工具卡片。卡片依据Controller的权威活动事件，展示名称、invocation身份、开始/结束及失败/取消状态，不从回复里推断“已完成”。

候选Node API：

| API | 精确请求 / 行为 |
| --- | --- |
| POST `/api/resources/add` | `{sessionId,name,text}`，验证后返回宿主快照 |
| POST `/api/resources/remove` | `{sessionId,resourceId}`，活动Run期间409 |
| GET `/api/session`、既有SSE | 返回同一权威快照，包括当前资源目录和工具活动 |

推荐将独立宿主快照从严格v3显式升为v4，增加`resources`与`activities`，同时更新decoder、客户端和测试，不给v3偷偷增加字段。资源上传端点单独允许最大256KiB JSON请求体，以容纳32KiB正文的JSON转义；其他命令保留64KiB限制，实际正文限制由宿主再次检查。

Runtime Session提供经过runId/代次过滤的活动观察入口，Host据此维护有界工具活动列表。新Run、新会话及dispose隔离旧活动；取消中的迟到完成不能覆盖取消。观察者异常不能影响执行。

资源正文和工具活动不写入聊天文件v1。刷新/断线恢复当前宿主状态，不重放执行；退出后的聊天保留原有中断语义。M3.3再处理长期活动时间线、供应商实际usage和费用。

连接探测使用独立无工具Session，不获得已添加资源。保存设置、添加文本、GET快照及SSE重连均不触发供应商请求。

## 6. 实施顺序与边界

1. **反馈记录**：先补Controller创建的调用/结果关联和Pi继续输入，验证完整组、别名、去重、预算及取消。源记录与External v1保持兼容。
2. **资源工具**：Node宿主保存真实文本快照；Runtime增加宿主上下文/活动注入入口，复用Registry、策略和执行器，不导入文件系统或UI。
3. **宿主桥接**：严格资源命令、同origin检查、忙状态/会话身份、v4快照与SSE。同步客户端decoder。
4. **界面**：真实文件选择、上传/移除反馈、临时资料说明与工具卡片，保留启用/停止/会话管理。
5. **检查与展示**：本机模型fixture配真实资源读取，检查实际wire、页面操作和桌面/390px；真实DeepSeek由用户手动触发，提交前单独展示本批清单。

主要触及：Runtime的provider/Controller/Session/Pi投影与预算，Node的resource工具/Host/模型别名/HTTP，独立客户端的资源和活动组件/decoder，以及对应测试、规范和文档。Workbench只做共享Runtime兼容回归，不修改乐谱工具；不修改其他窗口的notation/plugin/desktop/shared工作。

## 7. 固定验收

| 场景 | 必须验证 |
| --- | --- |
| 读取实际TXT/MD | 模型第一次只收到资源目录；工具实际读取后，下一次wire包含对应call ID及真实文本，执行次数可数 |
| 分页与Unicode | 中文/emoji完整；nextStart可连续读取，页大小包含JSON转义，eof真实 |
| 多调用 | 每个call与result一一对应，顺序正确，不重复正文，不多执行 |
| 授权/失效 | 未知或另一会话资源无真实读取；移除、切换和重启无残留授权 |
| 一致性 | 运行中变更拒绝；迟到上传/工具响应不落到新会话 |
| 失败/取消 | 卡片与Controller状态一致，停止后不再进入新的模型决策；读取失败不冒充已完成 |
| 超预算 | 调用与结果整组保留或明确拒绝，不删成孤立tool消息；拒绝后的供应商请求为零 |
| 静默操作 | 打开页面、上传、保存、probe和SSE重连无隐式工具执行或生成 |
| 兼容 | 无资料对话、Pi、External v1、乐谱读取/审批/恢复回归通过；聊天文件v1保持 |

第一版不包含PDF/图片/目录遍历、文件写入、终端、网页搜索、AGENTS.md、长期记忆、MCP、评分/检索、自主重试或工具执行持久化。这些仍按计划书的后续里程碑处理。

## 8. 为什么先做这一块

M3.0改善模型接收的职责与历史。M3.1给它可验证的新信息来源，让它根据实际资料完成任务。二者分别验证；不能把“加了工具”当成模型回答质量已经合格的证据。

用户已确认：先采用主动选择的TXT/MD快照（最多3份、每份32KiB），同时完成读取工具、反馈闭环和最小活动界面。按上述顺序实施；功能和验收的完成状态以任务计划书及实际证据为准。真实供应商请求仍由用户手动触发。
