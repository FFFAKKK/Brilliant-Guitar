# M3.2b 旧对话词面排序评估 v1

日期：2026-10-08。运行基线：78cac1e。结论：**保留现有时间排序，不把本版词面评分接入生产。** 本批交付可重放的离线比较及结论，不修改Agent运行策略、Pi、模型接入、权限或公开协议。

## 评估的是什么

模块仍是通用Agent Runtime的上下文选择。M3.2a已交付近两轮保护、真实工具结果和预算；本次b只比较保护范围之外、已通过会话校验、可以省略的旧成功对话。当前要求、近两轮、必需事实和实际反馈不参加评分竞争。

数据是20个事先写定的合成样例，不是用户聊天或商业Agent榜单。每个样例用neededTurnIds标出回答需要回看的旧轮及理由；19个样例有标签、1个零预算控制。合计21个目标源轮，其中1个已在16轮候选窗口之外。后10个为预留复核组（同一作者设计，非盲测；不是对真实任务泛化能力的证明）。首次运行后没有改样例、标签或权重。

## 公平比较方法

- 时间基线调用现有ContextBuilder/standalone-context-v1，实际核对保护轮、选中ID和完整原文。统一16轮成功历史窗口、8192估算预算及每例0/1/2个完整旧轮槽位，比较时槽位数量是受限资源，不冒充真实Pi token预算实验。
- 词面基线只读候选用户原文，使用NFKC、小写、中文相邻双字、英文/数字词，去重。每次排名扫描最多2048 code points、256词项。得分=查询中被候选命中的唯一词项数/查询唯一词项数，没有调权重。
- 比较“当前问题”与“当前问题+最近两轮用户原文”两种查询；同分按新到旧，选择后恢复原对话顺序。扫描限制只影响排名，选中轮原文不裁剪。失败/取消/中断不进入候选，不读取文件正文、调用工具或请求模型。
- 指标是**标注源轮的召回率**：选中的目标源轮数/目标源轮数。窗口内召回率剔除本来不可见的目标；同时保留包含窗口外目标的总召回。它不是模型答对率、事实正确率或用户满意度。

## 这些结果说明什么

**相似不等于当前有效。** c05里旧“每天20分钟节奏训练时间安排”重复了很多问题关键词，新的“更正：只剩12分钟”字面相似度低。保护范围之外采用时间排序能保留较新修正，词面排序却把已过时的旧要求换回来。提高分数本身不会识别替代关系。

**查询拼接也有代价。** c03的“继续细化”借助近两轮话题找到旧音阶方案；c09已明确切回八分音符，拼入最近的UI话题却抢走了名额。两个查询方案总分一样，逐例行为不同；不能只看平均数。

**扫描和窗口是能力边界。** c16排名只看前2048字符，漏掉后面的新要求；c15目标已在16轮窗口之外，窗口内任何排序都找不到它。c17当前用户明确引用先前助手示范，但只排名用户原文会漏掉助手正文中的相关内容。不能用无限扩大扫描或给助手文本升级权限来掩盖这些边界。

因此本版评分保留为实验，不增加运行时开关、分数公开字段或另一套选择器。若真实验收证明经常遗忘较早的有效要求，应另行设计任务状态中约束的来源、更新和撤销关系，再评估是否需要检索；本轮没有实现自动事实提取或长期记忆。
