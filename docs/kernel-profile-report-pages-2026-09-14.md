# Core 功能报告有界分页 V2

2026-09-14，改动前基线 `4e518de`。

## 当前完成的能力

Foundation 提供 `assess_score_profile_page_v2`，Rust 集成会话增加显式、
私有的 `readCoreReportPage` 操作。功能提示可以超出 4,096 条总量，
每次最多返回 4,096 条，并保留完整总数、原始顺序和下一页位置。
它与原有完整报告共用同一个功能规则遍历，没有另写一套简化规则。

这完成的是报告读取能力。编辑事务目前仍返回旧版完整报告，
其 4,096 条总量上限没有改变。因此冻结压力规模的编辑仍会拒绝，
不能将本轮标记为容量问题整体解决或商业资格通过。

## 私有会话协议

请求必须且只能包含以下字段：

```json
{
  "operation": "readCoreReportPage",
  "reportVersion": 2,
  "documentId": "score-1",
  "documentVersion": 0,
  "profileId": "brilliant-guitar.k1",
  "offset": 0,
  "limit": 1024
}
```

成功返回 `ok: true` 和 `report`。报告包含 `reportVersion`、
`documentId`、`documentVersion`、`profileId`、`status`、`offset`、
`total`、`diagnostics`、`nextOffset`。

- `limit` 是 1..=4096 的整数，`offset` 是非负安全整数。
  `offset == total` 返回空末页；`offset > total` 拒绝。
- `status` 是整份报告的状态，与当前页是否为空无关。
- `nextOffset: null` 表示已到末尾；非空值表示下一段的起始位置。
  总数与下一页信息明确表明这一页不是完整报告。
- `documentId`、版本和固定 K1 配置必须匹配当前会话。
  编辑或撤销导致版本变化后，旧请求均返回 `report.stale-version`；
  即使撤销恢复原始内容，旧版本也不会复活。
- 相同版本重复读取同一页得到相同结果，没有消耗型游标。
- 读取不执行插件，不提交 Store，不改变历史、dirty 或分类缓存。
  会话同步借用确保读取过程中不存在中途换版。
- 返回诊断保持现有 code、messageKey、path、details 契约。
  原请求/响应字节与解码资源边界继续生效。

私有失败码：

| 条件 | failure.code |
| --- | --- |
| 字段、版本、配置、页大小或整数格式错误 | `report.invalid-request` |
| 文档 ID 不匹配 | `report.document-mismatch` |
| 文档版本不匹配 | `report.stale-version` |
| offset 大于报告总数 | `report.offset-out-of-bounds`，含 total |

错误仍通过现有会话失败封装返回当前文档版本和历史。
未增加公开 TS 导出、公开 CommandBus 报告类型或 Native 顶层 ABI 名称。

## 资源和正确性边界

分页函数先执行原有语义校验。非法语义压制所有 unsupported 提示；
语义诊断仍保留旧的 4,096 条上限，超限仍是明确的机制失败。
功能报告遍历只为当前页建立诊断对象，其他位置只计数，
不先创建完整报告再切片。计数采用 checked arithmetic。

当前每页仍导出完整强类型文档并重新执行语义和功能扫描。
因此时间成本随页数重复；文档投影和语义校验也有自己的内存成本。
此实现只限制报告条目的保留量，不代表整个操作是常数内存、
增量读取或性能合格。Foundation 不持有会话状态，跨调用版本一致性
由 Runtime 请求校验负责。

## 验证范围

- 6,401 条受控功能提示逐页全部读取，对照独立构造的完整路径序列；
  重复读取和末页读取一致，源文档不变。
- 不同页大小结果拼接后与旧 V1 完整报告一致，覆盖混合规则顺序。
- 支持/不支持的空末页有明确状态；负数、小数、超安全整数、
  多余/缺失字段、配置错误、越界 offset 均验证。
- 语义错误优先，4,097 条语义诊断仍拒绝，非法分页参数先于语义扫描失败。
- 实际 Rust 会话读取 4,097 条提示，没有插件回调或历史变化。
  修改和撤销后旧分页请求始终过期，新版本可正常读取。
- Native 测试使用未经修改的冻结压力文档（102,400 事件）；
  6,401 条报告逐条与 TS 功能报告参考实现比较，并验证重复页和会话不变。
  旧 addon 先复现 `command.invalid-envelope`，用于确认新能力的测试有效。

最终结果：Rust 全量 597 通过、1 忽略；Node 全量 893 通过、
2 跳过、0 失败。严格 Clippy、fmt、Rust 1.88 全目标/全功能检查及
TS 严格类型检查通过。Core、Integrated、Wasm 三种 addon 均从本轮
源码重建，完整 Node 回归在重建完成后执行。
Native 专项在新产物上通过，逐条比较的冻结压力文档报告完全一致。
产物 SHA-256 与验证摘要记录在
`docs/evidence/profile-report-pages-2026-09-14.json`。
本轮没有性能资格测量，不能用测试耗时推导产品操作延迟。
