# 导航栏组件规划

2026-09-13。仅设计导航栏；本轮不设计谱面工作区、记谱工具条或其他组件，不修改应用代码。当前预览均待用户选择，不视为已批准实现稿。

## 设计问题

用户否决了上一张导航与谱面组合图中的导航栏，明确要求现代、美观、有层次，避免光秃秃的一排文字；同时保留此前紧凑、组件化、不照抄成熟厂商的要求。

本轮将导航栏单独作为组件设计。通过品牌识别、文档上下文、操作分组、表面细节与状态层次提高完成度，不通过加入账户头像、分享、AI、播放或大量新功能填满空间。

## 内容与职责

| 子组件 | 内容 | 交互责任 |
|---|---|---|
| 品牌与主菜单 | 原创小型标记、Brilliant Guitar、文件/编辑/视图 | 文件级及应用级入口保持可发现；品牌区不默认跳转外站 |
| 文档上下文 | 当前文档名、状态、可选文档操作菜单 | 当前单文档；不伪造团队/工程目录或多文档标签 |
| 历史操作组 | 撤销/重做 | 使用统一动作及可用性；没有历史时显示禁用态 |
| 布局入口 | 布局图标与文字 | 将来调整工作台组件显示/布局；预览不代表功能已实现 |
| 保存动作 | 明确的“保存”按钮 | 使用宿主文件能力；首次保存和另存为才收集文件名，不影响音符直接输入 |

视觉上组织成三段：品牌/菜单、文档上下文、常用操作。三种候选探索这三段的不同组合方式，单独检查导航栏即可比较。

## 样式方向

- 单行高度先探索56–64px，控件高度约32–36px，文字14px，图标18px。此前44px是草案建议，不是限制本轮设计的硬合同。
- 品牌标记约28px，原创图形，不复用厂商 Logo；字体、图标线宽和控件状态统一。
- 通过轻微底色、细边界、局部分组建立层次，避免所有文字直接均匀排在一条空白线上。
- 允许适量6–8px圆角与细阴影；不把导航膨胀成多个大卡片或多行工具墙。
- 保存是小而明确的强调动作；保存状态附着文档，不能只有一个无法解释的圆点。
- 图像采用导航局部的宽幅容器，指定1440×220设计画布；实际导航只占其中一条紧凑横带，其余仅为展示边距，不作为应用空白区域实现。

## 状态与响应

- 保存状态区分：未保存、保存中、已保存、保存失败；文本和形状同时表达，不只依靠颜色。失败时继续显示未保存事实与重试入口。
- 文档名较长时省略并可查看完整名称；不挤走保存和主菜单。
- 窄窗口优先缩短品牌文字、压缩菜单组；文档身份、文件入口与保存动作保留。具体断点由组件原型验证，不在效果图里假装已验证。
- 菜单支持键盘操作与Esc关闭；退出菜单后将焦点归还来源。快捷键复用应用动作，不在导航中实现独立编辑逻辑。
- 保存忙碌状态防止重复请求。无文档状态不展示虚假已保存状态，文档相关动作根据能力禁用或收起。
- 这是应用内部固定导航组件。系统标题栏、窗口最小化/关闭、拖动窗口区域属于宿主集成另行处理。

## 模块边界

导航接收文档显示信息、保存状态、动作可用性及动作回调，不接收可写ScoreDocument，不导入内核实现。

视觉基础提供按钮、菜单、分隔、状态标签和语义颜色；导航只负责编排。文件/编辑/视图菜单内容来自所属功能模块的公开动作定义，避免每个入口各写一套业务逻辑。

布局入口与保存入口分别作用于工作台配置和音乐文件；二者的状态与历史不得混用。各子组件可以单独理解和验证，但无需全部变成可安装插件。
