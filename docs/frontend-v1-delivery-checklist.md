# 第一版前端交付清单

日期：2026-09-18。

本文把 [第一版操作频率地图](frontend-v1-operation-frequency-map.md) 转换成逐项审核和交付顺序。它是后续前端工作的任务清单，不创建 Trellis 任务，也不把未审核的功能直接装进界面。

## 一、状态定义

| 状态 | 含义 |
|---|---|
| `已验收` | 用户已经看过实际浏览器表现并同意当前版本可继续 |
| `已实现` | 真实功能已接入并验证，但仍可能需要用户视觉验收 |
| `部分完成` | 已有可用切片，明确还有业务或交互缺口 |
| `方案待审核` | 已完成调研和设计方案，等待用户确认后实施 |
| `待规划` | 只记录需求；轮到该项时先调研和出方案 |
| `后续版本` | 不进入第一版默认闭环，本期只保留扩展边界 |

“代码存在”不等于“已验收”；静态按钮存在也不等于功能已实现。

## 二、每项功能的固定流程

除修复明显回归外，每个新功能按下面顺序推进：

1. 查阅领域规范和成熟商业软件的交互方式。
2. 明确操作频率、对象、作用范围、状态来源和撤销边界。
3. 给出组件或弹窗的功能清单、布局草图和窄窗口表现。
4. 用户审核方案。
5. 接入真实业务能力，不制作无法执行的假控件。
6. 在 `http://127.0.0.1:5173/` 打开浏览器完成实际交互验证。
7. 根据用户反馈修改，明确标为“已验收”。
8. 更新本文和操作频率地图中的状态、遗留问题与决定。

桌面宿主只在阶段性交付时统一接入验证；日常组件审核继续使用本地浏览器。

## 六、已经固定的跨功能决定

1. 工作台中不显示项目或产品名称；名称留给桌面图标、窗口元数据和关于页面。
2. 文件操作属于宿主命令和导航菜单，不是可停靠业务组件。
3. 左右停靠区显隐不得推动中央谱面；上下区域可以参与高度分配。
4. 四个共享停靠区默认展开，用户可以明确关闭并再次开启。
5. 停靠区本身不显示“左停靠区”等占位文字；空区域保持简洁。
6. 组件宿主只负责尺寸、停靠、显隐、焦点和生命周期，不强制所有组件使用同一张卡片外观。
7. 具体组件必须提供窄宽、正常宽度和收起图标三种有效表现，不能只靠压缩桌面版布局。
8. 音符属性不再建立重复检查器；输入和选择修改统一由音符控制承担。
9. 音符占小节比例与谱面位置是不同信息，允许相邻显示，但必须有明确层次。
10. 高频、中频和低频是入口策略，不取代业务领域、组件职责和作用范围。
11. 低频功能可以共用属性页或命令入口，底层命令、校验、撤销和上下文范围仍保持独立。
12. 拍号的中途变化记录在拍号任务下，等进入 F13 时再详细设计，不提前做假控件。
13. 所有新组件先出计划或视觉方案，用户审核后再实现；每次修改在本地浏览器展示实际效果。
14. 核心组件全部稳定以后再统一提高视觉丰富度和高级动画，不用装饰掩盖布局或交互问题。

## 七、推荐的近期顺序

1. F09 精确光标与键盘导航。
2. F10 基础播放控制和真实播放服务。
3. F11 范围选择与剪贴编辑。
4. F12 小节结构操作。
5. F13 拍号能力。

顺序不是永久冻结：如果某项底层能力尚不存在，就先完成其最小真实服务，再进行 UI 设计；不能用静态界面冒充完成。
