# 历史预览与提交准备复用

## 本轮范围

基线为 `199f06c`。集成会话此前先重放历史生成插件评估文档，
评估通过后又重放相同历史、执行最终语义校验并准备提交。

现在，对于 typed prefix 的正向和逆向操作列表均为空、suffix 非空的
Candidate 历史，一次重放同时产出独立的评估文档和拥有自身数据的提交计划。
插件评估及回复空间预留通过后，提交直接消费该计划。
Core/module Batch 使用这条路径；普通 typed 历史和非空 typed prefix
混合历史继续使用原有实现。

此修改没有新增公开接口、默认切换或插件业务能力。
普通 V1 `undo`/`redo` 仍使用原来的准备路径。

## 安全与可观察行为

- 预览阶段保留日志前置条件、逆向起点身份验证及最终语义校验。
- 提交计划中的索引/容量准备错误延迟到插件评估和回复空间预留之后处理，
  保持预览、插件评估、提交失败之间的优先次序。
- 私有准备结果绑定文档版本、当前历史身份、条目序号、方向及实际持有的
  `Arc<CandidateHistory>`。过期结果、错误方向和另一会话的条目均拒绝。
  提交计划还会核对目标文档 ID/版本，并在实际提交时预留 Store 空间。
- 插件拒绝或丢弃准备结果不会修改 Store、历史游标、版本或已发布报告。
  失败后可以重新准备并重试。
- 脏状态、保存标记和事件序列在实际提交时重新计算；
  `markPersisted` 不提升文档版本，也不能使预先计算的事件状态漏进提交。
- 实际发生过操作但净内容不变的历史仍提交、推进版本，并可撤销重做。
  原有操作数、历史逻辑字节数和受影响地址计数保留。
- 复用后的计划包含生成回调文档时的候选读取计数；
  工作指标不应与旧版仅计提交准备的读计数机械比较。

## 验证与测量口径

新增测试比较复用路径与原重放的文档、重建索引、历史、版本、事件和保存状态，
并覆盖净零操作历史、复杂 typed prefix 回退、错误方向、外来历史、过期版本、
丢弃准备结果、延迟错误及插件在撤销和重做阶段拒绝后重试。
语义无效逆向日志也必须在返回可评估预览之前失败。

性能诊断沿用 `scripts/profile-native-paged-batch.mjs`，
使用冻结的 25,600/102,400 事件输入和真实 Wasm fixture 插件，
分别验证混合 Batch、撤销、重做的状态、版本及完整编码哈希。
旧产物保存在 `target/history-reuse/prior-wasm-v1.node`，
新旧样本各自使用新进程，且测量时不并行构建或测试。
60 秒诊断期限、输入、脚本和 guest 不变。

这是单样本诊断，不是正式资格采样，也不能提供 p95/p99 或通用提升比例。
历史记录中的同版耗时存在较大波动，必须保留每次原始结果。

验证结果：

- Rust 默认配置：581 通过、1 忽略；全部功能开关：607 通过、1 忽略。
- 严格 Clippy、Rust 1.88 全功能检查、格式检查、TS 类型检查与构建通过。
- 三种 Native addon 均重建；Node 全量 894 通过、2 跳过、0 失败。
  包含压力文档真实 Wasm 操作及分页报告与 TS oracle 的逐项比较。
- 本轮四次串行新进程探针均在原 60 秒期限内完成；
  新旧输入编码、提交后编码、脚本、guest 哈希均一致。

## 剩余商业差距

此次减少了一次历史重放及对应的候选最终语义校验；
仍有完整文档投影、候选语义遍历、集成层 Core 语义/分类检查和插件评估。
非空 typed prefix 与普通 typed 历史尚未复用准备结果。

下一步应继续定位这些全量工作，按依赖范围缩小读取和评估，
并保持错误、报告、未知扩展、历史身份与原子提交契约。
正式延迟分位数、长序列/故障验收、真实 UI/业务插件集成和默认发布切换仍未完成。
本轮代表规模约 0.72 秒、压力规模约 3 秒的撤销/重做，
仍远高于冻结资格契约要求的毫秒级交互延迟。
