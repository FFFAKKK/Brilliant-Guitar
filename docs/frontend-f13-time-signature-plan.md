# F13 拍号能力方案

日期：2026-09-18。

## 实现状态

截至 2026-09-18，浏览器工作台闭环已经完成：应用 Action／Intent、统一编辑队列、连续拍号段解析、Core 批事务、乐谱属性分区、小节上下文入口、规则提示和回归测试均已接通。生产构建通过，相关 15 项回归测试通过，并已在本地浏览器实际验证 `4/4 → 3/4 → 撤销` 流程。

桌面应用仍按既定开发顺序留到全部前端能力完成后统一接线和验收；本切片没有修改 Rust 或 Core。

## 目标与组件归属

拍号是低频的乐谱结构能力，不创建新的常驻停靠组件或独立属性面板。它是统一“乐谱属性”组件中的一个结构分区。第一版提供两个入口：

1. 乐谱属性中的“初始拍号”，用于修改从第一小节开始的拍号段。
2. 小节上下文菜单中的“更改拍号…”，用于从指定小节建立或修改拍号变化。

两个入口打开同一套拍号编辑内容，并使用同一个应用层命令、校验和事务边界。五线谱负责显示拍号与变化位置，音符控制器不承载拍号功能。

“乐谱属性”组件的建议分区为：

1. 基本信息：标题、作者、版权。
2. 音乐结构：拍号、调号、谱号、速度记号。
3. 页面：纸张规格、方向、边距和排版范围。
4. 插件属性：由乐器或谱式插件通过受控扩展点注册。

这些分区共享一个对话框壳、焦点恢复、提交状态和错误反馈，但各自保留独立的应用意图与事务语义。

## 规范与成熟软件依据

- MusicXML 4.0 使用 numerator 对应的 `beats` 与 denominator 对应的 `beat-type` 表达拍号，也允许复合拍号和拍号显示形式。第一版先支持规则数字拍号，数据合同保留以后扩展复合拍号与 `common`／`cut` 显示的空间。
- Dorico 规定拍号从出现位置持续生效，直到下一个拍号变化或乐段结束；添加新拍号时不应无条件覆盖后续已有变化。
- MuseScore 将初始拍号放在新建乐谱流程，把中途拍号放在所选小节或拍号的上下文操作中；常用拍号与自定义拍号分层呈现。

## 第一版交互

### 入口

- 乐谱属性：在“音乐结构”分区提供当前初始拍号入口，点击展开或打开拍号编辑内容。
- 小节上下文菜单：在插入小节命令之前增加“更改拍号…”。菜单标题继续明确目标小节编号。
- 后续可以允许直接双击谱面上的拍号打开编辑器；第一版先不让普通音符区域的双击承担更多含义。

### 紧凑拍号编辑器

- 顶部显示目标：“初始拍号”或“从第 N 小节开始”。
- 常用选择：`2/4`、`3/4`、`4/4`、`6/8`、`9/8`、`12/8`。
- 自定义值：分子使用正整数输入，分母使用受支持音符值选择。
- 作用范围默认是“直到下一个拍号变化”；另提供“仅当前小节”，用于单独的不规则小节。
- 不加入大段说明文字。结果范围通过目标行和简短辅助文本表达。

第一版不提供复合拍号、交替拍号、自由拍号、局部谱表拍号、拍号外观文本、拍号隐藏和自定义连梁分组。这些能力进入后续高级记谱切片。

## 应用层合同

新增应用意图，而不是让 React 组件拼装 Core 命令：

```typescript
interface SetMeasureMeterAction {
  readonly kind: "set-measure-meter";
  readonly measureId: string;
  readonly meter: Readonly<{ numerator: number; denominator: number }>;
  readonly scope: "meter-run" | "measure";
}
```

- `measure` 只修改目标小节。
- `meter-run` 从目标小节开始，修改连续使用原拍号的区段，在下一个已经存在的不同拍号前停止。
- 应用服务读取当前文档后解析目标范围，保留每个小节的 pickup 定义，并把全部修改作为一个批事务提交。
- 整次操作只产生一个撤销步骤。重做恢复同一拍号段。
- 组件只提交乐谱语义意图，不接触 Rust DTO、Tauri command 或内核命令信封。

## 内核与现有能力

内核已经提供 `core.measure.set-definition`，并校验拍号分子、分母与小节目标。当前切片不需要修改 Rust 或 Core。

工作台需要补齐：

1. `ScoreEditAction` 和 `ScoreEditIntent` 的 `set-measure-meter` 分支。
2. 浏览器／桌面共用应用服务中的拍号段解析与批提交。
3. `useScoreInput` 的统一排队、忙碌、失败反馈和焦点恢复。
4. 乐谱属性与小节上下文菜单的同一编辑器入口。
5. 应用层测试、浏览器预览和最终桌面集成验证。

## 内容超出新拍号容量

修改拍号后，小节内容可能少于或超过新的名义容量：

- 不自动删除、截断或移动音乐内容。
- 不阻止拍号修改和文档保存。
- 继续使用现有内核规则诊断，把超拍小节标记为轻量警告。
- 不足拍保持已有留白表达，不自动写入新的休止符数据。
- 自动重分小节、移动后续事件和重新连音属于单独的“重排节奏”能力，不作为拍号编辑器的隐式副作用。

## 谱面显示

现有排版已经在首小节、每个系统开头以及拍号与前一小节不同时显示拍号。F13 接入后继续复用这条规则。

第一版暂不绘制系统末尾的预告拍号。以后加入预告拍号时，它只能是派生显示，不能生成额外音乐数据。

## 验收场景

1. 空白四小节从 `4/4` 改为 `3/4`，目标拍号段正确更新并可一次撤销。
2. 第三小节改为 `6/8`，第一、二小节不变，第三小节及连续原拍号段更新。
3. 已有后续拍号变化时，`meter-run` 在该变化前停止。
4. “仅当前小节”只修改一个小节，下一小节显示恢复原拍号。
5. 内容超拍仍保留、可保存并显示轻量规则警告。
6. 输入非法分子、非法分母或过期小节 ID 时不修改文档。
7. 提交期间不能重复执行；失败后编辑器保留用户填写的值和目标小节。
8. 菜单、乐谱属性和未来直接拍号入口调用同一应用命令。
