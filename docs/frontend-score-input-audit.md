# 五线谱输入闭环审计

## 目标

输入系统只负责把用户意图转换成统一的谱面编辑意图；具体的拍号、时值、事件顺序和文档版本仍由内核校验和提交。工作台不直接修改谱面数据。

## 竖向输入流程

```text
谱面获得焦点
    │
    ├─ 小节空白位置 ───────────────┐
    │                              │
    ├─ 已有音符被选中 ─────────────┤
    │                              │
    └─ 选区被激活 ────────────────┘
                   │
                   ▼
              确定编辑目标
          （输入点 / 音符 / 选区）
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
      插入        修改        删除
        │          │          │
        └──────────┼──────────┘
                   ▼
             生成编辑意图
                   │
                   ▼
             工作台命令队列
                   │
                   ▼
              内核原子操作
                   │
          ┌────────┴────────┐
          ▼                 ▼
        提交成功           提交失败
          │                 │
          ▼                 ▼
    更新谱面投影       可重试 / 明确拒绝
    更新输入位置       显示局部反馈
    恢复可继续输入     保留当前目标
```

## 插入音符的形式

### 1. 连续键盘输入

```text
输入点 → 音名 A–G → 组号 2–6 → 形成绝对音高 → 插入
```

这是主输入路径。单独输入音名只产生草稿，不进入内核历史；组号完成后才生成一次 `append` 操作。

### 2. 休止符输入

```text
输入点 → R → 形成休止符事件 → 插入
```

休止符和音符共享同一个插入协议，区别只在 `content`。

### 3. 鼠标双击空白位置

```text
小节空白 → 解析为输入点和谱表音高 → 使用当前时值与变音设置 → 插入
```

鼠标只负责确定位置和音高，不能绕过统一的输入状态和内核校验。

### 4. 剪贴板粘贴

```text
输入点 / 选中位置 → 校验谱面片段 → 以一个原子操作插入多个事件
```

粘贴属于批量插入，不应拆成多个独立历史步骤。

### 5. 未来的其他输入源

数字简谱、六线谱、MIDI 或外部导入，都只需要输出统一的：

```text
绝对音高 + 时值 + 内容类型 + 输入位置
```

它们不应直接操作 React 状态或绕过工作台命令队列。

## 修改音符的形式

已有音符被选中后，输入组件进入“修改当前事件”模式：

- 音高：音名字段、键盘音名加组号、滚轮和方向键。
- 时值：加号、减号、附点按钮和键盘快捷键。
- 变音：无、升、降、还原四种状态。
- 内容：音符与等时值休止符之间转换。

所有修改最终统一为 `set-event-properties`，保持事件 ID 不变，由内核决定时值变化后是否需要移动后续事件、生成休止符或产生轻微规则警告。

## 删除音符的形式

- 选中单个音符后按 `Backspace` 或 `Delete`。
- 输入点位于事件之后时按 `Backspace`，删除前一个事件。
- 通过连续选区执行范围删除。
- 剪切操作先复制片段，再以一个范围删除提交。

删除必须明确使用 `preserve` 或 `collapse` 时间策略，不能由组件隐式决定。

## 当前实现审计

已经具备：

- 输入点、选中事件、输入草稿、提交中、失败和重试状态。
- 键盘音名输入、组号完成、休止符输入。
- 鼠标单击定位、双击插入。
- 选中后的音高、时值、附点、变音和休止修改。
- 单项删除、输入点退格删除、范围删除、粘贴和撤销重做。
- 成功后更新投影并恢复输入位置；失败后保留目标并区分可重试失败和明确拒绝。

需要继续打磨：

1. **输入目标切换要显式化**：输入点、单事件、范围选区三种目标必须始终只有一种生效，不能让组件同时显示“接下来输入”和“正在修改”。
2. **插入前后位置要有稳定入口**：选中音符后需要能明确进入“音符之前”或“音符之后”的输入点，而不是依赖多次方向键或猜测 `Escape` 的含义。
3. **删除入口要对称**：选中状态支持 `Backspace` 和 `Delete`；输入点状态明确规定 `Backspace` 删除前一个事件，`Delete` 删除后一个事件或给出不可用反馈。
4. **提交队列要保持闭环**：队列运行时禁止改变正在提交的目标；提交成功后再依据内核返回的事件 ID 和位置更新状态。
5. **规则警告不能改变编辑目标**：超拍、时值调整和自动移动后续事件属于内核结果，界面只显示反馈，不自行重算谱面。
6. **竖向输入面板只负责展示分组**：高频输入控制、当前对象属性和位置状态应分成上下三个区域，不能把它们混成一个无层次的横向工具条。

## 下一步实现顺序

1. 先补齐编辑目标模型：输入点、单事件、范围选区的切换和退出规则。
2. 增加“插入前 / 插入后”的明确导航命令。
3. 补齐 `Delete` 与 `Backspace` 的对称行为和测试。
4. 把竖向输入面板按“目标 → 音高 → 时值 → 变音/休止 → 位置”分组展示。
5. 用鼠标、键盘、面板、粘贴四类输入各跑一遍完整闭环测试。
