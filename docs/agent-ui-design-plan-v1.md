## 2. 用户与设计方向

目标用户：在独立Agent里持续交谈、交付资料并观察任务结果；以后可嵌入软件。用户要能迅速回答“它正在做什么、读了什么、完成了吗、出错后怎么办”。

- **领域**：委托、对话、资料来源、执行证据、交接、修订。通用Agent不把乐谱术语放进固定导航；软件宿主可提供自己的资料视图。
- **色彩来源**：直接沿用`design/frame-visual/styles/tokens.css`：canvas #1C1D20、command #242529、bar #202125、surface #2D2F35、ink #F2F0EB、muted #AFB1B8、selected #2C67C5、focus #8FB7FF、danger #D98383。不另造暖白/纸灰主题；独立UI可使用同一视觉映射而无需启动软件。
- **特征**：每次回答关联“依据与本次执行”的可展开条；资料来源、真实invocation、估算预算和最终完成状态分层展示。该条是设计目标，当前只具备其中部分数据。
- **避免的默认选择**：把每段消息都装进高对比卡片；默认常开三栏挤压正文；为了显得强大提前展示未实现的功能入口。采用开放正文、按需检查区和真实能力入口。
- **修订方向**：“对话工作区”默认会话展开、资料收起；“资料工作区”默认会话收成轨道，右侧显示已授权资料目录或本次活动；资料全文预览留给后续合同。展开资料时给正文让位，避免双侧栏同时挤压。两者共享布局与状态合同，不维护两套产品；用户继续后已按此方向实施U1，实际结果仍待视觉签收。

视觉依据已核对当前frame-visual源码并查看保存的`evidence/default-1280.png`。`design/frame/styles/tokens.css`为早期线框，`docs/ui-visual-design-system-v0.1.md`为较早建议，不能覆盖当前实际色值。保存画面属于历史证据，最新整体框架仍未签收，不把它说成已批准的现行产品截图。

## 3. 信息架构

| 区域 | 内容与操作 | 首批数据依据 |
| --- | --- | --- |
| 左侧会话 | 新会话、名称搜索、列表、命名、归档/恢复；全局设置入口 | conversations/Session现有接口 |
| 顶部当前会话 | 标题、连接/模型摘要、资料/活动检查区开关 | 当前快照；运行中禁止不支持的目标变更 |
| 中间对话 | 原始问题、Markdown回复、流式状态、未完成原因、展开工具摘要、复制 | ChatMessage/权威Session/activities |
| 底部输入 | 草稿、附件入口、明确启用/停止/发送、连接与保存问题 | 现有action、ResourcePanel和存储notice |
| 右侧检查区 | 已授权资料目录、本次活动；后续输入估算和来源说明 | resources/activities；诊断需要独立生命周期处理 |
| 设置 | 连接/模型/密钥；高级输入预算、声明容量 | 现有设置；预算项依赖M3.2c1 |

资料“已添加”只表示可供读取，不表示已发给模型；“工具已完成”不表示“回答已完成”。执行卡不混入Markdown正文，复制保持原文。完整对话、上下文选择、运行活动、成果预览是不同数据，不按视觉位置互相推断。

## 4. 分批落地

### U1 核心对话布局（先做，复用现有能力）

- 重排会话/标题/输入/资料入口、优化正文密度与间距、工具摘要折叠、保留M3.3a失败语义。
- 复用useAgent、现有权威decoder、ChatMessage、SettingsDialog、ConversationSidebar、ResourcePanel、ToolActivities，不新造运行状态机。
- 先只显示当前Run已有资料/活动。历史没有保存的原因、活动、估算明确不可用，不能复制当前Run的值填充。
- 无生产端口变更、无新模型请求、无自动重试，不新增写工具/审批/队列/记忆开关。

### U2 上下文与用量可解释（依赖相应合同）

- 只读model-input/context-selection按会话/Run/连接代次绑定，旧异步结果丢弃，刷新零生成。
- 显示“输入估算/设置预算/省略旧轮数”，与供应商实际usage分别标注；没有usage/价格时显示未知。
- 预算中断提供明确下一步入口，编辑后由用户重新发送；不擅自恢复旧Run。

### U3 执行控制与成果（依赖M4/M5）

- 写入审批、变更预览、排队/追加指令、成果版本、项目/AGENTS.md、记忆、Skills/MCP与Agent选择按真实能力逐项接入。
- 独立UI与软件嵌入共享状态投影/呈现组件，业务视图从宿主能力提供，不让通用聊天组件导入乐谱实现。

## 5. 视觉基线与状态合同

Intention：长时间阅读与任务协作，贴合项目深色工作台。Hierarchy：当前问题和结果为主，过程与设置降一级。Depth：平面区域、弱分隔、3px控件/6px输入圆角，无外壳大卡片或装饰阴影。Typography：项目Segoe UI Variable Text/Segoe UI/Microsoft YaHei UI，正文15px、元信息11–13px、回复标题20px，行高1.7–1.8。Spacing：4px基准，控件/正文按8/12/16/24/32组织。

修订草图尺寸：顶部44px、会话204px/轨道44px、正文最大680px、资料300px。打开资料自动收会话；关闭后恢复原展开偏好。700px以下改为顺序布局与显式会话开关，生产实现可复用现有原生dialog；草图的浏览器滚动不作为生产容器滚动合同。目标触控区域44px，键盘focus与返回焦点保留；不新增动效。

必须设计并验证：空会话、未配置/未启用、连接中/断线、读取中、流式、正在停止、完成、失败有/无正文、取消、宿主退出中断、历史原因缺失、存储失败与预算超限。颜色同时配文字，错误旁给具体可执行操作。

## 6. 验收与边界

- [x] U1-A1：现有能力不回退，真实HTTP fixture完成/失败/停止/资料流程与权威状态一致；不把界面草图当接入完成。
- [ ] U1-A2：1280×900、1024×768、390×844及320px，正文/输入无横向溢出，折叠区可访问，键盘/中文IME/焦点/滚动跟随正确。
- [x] U1-A3：会话切换/重连/新Run不串资料、活动、错误或草稿，未保存/禁用/不可用入口真实；浏览器无异常及直接模型请求。
- [ ] U2-A1：估算与实际usage准确区分，无凭据/正文诊断泄漏，历史缺失不虚构，旧诊断HTTP回包不得覆盖新会话。
