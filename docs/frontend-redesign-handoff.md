# 前端重新设计交接：仅保留需求与原则

日期：2026-09-13。

## 本次交接的唯一用途

从用户需求重新设计 Brilliant Guitar 前端。此前展示的界面和候选方案均未获得用户认可，不是可继续迭代的设计基线。新会话应以本文为需求起点，不主动读取旧设计、旧预览或从旧界面提取样式。

本文不指定界面布局、组件清单、视觉主题、尺寸、颜色数值、字体方案、快捷键映射或具体交互实现。文中“待梳理”不代表已经批准的功能合同。

## 产品目标与近期范围

- 产品面向乐谱创作、编辑与播放，应同时关注美观、操作效率和长期扩展性。
- 用户说明内核基础工作已基本完成，当前重心转向前端。进入实现时应核实公开接口能力，不把这段背景当作所有能力均已通过验证。
- 近期产品目标是先完成最小可用的基础 UI，并通过公开接口接入内核，完整运行一次真实的创建或打开、输入与修改、保存及重新打开流程。设计效果图本身不能代替这个目标。
- 第一版以基础五线谱和基础编辑能力为范围；吉他领域插件完成后，再适配吉他专属谱面与操作。
- 最终需要整体、详细的前端方案：不仅包括外观，还要覆盖核心用户流程、功能组织、组件职责、状态与反馈、配置需求、扩展边界及验证标准。

## 设计方法与审美要求

- 先理解核心用户流程和整体需求，再建立整体框架；框架未成形前，不逐个微小交互反复推演。
- 视觉探索可以按单个组件逐步进行，当前重新开始的设计对象是导航栏；这不意味着将整套产品需求缩减为导航栏。
- 使用 Interface Design 做界面设计规划；Product Design 可用于产品流程与设计探索。技能中的默认风格不能覆盖用户要求。
- 期望现代、美观、有清晰层次。既不要臃肿，也不要缺乏组织、显得光秃。
- 第一版首先解决布局逻辑、几何关系、比例、对齐和信息层次。配色保持常规，不靠复杂动画、特殊字体或装饰掩盖结构问题。
- 产品 Logo 暂不设计。
- 可以研究成熟软件和界面灵感站点，学习其组织与操作思路；不要照抄厂商外观。参考对象与新方案均需重新选择，不继承上一轮结论。

## 操作体验需求

- 常用功能必须容易找到。功能组织应符合任务关系和使用频率，相关全局管理操作应保持一致、易理解的归属，不随意散布。
- 输入要快速、直接、连续，不要求每输入一个音符再单独点击或按键确认。
- 键盘应能承担连续输入与编辑。鼠标定位可以存在，但不能把核心编辑做成只能逐项点击的流程。
- 时值应可选择和修改，不能将第一版永久限制为固定时值的演示。
- 技巧操作需要支持快速、按需调用与连续使用；用户希望常驻显示与便捷调用能适应不同使用偏好。具体入口、按键和控件形态重新设计。
- 用户关心选定内容后的便捷循环试听。具体触发方式、与普通播放和编辑选区的关系需要重新梳理，不把旧讨论中的某个手势或切换规则当成已冻结合同。
- 用户提出播放期间是否允许修改以及相关行为可配置的需求方向；应在整体流程中说明用途和状态边界，具体配置项与默认行为待梳理。
- 配置应回应真实使用差异，避免把每一个尚未决定的问题都变成设置项。

## 模块化与扩展原则

- 前端以可组合、职责明确的组件和模块构建，便于管理、复用、扩展和他人审查。
- 工作台负责装配；部分组件固定，部分组件可调整。具体固定对象、活动范围和默认位置在新方案中重新确定。
- 模块分层必须体现在依赖和接口上，不能只靠视觉分块或拆文件命名来宣称模块化。
- 最重要的边界：UI 插件及其他插件只能调用内核公开接口，不导入内核私有实现、不依赖其内部结构，不绕过接口修改音乐数据。
- 音乐文档及历史应有统一权威来源。前端显示、编辑临时状态和个人界面配置需职责清楚，不能因更换界面或谱面而产生互相冲突的数据副本。
- UI 容器与具体谱面渲染解耦。应允许通过明确的注册与适配接口接入新的谱面类型，不将某一种乐器的专属谱面写死在通用 UI 中。
- 没有乐器扩展时，基础产品仍可使用五线谱；乐器插件提供适用的专属能力，例如吉他相关记谱。不能要求基础 UI 依赖尚未完成的吉他插件。
- 绘谱实现可评估成熟开源项目，但库的选择、对象和内部实现不应成为内核与通用 UI 的隐式耦合。本文不继承旧的选型结论。
- 扩展预留应服务新增或替换真实能力，关注通用性和清楚的合同；第一版不需要提前实现所有未来功能。

## 新会话的工作方式

- 从本文的需求重新组织思考，不沿用被否决的视觉、布局或具体交互方案；已有代码存在不代表其界面被认可。
- 清楚区分用户明确要求、设计者建议和仍需验证的假设，不把建议写成用户已确认的决定。
- 主动给出建议与理由，保持推进速度；已明确的要求不重复请求确认。只在真实缺失的信息会改变方向时集中澄清。
- 当前交接是为重新设计做准备，不是要求立即改写应用，也不是授权提交或发布。
- 后续先交付当前组件的独立新设计供判断，再按用户反馈推进。整体前端方案与真实内核闭环仍是最终目标。
