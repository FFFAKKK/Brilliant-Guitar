# Brilliant Guitar UI 视觉设计系统与 WorkbenchFrame 皮肤方案 v0.1

日期：2026-10-01\
状态：视觉研究与设计建议，**不是已批准的业务合同，也不替代八区域结构方案**。

## 1. 目的与边界

本文只定义当前插件化 workbench 的视觉方向、层级、颜色、控件和验收方法，为未来 `WorkbenchFrame` 的八区域实现提供可落地的皮肤方案。

本文不重写插件平台，不改变布局持久化合同，不定义谱面渲染规则，也不决定各业务模块的内部字段和交互。宿主继续负责区域、槽位、浮层、焦点、持久化和权限；插件继续负责自己的内容与业务状态。

## 2. 研究证据：当前界面实际是什么

本次审查以当前源码、保存的 workbench 预览图和测试为准。`apps/workbench` 的 Vite 开发服务器在本机尝试启动时因 `spawn EPERM` 无法加载配置，因此本文没有把一次新的浏览器运行误报为成功；现有预览图仍能反映已提交的真实组件组合和 CSS 结果。

### 2.1 当前结构

- `WorkbenchShell` 组合 `NavigationBar` 和 `DockLayout`；`DockLayout` 当前提供 `top/right/bottom/left` 四个停靠区和中央 workspace。
- `DockRegion` 在每个停靠区内渲染内容、占位文本和收起按钮；收起后仍保留 `COLLAPSED_DOCK_SIZE = 32px` 的轨道。
- `SharedDock` 根据空间在内嵌内容、图标轨道、页签和浮出面板之间切换，已经具备“窄空间压缩”的视觉行为，但它不是目标方案中固定的图标栏或页签条。
- 当前没有独立的 44px 图标栏、40px 页签条、标题栏 34px 的八区域外壳；这些需要在未来 `WorkbenchFrame` 中承接，不能通过继续堆叠当前四 dock 来模拟。

### 2.2 当前 CSS 的视觉事实

当前主题是深色，但使用了明显的卡片化表达：

- `--color-background: #181818`、`--color-navigation: #1e2024`、`--color-surface: #2a2a2a`。
- `--color-score-paper: #f4f4f2`，与结构方案要求的谱页固定 `#FFFFFF` 不一致。
- 控件圆角约 8px，菜单 12px，表面 16px；`.workbench-body` 使用 10px 外边距和 12px 间隔；`.workbench-panel` 有圆角、边框和阴影。
- 菜单、对话框和通知已有统一的浮层阴影及语义颜色；焦点环已有宿主级实现。
- 多个业务模块自行声明颜色、圆角和动画；这适合业务模块局部表达，但需要通过宿主 token 限制它们不要破坏纸页、槽位和状态层级。

保存的 `apps/workbench/workbench-preview.png`、`shared-dock-medium.png` 和 `compat-900-preview.png` 显示：中央纸张已经被单独放在深色舞台上，左、右、上下区域可见，但空白区域被大块圆角容器包围；当前原型更接近“带卡片的 IDE 停靠布局”，还不是“紧密分隔的排版工作台”。

### 2.3 当前布局持久化与恢复

当前 `WorkspaceConfigurationV1` 保存：

- 四个 dock 的宽高、可见性和当前选择项；
- `uiLayout` 中组件的 `slot`、`presentation`、顺序和可见性；
- 右侧检查器宽度。

`restoreUiLayout` / `reconcileUiLayout` 会校验版本、过滤未知组件、迁移旧版本并在无效数据时恢复兼容布局；`useWorkspaceConfiguration` 在启动时读取、归一化并写回。该行为说明视觉层必须支持“恢复原宽度、原页签、原模块组合”，不能通过挂载/卸载动画或默认重排改变用户看到的状态。

### 2.4 当前 UI 插件宿主边界

`UiComponentDefinition` 已明确组件的 `slots`、允许的 `presentation`、可移动/可调整/可停靠能力、投影权限和扩展点。插件视图通过 `UiPluginHost` 解析，投影读取器按插件声明隔离；插件会话在启动时冻结，运行中不做热卸载。

因此视觉皮肤的安全边界应是：

1. `WorkbenchFrame` 拥有区域背景、分隔线、标题行、拖拽边界、浮层层级和全局 token。
2. 插件拥有模块内部内容、业务状态和声明式扩展点内容。
3. 插件不能改谱页底色、区域尺寸合同、浮层定位、焦点关闭规则、全局 z-index 或其他插件的表面。

## 3. 已确定约束、设计建议与待评审项

### 3.1 已确定约束

以下来自 `E:\desktop\吉他打谱软件 · 界面框架方案（结构与布局）.md`，实现和视觉细节都必须服从它：

- 八区域结构：标题栏、上侧栏、图标栏、左侧栏、谱面舞台、右侧栏、页签条、底部（声部面板与合并栏）。
- 谱页底色永久为 `#FFFFFF`；选区、播放头和批注只能在独立透明层绘制。
- 关键入口默认可见；区域开关、模块入口、翻页、编辑布局不能只靠悬停或快捷键发现。
- 同一区域的分区和模块紧密排列，用 1px 分隔线表达边界；框架阶段不做动画。
- 目标尺寸：标题栏 34px、上侧栏 36px、图标栏 44px、左侧栏 240px（200–360）、右侧栏 300px（260–420）、页签条 40px、合并栏 32px；谱面舞台最小 480×300。
- 收起状态记住用户上次宽高、页、模块组合；窗口缩放由舞台吸收变化。
- 新模块、页面和槽位内容通过注册接入，不要求修改外壳代码。

### 3.2 设计建议

- 深色工作区使用低对比度石墨色，纸页使用真正的白色，以形成“工作台 / 打印介质”的稳定关系。
- 外壳采用平面分区和 1px hairline；只给纸页和真正的浮层使用阴影，减少卡片堆叠。
- 模块、页签、合并栏和状态反馈使用同一套 token；模块内部可以有小型分组，但不再重复整块圆角卡片。
- 保留现有焦点环、键盘调尺寸、Esc 关闭和 aria 语义，并把视觉状态补齐为默认、悬停、按下、选中、禁用、错误、等待。
- 视觉变更先作用于宿主皮肤层，优先复用现有 DOM 与 `UiComponentHost`，不把建议反向写成新的插件业务合同。

### 3.3 需要评审的项

- macOS 标题栏是否完全交给系统按钮，还是在标题栏内预留同一套 34px 空间。
- 图标栏的模块顺序和模块库是否属于本期八区域实现，还是先保留现有 `SharedDock` 作为迁移适配器。
- 右侧页签条的图标集合、页面是否允许隐藏和排序。
- 左侧栏半行模块的空位是否保持显式空槽，以及空槽的最小可见高度。
- 当前预览图中“纸页周围 20px 留白”是否接受为舞台内边距，还是需加入缩放下限和滚动条视觉样式的独立规格。

## 4. 视觉设计系统

### 4.0 最高优先级原则：关键文字，其他优先图形

- 界面文字只承担关键内容：文档、谱面、状态、错误原因、确认动作和不可推断的业务名称。
- 可由形状、图标、位置或状态表达的操作，不在常态界面重复写成长句；优先使用清晰图形和可访问名称。
- 说明性文字只在用户主动请求时通过 tooltip、帮助浮层或辅助技术提供，不占用常态布局空间。
- 图形入口必须同时具备可访问名称和 tooltip，不能以删除文字为理由牺牲可发现性或键盘可达性。
- 任何新增文字都要先回答：它是否是关键内容？若不是，改为图形入口或用户主动展开的说明。

### 4.1 颜色角色

颜色先定义为角色，具体代码 token 可以继续保留兼容别名。建议初版如下：

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| `--frame-canvas` | `#141619` | 整体工作区背景、舞台外侧 |
| `--frame-chrome` | `#1B1E22` | 标题栏、图标栏、页签条 |
| `--frame-surface` | `#22262B` | 左右侧栏、上侧栏、声部面板、合并栏 |
| `--frame-surface-raised` | `#292E34` | 当前选中模块、浮层内层、输入组 |
| `--frame-divider` | `#363C44` | 1px 分隔线、边界线 |
| `--frame-divider-strong` | `#48515C` | 拖拽边界、模态层边界 |
| `--frame-ink` | `#F1F3F5` | 主文字和高优先级图标 |
| `--frame-muted` | `#AAB3BD` | 次要文字、说明、非当前页签 |
| `--frame-subtle` | `#77818C` | 提示、禁用前的低优先级信息 |
| `--frame-accent` | `#6EA8FF` | 当前入口、焦点、活动线、可执行主动作 |
| `--frame-accent-quiet` | `#233A5C` | 选中背景，不代替边界线 |
| `--state-success` | `#6CCB92` | 已保存、完成 |
| `--state-warning` | `#E3B35B` | 等待、注意 |
| `--state-danger` | `#FF7A83` | 错误、阻断、撤销确认 |
| `--score-paper` | `#FFFFFF` | 谱页唯一底色，禁止主题覆盖 |
| `--score-ink` | `#1C1F23` | 谱面文字和符号 |

建议保留当前 `--color-*` 别名作为迁移层，但将 `--color-score-paper` 改为 `#FFFFFF`，并在纸页宿主上设置局部 `color-scheme: light`，避免浏览器控件和系统滤镜把谱页变灰。

### 4.2 层级与表面

视觉层级按“区域 → 模块 → 控件 → 浮层”递进：

- **区域层**：平面背景和 1px 分隔线，不使用 16px 大圆角。
- **模块层**：标题行 28px，内容区直接承载模块；模块之间只用分隔线，不留 8–16px 空隙。
- **控件层**：按钮、输入框和选择器可有 4–6px 圆角；选中使用背景色 + 2px 活动线，不能只依赖颜色。
- **谱页层**：白纸可使用轻微外阴影和 2px 圆角，阴影只为纸张边界服务，不传播到舞台。
- **浮层层**：菜单、面板层、模态层使用不透明表面、强边界和统一阴影；通知层不能改变布局。

推荐圆角：框架区域 `0–2px`，控件 `6px`，菜单/面板浮层 `8px`，模态 `10px`。当前 12–16px 区域圆角只在视觉稿对比通过后逐步减少，不要求一次性改动所有业务组件。

### 4.3 密度与分隔

- 基础间距继续采用 4px 倍数，但八区域内部默认间距为 0；内容 padding 采用 8、12 或 16px，按模块密度选择。
- 统一 1px 分隔线；不要用阴影表达区域边界。
- 拖拽边缘保留至少 8px 的可操作命中区，但视觉线只显示 1px；键盘聚焦时显示 2px accent 线。
- 标题栏、上侧栏、页签条和合并栏高度固定；模块内容超出时内部滚动，不推动固定区。

### 4.4 标题栏、图标栏和页签条

- 标题栏只放菜单、文档名、状态标签、四个区域开关和窗口按钮；不新增固定顶部命令栏。
- 区域开关默认以图标 + 短文字或明确 tooltip 呈现，按下态使用 `--frame-accent-quiet` 与活动线；不可只显示一个不明箭头。
- 图标栏按钮 36×36px，图标 18–20px；激活模块显示 2px 左侧或底部 accent 线，角标使用语义色小圆点或数字。
- 页签条按钮 32×32px，条宽 40px；当前页使用连续的活动线和高对比图标。页签条始终可见，不因右栏收起而消失。
- 悬停提示只补充名称和快捷键，不承担发现入口的唯一职责。

### 4.5 左右侧栏模块与卡片

- 左侧栏标题行 32px，预设栏 32px；模块标题行 28px，模块内容直接接在标题行下方。
- 整行模块和半行模块都使用相同标题行 token；半行模块在 100px 内容宽度下只保留必要标签和图标。
- 复杂表单使用分组线、紧凑 label 和状态色；只给输入组或明确的选择集合使用小圆角背景。
- 右侧栏页面标题行固定 32px，翻页控件和页名在同一基线；底部固定区与内容区用 1px 线分隔。
- 层叠页边使用比纸页略深的白灰色或 `#E7EAEE`，只表示后续页面数量，不承载文字或点击行为。

### 4.6 谱面舞台和纯白谱页

- 舞台使用 `--frame-canvas`，谱页固定 `#FFFFFF`；谱页上方、左右至少 20px 内边距。
- 谱页只承载打印内容。选区、播放头、批注、调试框和拖拽提示全部位于独立透明 overlay，透明 overlay 不改变白纸像素。
- 舞台滚动条只在舞台内部出现；滚动条轨道、拇指和焦点态使用低对比度深色 token，不得盖住纸页内容。
- 缩放控件位于合并栏右槽位；缩放变化只改变谱页显示尺寸，不改变纸张底色或布局区域尺寸。

### 4.7 合并栏与状态反馈

- 合并栏 32px，左、中、右三槽位均用 1px 竖分隔，模块不足时进入槽位末端“更多”菜单。
- 播放状态使用 `--frame-accent` 或 `--state-success` 的小点、短线和数字，不使用大面积发光。
- 保存、等待、恢复和错误反馈优先在标题栏状态标签或通知层显示；通知层可自动消失，但错误和需要用户决策的状态必须能手动关闭或进入诊断面板。
- 操作反馈不通过自动展开侧栏或自动翻页表达；用户动作完成后只更新相关状态色、文字或通知。

### 4.8 浮层系统

沿用框架方案的五级浮层：提示、上下文、面板、模态、通知。建议视觉规则：

- 提示层：透明度高、无边框或极弱边框，不抢焦点。
- 上下文层：不透明表面、8px 圆角、1px 边界，菜单项高度至少 32px。
- 面板层：8–10px 圆角、强边界、统一阴影，宽度按内容但不遮挡窗口按钮。
- 模态层：遮罩不超过 `rgb(0 0 0 / 55%)`，标题、说明、动作区域用线分隔。
- 通知层：不抢焦点，固定在舞台或窗口边缘，不参与 dock 尺寸计算。

框架阶段不加入位移、缩放和淡入动画。未来若加入动效，只能作用于表现层，且状态先同步完成、可被 `prefers-reduced-motion` 和应用设置关闭。

## 5. 与插件 Facet 的落地关系

视觉实现应增加宿主皮肤能力，而不是扩张插件合同：

1. `WorkbenchFrame` / `UiComponentHost` 提供区域级 data attributes、CSS token 和统一 header/resize/overflow chrome。
2. `UiComponentDefinition.presentation` 继续只决定 `inline/panel/popover/dialog` 能力；不新增“插件可以控制外壳颜色”或“插件可以定位浮层”的自由度。
3. 组件内容通过宿主提供的表面上下文获得 `slot`、密度、选中态和可用宽度；插件只能消费 token，不得覆盖 `--score-paper`、z-index、浮层定位和区域尺寸变量。
4. `extensionPoints` 继续表示组件拥有的插槽；扩展内容继承宿主模块的 typography、spacing 和状态色，不创建平行的全局主题。
5. 插件固定会话与布局恢复不变：插件停用只影响下一次启动计划，当前工作台的视觉状态不因为热卸载而跳变。

建议后续为第三方插件提供一页“视觉贡献指南”，只描述可用 token、允许的局部 class 范围、最小宽度/高度和状态语义，不把它写成新的业务能力合同。

## 6. 设计验收标准

### 6.1 几何与结构

- 在 1440×900 下，标题栏 34px、图标栏 44px、页签条 40px、合并栏 32px；左栏默认 240px、右栏默认 300px，舞台仍至少 480px 宽。
- 在 1280×720 下，舞台仍至少 480×300；拖拽、收起和恢复不改变其它区域的持久化偏好。
- 左右栏收起后宽度为 0，图标栏和页签条仍可见；声部面板收起后只保留标题行与合并栏的目标总高。
- 区域内部没有无意义的卡片间隙；边界由 1px 线和固定标题行表达。

### 6.2 视觉与纸页

- 对谱页像素取样结果必须为 `#FFFFFF`；切换深色工作区、选中、播放、批注和浮层后仍成立。
- 工作区、侧栏、纸页和浮层的层级无需依赖大面积阴影即可辨认；只有纸页和浮层可以有阴影。
- 文本、图标、焦点环和语义色在暗色表面上达到产品规定的可读性目标；颜色之外必须有线、形状或文字差异。

### 6.3 交互与反馈

- 区域开关、添加模块、编辑布局、翻页和缩放入口在默认状态可见；没有只在悬停时才出现的关键把手。
- 区域切换、页签切换、模块排序和布局恢复在逻辑上同步完成；框架默认无动画。
- Esc 按层关闭，浮层不越界，模态层阻断下层操作，通知层不抢焦点。
- 键盘可以访问区域开关、尺寸调整、页签、模块编辑和所有状态反馈。

### 6.4 插件与恢复

- 一个 fixture 插件可以声明 `workspace/left/right/top/bottom` 中允许的 slot，并在不同 presentation 下呈现，但不能改宿主区域 token 或浮层管理器。
- 重新加载有效布局后，组件 slot、顺序、presentation、可见性、dock 宽高和当前页保持一致；无效布局会恢复并留下诊断，不产生视觉跳变。
- 插件诊断、恢复、审批和错误内容使用统一状态 token，并保持在可信宿主提供的浮层或模块内。

## 7. 按优先级的设计交付物

### P0：先冻结视觉规则

1. 本文的角色 token、几何 token、表面层级和验收清单。
2. 一张 1440×900 的八区域高保真静态视觉稿，明确标题栏、图标栏、页签条、纸页和合并栏。

1. 先评审本文的 P0 规则与开放项，确认八区域视觉稿。
