# M3.3a：失败回复可见性与长资料预算后续方案

日期：2026-10-08。当前批次只实现失败回复可见性；预算调整仍是后续设计。

## 1. 问题与证据

真实服务验收中，7465个Unicode字符、19089字节的中文资料两次读取均完成，但最终输入估算9896超过8192，下一次模型请求被阻止。聊天正文只留下61字符开场白。具体原因位于底部状态栏，回复旁只有泛化失败小字，容易把部分输出当作完整结果。

证据保存在当前Trellis任务的`research/real-acceptance/results.md`与`live-evidence.json`。这是一次已复现的预算失败；另4次无输出连接失败单独记录。不能由此推断长期记忆、AGENTS.md或TCP链路缺失。

## 2. 本批实现合同

- `ChatMessage({message, session, activities})`负责现有聊天条目的展示，直接消费权威快照，不引入新的运行状态机。
- assistant的`status=failed`时，在正文前显示醒目的“回复未完成”。已有正文标为“以下仅为中断前的部分回复。”；空正文显示“未收到回复正文。”，不伪造助手回复。
- 只有`session.status=failed && session.runId=message.runId`时显示当前`session.message`作为原因。它是宿主已有的用户提示，按普通文本转义，不解析Markdown/HTML，不通过匹配错误字符串猜类别。
- 历史失败、会话恢复、后续Run或停用后，若原原因不可得，明确显示“此回复的具体失败原因未保留。”。聊天文件v1没有逐消息原因，不能把当前Run的提示套到旧消息。
- 部分正文仍可复制，按钮标为“复制部分回复”，复制内容保持原文。工具卡继续按真实invocation显示完成/失败，工具完成不代表最终回答完成。
- completed/streaming/cancelled/interrupted和用户消息保持原有语义；不自动重试，不新增模型请求。

保持Host v4、External v1、聊天文件v1、Runtime、预算8192、1500输出和45000ms不变。本批不增加历史原因持久化或诊断API调用。

## 3. 本批验收

- M33A-A1：真实Host/本机HTTP模型fixture产生“开场白→两次读取完成→最终预算失败”，实际聊天组件显示部分回复和准确原因；没有第3次模型请求。
- M33A-A2：失败无正文、不同Run/恢复/停用、完成/流式/取消/中断和用户消息的展示正确。错误提示按文本转义，跨Run工具不展示，已完成工具保持完成。
- M33A-A3：应用测试、类型检查、隔离生产构建通过；桌面与窄屏验证记录实际执行方式和限制。fixture与真实供应商证据分开。

## 4. 预算为何在分页后仍会超限

当前最终估算器按消息与工具完整JSON的UTF-8字节计数：`ceil(bytes/3)+8*消息数+12*工具数+32`。它是工程估算，不是供应商真实token用量或模型上下文上限。

读取每页最多4096字符、结果JSON最多12KiB，只限制单次结果。已读页的调用与反馈全部作为本Run必要证据保留；第二页加入后，总输入仍会增加。把页切小只会减小单次结果，不能保证累计资料可容纳。中文与ASCII字符长度相同，UTF-8字节和最终估算可以不同。

必须把以下三层分开：供应商模型的实际上下文容量、产品允许的输入成本预算、单次工具结果大小。当前自定义模型的`contextWindow`是宿主装配值，不能仅凭模型名称/公开模型列表断言真实容量。

## 5. 后续候选方案（尚未实施）

建议先做“显式输入预算配置与反馈准入”，再决定是否需要摘要：

1. 给连接提供明确的输入估算预算，保留安全默认值和最终阻断；配置合同显式版本化，不从未知模型名称猜容量。输出预留与已知模型容量要校验，未确认容量时说明属于用户设置。
2. 用已有最终投影计算固定指令、当前要求、近轮保护、工具定义与累计反馈的开销。工具执行前预估新增结果；预算不足时返回明确、有来源的资源限制反馈，不能显示“完整读取完成”后静默丢页。准入是提前解释限制，本身不能让任意长资料都可回答。
3. 页结果允许在合同内按可用预算缩小，保留真实start/nextStart/eof；不改已执行结果、不破坏调用/反馈配对。预留应答空间仍需供应商容量信息，不能与输入估算混为一谈。
4. 之后再设计显式的工作摘要/按需检索：保留原始证据及来源，可重新读取，记录压缩边界，并评估约束丢失风险。M3.2a要求所有已执行结果受保护，采用摘要需要另行修改公共选择合同，Pi与外部Agent走同一路径。

不推荐直接把8192改成一个很大的常数，也不删除较早工具结果来刷过验收。下一批验收至少包括原中文/同长度ASCII对照、超过配置预算、未知模型容量、配置持久化兼容、取消/会话隔离，以及零多余请求。M32-A8中文长资料完整回答仍未通过；本批清楚显示失败不能替代该验收。
