# 插件编辑的局部变化比较

2026-09-13，生产基线 `a72805f`。本轮去掉单条插件命令开始前的一次完整
Store 文档导出。它原本仅用于与最终文档比较，判定提交还是 no-op。

## 行为与工作量

当前单条插件命令只允许写音高与扩展块。现在比较实际触及的音高、扩展块
最终值与原值；扩展块发生增删时，还比较扩展头的最终顺序。没有变化时，
继续丢弃临时操作，不产生新历史或事件。内容相同但扩展顺序改变仍是有效修改。

比较过程不读取无关 Core 实体、Core 顺序或无关扩展 payload。增删扩展且
最终值相同时，仍需遍历扩展头及其顺序；这不是常数时间，也不能被描述为
整个编辑流程已经增量化。触及的 payload 比较仍与其大小有关。
未支持的结构修改或已中止的 overlay 会拒绝此比较，不默默漏判。

此优化仅用于单条插件命令。Core Batch 的操作事实与历史语义不变。
最终文档投影、Core/插件校验、报告大小检查、原子提交和资源上限仍然执行。
默认引擎与协议未切换。

## 验证

- 新 Rust 测试逐步比较局部判定与完整文档判定：音高改回原值、扩展版本改回
  原值、删除再插入导致顺序变化、恢复原顺序，以及临时插入后删除。
- 另一个测试仅提供被修改的音高，完全不提供 Core 实体、顺序或扩展头，
  局部变化/恢复判定仍成功；已中止的 overlay 会拒绝。
- 真实 CVN-7 Wasm 与 SDK 差分增加相同命令重复提交，验证 no-op、历史、
  事件与后续撤销/重做结果一致。
- 全量 Rust **582 通过、1 忽略**；Node/Native **890 通过、2 跳过**；
  无失败。TS 构建/严格类型检查、Rust fmt、严格 Clippy、Rust 1.88
  全目标全功能检查通过。

只有 Wasm addon 被重建；其他 Integrated/Core addon 沿用原产物。
本轮生产变更的 Native 执行证据来自重建后的 Wasm addon。

## 参考性能

同机 Windows x64 / Node 24.15.0，冻结代表性文档 25,600 个事件。
每轮新进程、一个会话，先做一次不计时编辑，然后测六次公开接口的插件编辑。
新旧顺序交替，测试/构建结束后运行；不使用正式资格测试的采样方法。

| 轮次 | 旧产物中位数 | 新产物中位数 |
| --- | ---: | ---: |
| 1 | 542.84 ms | 509.04 ms |
| 2 | 498.95 ms | 499.66 ms |
| 3 | 505.06 ms | 490.36 ms |

两轮降低，一轮近乎持平，**未证明稳定提速或峰值内存下降**。新产物单轮
进程峰值最高 555,020,288 字节，旧产物最高 488,112,128 字节；其他轮次
约 483 MB。峰值包含构建夹具、初始化、保留历史等，不能单凭此数判断泄漏。

源码已经减少一次完整初始文档复制，但性能主因仍需从最终投影与全量评估中
解决。不能把本轮结果当成 p95/p99，也不能提高商业完成度估计。
原始六轮记录：`docs/evidence/module-net-comparison-2026-09-13.json`。
