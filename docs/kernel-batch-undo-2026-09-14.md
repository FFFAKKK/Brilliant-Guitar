# 无前置修改的组合历史撤销优化

2026-09-14，改动前基线 `dafd8c8`。

## 问题与改动

组合历史包含 typed prefix 和 occurrence suffix。旧的非空 suffix 撤销
在恢复 suffix 起始身份后，无条件封存结构边界，再用该只读视图建立
新的候选来重放 prefix.inverse。即使 prefix 完全为空，仍走这条路径。

封存视图没有建立第二份物理文档，但产生了额外的完整结构扫描和候选
读取层。后续完整校验与读取经由这个中间层访问原候选，
因此“fullDocumentClones 为 0”不能证明该路径便宜。

现在仅在 `prefix.forward` 和 `prefix.inverse` **同时为空**时：

- `project_replay` 直接投影并校验已经逆向重放的 suffix 候选；
- `prepare_replay` 直接执行其最终语义校验和提交准备；
- 仍先执行 `ReplayBindings::at(..., SuffixStart, ...)`，检查保留的身份定位；
- 不改变含有真实 prefix 的两阶段重放，它仍可经过语义暂时非法、
  但结构可读取的中间状态，再由 prefix.inverse 修复最终文档。

没有删除最终语义校验、提交容量预留、索引准备或唯一 Store adoption。
该优化同时适用于存储历史预览和真正的撤销提交。

## 回归范围

新增专项验证纯 suffix 历史的预览、撤销、重做、版本和重建索引一致性，
明确断言最终语义校验仍为 1 次、完整扫描为 1 次。
篡改逆向记录使其恢复非法 tempo 时，预览和提交准备均拒绝，
Store、版本、指标保持不变。

组合历史的 13 项专项回归涵盖全部 11 种 typed prefix 操作、无变化、
前置元数据/引用暂时非法、Part 死亡与重生、扩展归属恢复以及晚期
前置条件失败。全量 Rust 回归覆盖其他结构操作和历史路径。

最终 Rust 全量 602 通过、1 忽略；Node 全量 894 通过、2 跳过、
0 失败。严格 Clippy、Rust 1.88 全目标/全功能检查和 fmt 通过。
Core、Integrated、Wasm 三种 Native addon 均已重建，
完整 Node 回归在全部重建完成后执行。

## 独立诊断方法

`scripts/profile-native-paged-batch.mjs` 在单独进程中运行未经修改的
代表或压力文档，通过实际 V4 Wasm 插件和分页报告模式执行：

1. 创建会话；
2. 提交包含两个插件命令及一个 Core 元数据命令的 Batch；
3. 撤销；
4. 重做。

每步检查版本与提交状态；撤销后编码哈希必须等于原始输入，
重做后必须等于提交后的哈希；JS 插件回调为 0。
记录操作时间、Runtime 工作指标、RSS 和产物哈希。
父进程保留 60 秒诊断期限，超时是失败，不会当作通过；
逐阶段记录保留超时前最后进入的操作。

这不是正式资格采样，不提供 p95/p99。
首次旧压力探针超时且尚无阶段记录，该原始失败结果也予以保留；
后续带阶段记录的运行用于缩小耗时范围，不能替代或隐藏前次失败。

## 诊断结果

最终对照在完整回归结束后依次运行，各自使用新的进程和同一版探针，
期间没有并行构建或测试：

| 文档规模 | 旧产物撤销 | 新产物撤销 | 整个探针 |
| --- | ---: | ---: | --- |
| 25,600 事件 | 3,656.53 ms | 1,015.48 ms | 两者完成 |
| 102,400 事件 | 35,617.82 ms | 14,227.89 ms | 旧版重做期间超时，新版完成 |

旧压力耗时从已经完成的 undo 阶段起止标记计算；
随后进入 redo，说明撤销版本和原始编码哈希断言已经通过。
旧进程最终仍是超时失败，不是完整通过，不能给它补造重做结果。
新版两种规模均验证了提交/撤销/重做状态、版本、完整编码哈希及
零 JS 插件回调；撤销工作指标均为 1 次完整扫描、1 次最终语义校验。
新版峰值 RSS 分别为 438,562,816 和 1,061,838,848 字节，
包括语料生成与非计时正确性检查。

更早一次旧代表样本的撤销为 11,793.97 ms，早期旧压力样本直接超时。
这些结果全部保留，反映运行波动，不能只挑最慢旧值来报告提升比例。
本轮不发布通用百分比、p95/p99 或正式资格结论。

`docs/evidence/batch-undo-manifest-2026-09-14.json` 记录测试摘要、
产物/输入/脚本哈希和六份原始诊断文件，包括失败尝试。
主对照使用相同脚本哈希；早期样本对应加入或完善阶段记录之前的版本，
不参与主表的直接比较。
