用户反馈：`runtime-preview.html?rev=ux-fixes-20261007` 呈黑色且没有谱面。

## 现场观察与结论边界

- 当前 HTTP 返回 200，确实提供仓库中的原运行页。
- 独立 Chrome 打开用户相同 URL，工作区和真实 SVG 谱面正常，无 pageerror 或请求失败；初始观察保存在 `evidence/runtime-blank-20261007/inspection.json`。

- 已复现并修复能留下整页空黑的启动盲区；用户当前窗口刷新后的恢复仍待确认。

## 已复现的问题

原运行页直接加载 ESM 入口，入口又有顶层静态 import。入口/依赖获取失败或者依赖没有所需导出时，模块主体尚未执行，主体中的 try/catch 接不到错误。此时 `#app` 为零个子元素、零个谱面 SVG，画面只有深色背景。

独立浏览器控制复现覆盖入口网络失败、深层依赖网络失败、导出不匹配。另用明确标注的合成 pagehide/pageshow 事件，验证已释放为空的同一文档重新显示也会保持空白；这不是用户 WebView 生命周期的现场证据。正常浏览器历史返回另作验证。

## 修改内容

1. 只在原 `runtime-preview.html` 添加无模块依赖的内联 loader，通过动态 import 捕获加载/链接阶段异常。原入口、统一平台及谱面提供者不变。
2. 启动期间显示简短加载状态；失败显示原因和“重新加载”，错误使用 textContent。加载提示成功后移除，正常 UI 无新增常驻文字或控件。
3. 完整页面重载用于重试，不在同一文档中重复装配插件。BFCache 保留实例不重启；已经成功启动但释放为空的文档重新显示时重载。
4. 检查发现正式平台桥接生成文件已落后于工程源码。经原 `build-desktop.mjs` 链重新生成插件/桌面服务桥接、经典启动脚本和桌面资产，未手改 vendor 或工程源码。
5. 增加可重跑的浏览器回归工具，并记录启动边界合同。未新增 HTML，未修改废案产品 UI，也未引入静态谱图回退。
