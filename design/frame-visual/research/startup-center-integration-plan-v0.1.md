# 启动中心真实接入计划 v0.1

日期：2026-10-08。本文件将用户确认的三页启动中心接入原应用链。它不是第二插件平台、第二命令总线或新文档权威。

## 一个应用所有者

宿主bootstrap先提供配置、文档与最近元数据服务。欢迎视图只消费目录/投影/动作；原应用组合根拥有启动协调、一个文档会话和一个runtime。平台激活、UI router与核心谱面挂载仍由原组合链负责。

欢迎页准备文档使用createDesktopReadonlyScoreSession({ initialization: "read-existing" })。原client.read复用原workspaceId及宿主read_or_recover：可能接受已有/恢复作品，也可能返回null或报告恢复错误；不能把错误变成“没有文档”。此时不挂编辑工作区，也不先建空谱。

恢复作品未保存时，新建/打开仍由原保护拒绝；提供继续恢复作品的入口，不提供假保存或默认丢弃。已有正常接受文档可在失败后保留，不能由欢迎组件另存一份音乐正文。

## 首次进入与返回状态

| 阶段 | 允许动作 | 核心约束 |
| --- | --- | --- |
| 读取计划/恢复状态 | 切换三页、查看；等待或重试 | 不能开始文档替换或激活插件 |
| 欢迎就绪 | 保存计划、选择作品、新建、打开或继续恢复 | 参数/依赖非法或计划草稿未保存时先处理配置 |
| 文档选择进行中 | 保持页面可见、显示局部忙碌；允许系统文件框取消 | 同时只接受一个进入意图，双击/重复点击不产生第二次操作 |
| 工作区启动中 | 等待或展示失败 | 校验已保存计划，接受真实目标文档后才启动唯一平台；可见且正确尺寸时挂载 |
| 工作区运行 | 原编辑器和返回欢迎页 | 当前插件集合/参数固定；欢迎页保存的修改仅供下次进程 |
| 返回欢迎 | 查看最近/插件/设置，继续当前工作区；文档动作仍走同一会话 | 返回编辑器复用原实例，不销毁重建以应用新计划 |
| 应用结束 | 清理订阅/视图/平台/文档会话 | 迟到结果不能再挂载/通知，尚未发出的请求必须停止 |

计划校验与读取在文档替换前完成，并捕获本次选择使用的计划。首次完整启动成功后运行集合固定。若启动失败，释放该失败尝试的工作区资源并保留已接受文档；不能清空文档冒充回滚。重试不得再自动新建或重复打开同一文件。无法确认资源释放时不启动第二实例，要求重启恢复。

插件计划保存、文档接受和最近记录不是跨文件原子事务：计划保存失败阻止进入；文档接受后最近记录写失败不撤销作品；平台启动失败保留已接受文档及明确重试路径。

## 文档替换的宿主边界

旧兼容workbench_open_file_v1只有workspaceId，create也只比较预期ID。2026-10-08已增加明确guarded入口，原只读源显式新建/打开使用新路径。UI busy锁能阻止本入口重入，不能代替宿主原子比较。

受保护请求明确预期empty或documentId＋documentVersion。文件校验仍使用原read_document/codec；最终在原workspace服务锁内比较预期身份/版本并执行原import/create。对话框期间作品已变化则拒绝接受新文件，保持现作品。字段/IPC/重放与失败边界见[正式代码合同](../../../.trellis/spec/frontend/document-replacement-contract.md)。最近打开已复用该服务保护，后续欢迎页须使用同一openRecent端口，不得调用无保护import绕过；缺失新版命令不降级。

无保存入口时，不提供强制覆盖未保存内容。文件框取消、坏文件/未来格式、读取失败或预期版本不匹配均不改已接受作品、文件路径、保存检查点或最近记录。已发出的IPC不能靠前端dispose假装取消；宿主操作完成与前端接收结果分别记录。

## 最近目录的所有者与范围

最近目录由原桌面宿主持久化，UI获得记录id、名称、最近打开时间和用于展示的定位信息；执行时只传记录id，宿主解析实际文件位置。目录不是另一份谱面正文、版本权威或插件注册表。

- 第一版数量上限已固定20，成功登记优先；以宿主canonical普通文件路径去重，已有路径保持记录ID，不由UI简单转小写判断Windows路径等价。
- 成功接受真实文件后登记；取消/坏文件不增加。显式新建但尚无保存路径的作品不伪造最近文件。恢复作品用恢复状态展示，不混同于成功保存过的文件。
- 记录丢失文件时可仅移除记录；列表不扫描存在性，实际打开失败保留作品和记录。移除绝不删除作品。重新定位功能后续再做，届时也须经过同一文件校验/原子替换边界。
- recent-documents.v1.json复用原JsonDocumentStore原子写入和AppState配置租约，typed store的Mutex覆盖完整读改写，不增加第二套配置写入队列；未来/坏结构目录保留并拒绝覆盖。详见[最近目录合同](../../../.trellis/spec/frontend/recent-documents-contract.md)。
- 作品接受成功而最近记录写入失败时，返回独立warning并保留作品；recent.retryRegistration可独立重试，不重新导入。恢复清理失败同样为warning，但没有新增直接重试端口；不能把附属失败显示成“文件未打开”。

缩略图优先缓存原实际绘制结果，按文档/版本识别；缓存失败只影响预览，不影响打开。没有缓存时显示统一文件图形，不启动第二文档会话去画封面。当前视觉候选共用的SVG必须继续明确为示例。

## 窗口与验收次序

1. 原会话的read-existing准备与释放后请求保护先落地，并保留默认入口兼容。
2. 原宿主接受保护和最近目录：固定代码合同、真实磁盘往返、坏文件/版本冲突/写失败测试。
3. 应用协调接线：计划/恢复状态→显式用户意图→原文档接受→唯一平台→可见工作区；返回保留实例。
4. 三页产品入口及欢迎/编辑尺寸转换；窗口尺寸失败保留欢迎与已接受文档，不在错误几何下初始化视口。
5. 同版生成/类型/完整回归后，分别验收真实WebView、文件框取消/重试、正常进程重启、系统缩放/焦点与IME。

关键计数：选择前create=0且平台start=0；准备null后打开为read→open；显式新建为read→create一次；连续点击只有一个动作；恢复内容不被覆盖；返回/继续仍为同一平台/文档/view；全部结束后监听清理且晚到null不再发create。

2026-10-08应用协调切片已落实上述顺序的可执行核心，showView为必需注入端口，在完成后才挂载；实际原生尺寸端口尚未实现。返回继续使用固定runtime，直接忽略下次配置草稿的未保存/新版本，保留草稿供之后保存；首次启动仍必须先处理配置。具体签名、F-21通知重入修复及错误恢复见[应用协调合同](../../../.trellis/spec/frontend/startup-center-coordination-contract.md)。本批没有替换经典自动bootstrap或三页页面消费端口。

本计划与三页草案不授予独立作者、最低设备/真实绘制、当前原生候选或商业发布资格。各资格缺口继续单独跟踪。
