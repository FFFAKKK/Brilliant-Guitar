# 备份框架：整体视觉验收清单

日期：2026-10-08。范围为现有备份框架及布局插件，使用原runtime-preview.html；不新增页面，不参考废案产品UI，不执行作品保存、覆盖、导出或安装操作。

这份清单将分批修复串成实际使用流程。下表都是待现场验收，不能用自动测试通过、HTTP字节相同或旧截图代替当前画面。当前入口：[工作区预览](http://127.0.0.1:5193/runtime-preview.html)。服务会转到当前内容版本；开始、结束各记录一次版本，期间变版则重新确定受影响项。

## 开始前

记录实际窗口大小、浏览器缩放、DPR和Windows显示缩放；这四者分别记录，不能互相代替。使用当前已打开的备份预览与只读谱面；没有谱面时记录真实空状态，谱面位置项保持待验，不能拿空工作台算通过。

记下四区域开合与尺寸、当前排布、内容顺序和谱面缩放/浏览位置。结束时通过原入口恢复本次临时调整；不清空用户设置或浏览器存储。若已有未确认的内容编辑，先保留，不擅自确认、取消或重载。

## 第一轮：直接对应用户反复指出的问题

| 编号 | 操作 | 应当看到/不得发生 | 状态 |
| --- | --- | --- | --- |
| V01 | 看命令栏，再反复开合下侧栏、悬停其入口 | 顶部只有基础菜单及应用标记，没有四栏快捷开关、验证说明或Web模拟窗口按钮。下侧栏入口只有中性灰色方向图形，无常驻“下侧栏”文字或蓝底块；方向和按需动作提示同步。其他页签的合法蓝色选中态仍保留 | 待现场 |
| V02 | 分别开合四区域，逐项恢复；再组合开合 | 区域内容在自己范围进入退出，侧栏不盖谱面工作台。普通区域操作保持谱页位置和大小；不让整页缩放、晃动。上/下横带改变左右内容区高度是已认可排布，不能把这一变化误判为缺陷 | 待现场 |
| V03 | 分别调整四区域尺寸，试最小、较大、恢复；关闭后检查控件 | 图标开关、滑条和数值一行对应；关闭区域的尺寸不可操作。左右同范围/默认值，上下同范围/默认值，实际值独立。只拖右栏不改左栏；到合法上限反向立即有响应，不留死区。容量钳制不伪装为故障，也不擅自改对侧存值 | 待现场 |
| V04 | 在排布页连续切换均衡/紧凑，停在中间再反向 | 选择标记、对应字色和缩略图连续同步；设置页面外框、标题、尺寸行和谱面不因选择跳动。此处是预览，尚未应用就不能改变真实工作区 | 待现场 |
| V05 | 选不同排布，明确应用；再恢复原排布 | 应用才改变真实区域几何；重复应用同方案没有多余跳动。谱面和当前字段不重建，已输入内容、焦点和谱页位置不被重置 | 待现场 |
| V06 | 进入/退出内容编辑，快速反向；在原内容按钮中移动或启停一个可管理项 | 编辑/确认取消在固定空间切换，标题和核心设置不位移，文字不叠影。内容仅在已接受的新位置局部补位；关闭编辑时无蓝色组件边，只有编辑选中项才有蓝边。不把整张设置页作为动画对象 | 待现场 |
| V07 | 已开区域拖到最小，继续往外；四向分别检查；再靠近关闭区域的永久边缘并向内拉 | 最小值不是自动关闭点，需继续外拉24 CSS px才收起；靠近只显把手，不自动开栏，向内24 CSS px才展开。左右最小230、上下最小80 CSS px；小于阈值松手不切换。没有可靠坐标取样时只能记录手感，23/24边界资格仍待精确复验 | 待现场 |
| V08 | 关闭区域的把手短拉后松手并离开；拖动中取消、移出窗口，再重新靠近 | 捕获结束后不继续改变尺寸；非聚焦、指针已离开时把手不残留。快速返回从当前显示程度接续，不闪回；聚焦入口仍可见。触摸结束不遗留鼠标悬停态。取消不回滚已接受的普通尺寸 | 待现场 |

逐项判断不仅看终态：同时看鼠标按下、运动中、松手以及快速反向。主观判断采用用户提出的原则：变化是否有明确原因、是否只作用在相关对象、操作是否需要额外猜测；出现“为什么这里也跟着动”的情况即记录问题。

## 第二轮：连续使用与低容量

| 编号 | 操作 | 应当看到/不得发生 | 状态 |
| --- | --- | --- | --- |
| V09 | 内容编辑中调整普通尺寸并修改内容，分别走取消与确认 | 取消仅恢复内容配置，普通区域开合/尺寸保留；确认后再编辑，以新内容为基线。输入/谱面实例保持。拖动中第一次普通Escape只停止拖动，随后一次才取消内容编辑 | 待现场 |
| V10 | 点击左右轨道靠把手一侧的图标；打开长菜单；关闭顶部再靠近顶部把手 | 图标和把手各自容易命中，透明命中区不截获邻项；顶部把手使用菜单后的空余位置，不覆盖命令。只有实际点击/拖动才能证明命中，静态CSS尺寸不能替代 | 待现场 |
| V11 | 1280×720基线、1920×1080大窗口，再试1024×720和800×600低容量窗口 | 窗口变化按原合同重新居中；普通区域操作仍保持谱页。窄窗不挤出页面滚动条，不遮谱面；内容可在自己的阅读区浏览。低容量检查不把正式最低窗口要求降低为800×600 | 待现场 |
| V12 | 用Tab进入尺寸/内容控件；用原标准方向键及Home/End浏览长菜单并回到起点 | 焦点始终可见，必要时只露出本地阅读区，固定标题不盖住当前项；不连带滚动整个设置页或谱面。鼠标聚焦不额外跳滚。组件导航复用现有规则；功能快捷键继续由专门模块负责 | 待现场 |
| V13 | 检查实际存在的空、禁用、选中、处理中与失败状态 | 空状态简短且无不可达指引；禁用不表现可按/可拖，装饰不盖过禁用。处理中在原操作位置给图形反馈；重试不保留旧错误。只观察可安全复现的状态，不能制造真实业务失败；不可复现项保留待验 | 待现场 |
| V14 | 动画中快速反向、切页、切离窗口后返回；在已有合法入口切换减少/关闭动效 | 旧动画不补播、不抢状态；返回静态真实终态，新指针动作仍能播放。减少/关闭动效仍可操作。当前组合无策略入口时由工程提供同链设置后再验，不能注入另一个执行器当作正式结果 | 待现场 |

长菜单/空/失败项若当前插件集合不具备样本，记录“缺样本，待验”。已有审阅夹具可以辅助对照美术，但不能替正式运行路径通过。内容直接拖放/分组尚无正式控制器，本清单只验已有按钮操作，不假装具备拖放。

## 记录和批准

每项记录：版本/环境、初始状态、具体动作、预期和实际、截图或动态帧/命中/计时证据、结果、影响范围及负责方。失败从最早不同的一步复现；只修改一个原因后重验对应流程和必要关联项。源码发生变化时保留旧结果，不把它覆盖为新版本通过。

完成本表后由用户审阅认可的画面及手感，再封存批准快照。工程尚未提供的内容拖放、统一报告/恢复端口、原生构建与业务插件分别保持未完成；本表批准不代表这些能力已实现，也不代表外部插件自动取得美术资格。
