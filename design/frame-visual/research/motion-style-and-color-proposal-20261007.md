# 组件动效与局部色彩方案 · 2026-10-07

状态：供用户判断的设计方案；尚未实施或批准新风格。本轮读取当前备份视觉颜色、动画合同及官方工具资料，不改变原动画页面。现有连续/聚焦/静稳试点和已通过的验证保持历史状态。

## 当前优先归属：插件定义自己的动画

用户进一步确认：沿用之前的插件规划，由插件内部定义它有哪些动画、具体怎样运动和使用什么局部配色。动作样式目录是可选参考，不是宿主强制给每个组件挑选效果的中心目录。依据现有 `plugin-design-v0.1.md` §7.5：作者负责具体表现和资源释放，宿主持有目标许可、关闭/减少动效、冲突和最终取消策略。

插件作者定义局部目标、触发条件、关键帧/轨道、编排、默认曲线与时长、静态回退和配色；已声明能力须通过宿主开放接口的范围与程度检查。宿主提供共同执行规则、用户偏好及可执行预算，不统一代写插件私有曲线、图标或颜色。全局风格若保留，只在作者声明的兼容/可调整范围内作用；用户减少/关闭动效规则始终生效。

动画不是必填：基础共同身份/版本等合法时，未提供或 null 的动画贡献合法地保持静态；已提供的定义非法则明确拒绝。插件也可有功能、绘制和动画的组合，不按效果种类拆成插件类型。

当前试点已迁至 `motion-review/2`：布局自己的普通定义模块提供受限动作的曲线、时长、弹簧与变体，coordinator 校验后实际消费，不导入布局模块。原三套效果在 0/50/150ms 的改前/改后渲染一致；作者执行和生命周期已验证。仍未实现正式插件平台的完整动画贡献接口；新揭示/形变轨道和候选配色保持待实施，不能以这次归属拆分声称丰富动作已经完成。证据与当前签名见 motion-pilot-contract.md。

用户希望不同组件有不同动作与色彩，增加丰富度。沿用之前的边界：只完善备份视觉框架，不制作具体外部插件，不给插件分类，不把公共能力写成每个插件都必须产生的贡献。

## 1. 丰富度从哪里来

当前三种候选主要控制同一内容切换和排序交互的方向、时序及弹簧参数。增加第四套时长不会形成明显不同的动作。

建议把三个维度分开：

- **动作样式**：组件的对象如何发生变化，例如揭示、连接、形变、让位、重排。
- **公共动效策略**：当前完整/减少/关闭等用户偏好及执行预算；作者默认节奏和可调整范围属于插件定义，连续/聚焦/静稳只是当前试点候选。
- **局部色彩**：组件的强调色、柔和底色、图形色及真实状态色。

组件可以组合不同动作及自己的节奏，公共动效策略仍由同一个宿主执行，色彩可以单独调整。以上是设计维度，不是插件类型；同一个布局插件可以同时使用连接式选择、遮罩揭示与受约束的物理落位。

## 2. 可考虑的动作样式（中英文对照）

| 样式 | 看起来怎样 | 本框架中的具体例子 | 当前能力与下一步 |
| --- | --- | --- | --- |
| **连接过渡 / Connected Transition** | 同一个视觉对象从旧位置连续到新位置，形状或颜色随它一起变化 | 页签的选中窗口带着亮色字形移动；布局中的当前对象在重排后仍容易追踪 | 选择窗口已实现；更多跨状态对象需明确共享身份、局部目标与中断回退 |
| **遮罩揭示 / Mask Reveal** | 一块内容从所属边缘被逐渐揭开，内部文字保持稳定 | 布局设置分组展开时，内容从标题下方显露；收起回到相同边缘 | 选择窗口已有局部裁剪实例；通用内容揭示尚未进入现有受限端口，不能直接开放任意 clip-path |
| **几何形变 / Geometric Morph** | 图形内部的块、间隔或符号平滑变成下一状态 | 批准的布局缩略图里，关闭某侧时该侧灰块收回，中央浅灰工作区保持清楚 | 拟采用专门的局部图形轨道；当前端口没有 scale/路径能力，先确定许可和回退再做视觉样稿 |
| **分层编排 / Layered Choreography** | 外形、主要信息与次要操作有很短的先后顺序，形成一次完整动作 | 首次展开布局设置：先呈现缩略图，尺寸行紧接着出现；再次频繁操作不重复整段编排 | 现有引擎可作为基础；本地固定轨道需共用取消和减少策略，总耗时有上限，不能让每一行依次等待 |
| **物理让位 / Spring Reposition** | 拖动项跟手，邻项提前腾位，松手后有重量地到达槽位 | 当前布局内容排序，可继续细调邻项接续及局部层次 | 已实现核心；保留实际位置、业务释放提交和本轮修复的边界约束，不增加自由甩动 |
| **符号过渡 / Icon Transition** | 开合符号、状态标记或路径连续变成下一种形状 | 框架自有展开/收起图形转向；未来插件可为自己的私有图标制作局部动画 | 框架只设计自己的图形；路径形变不保证任意两条 SVG 都能插值，需兼容的图形结构或局部交叉显现；不能把路径绘制当作万能形变 |
| **局部染色 / Accent Transition** | 强调色从静止的普通状态自然进入当前状态，色彩与所表达的对象一起变化 | 当前布局对象的局部填色改变；选中底与字形始终沿同一个窗口变化 | 选择窗口已经同步；新色彩轨道需以角色限定属性和目标，不能恢复 aria-selected 提前变色的问题 |

这些名字描述视觉机制，不是可照搬的完整风格。一段动作的个性来自具体形状、方向、节奏和颜色的组合。优先试验能拉开区别的“遮罩揭示、几何形变、分层编排”，以现有连续选择与排序作为稳定参照。

## 3. 色彩如何丰富

当前批准框架使用石墨色表面、蓝色选择、浅灰文字与白色谱页，以 `styles/tokens.css` 为本轮基线。旧设计文档的 workbench 分析和旧推荐色不作为视觉参照。

建议保持框架底色，让组件在内部小范围拥有自己的强调色。下列是待试验的配色候选，不绑定插件功能，也没有要求未来插件采用：

| 局部气质 | 强调色候选 | 柔和底色候选 | 可用于哪里 |
| --- | --- | --- | --- |
| 冷蓝 / Cool Blue | `#8FB7FF` | `#273750` | 框架布局入口、导航与当前对象 |
| 青玉 / Jade | `#77C8C2` | `#263A3B` | 某个组件的局部图形、选中填色 |
| 鸢尾 / Iris | `#B6A6DD` | `#332F43` | 另一个组件的图形主题、轻量选中背景 |
| 暖铜 / Copper | `#D4AA8F` | `#3A302C` | 第三个组件的局部强调、图形细节 |

同一强调色可以有普通、悬停、当前等明暗层次，不用一个组件一种大面积亮底。单个操作的主动作对象拥有主要强调，其他对象用低对比表面衔接。候选颜色需要在实际图形、文字及目标窗口中验对比度，本轮不将十六进制值视为最终色板。

统一的部分仍有明确职责：

- 框架焦点环、布局编辑选中边、框架导航遵守共同语义；插件私有选中色可以有自己的特色。
- 失败、警告和完成的状态色不被组件主题重新解释；颜色同时配合图形或关键文字，不能成为唯一状态信息。
- 插件的颜色和动画限定到自身根区域，不覆盖外壳、其他插件、错误语义或谱页。谱页继续为白色。
- 一次状态变化可以有一次短颜色过渡；持续反馈由真实状态或播放进度驱动，不靠随机变色或一直循环强调。

## 4. 一个组件可以怎样组合

以已有布局组件为例：

1. 页签切换：保留蓝色连接窗口和同步亮字。
2. 设置分组展开：从分组标题下方揭示，文字无需整块跟着滑动。
3. 区域开关：对应缩略图块发生局部几何变化，以灰度和蓝色强调表达开合。
4. 内容重排：使用现有受约束的弹簧让位，局部层次随抓取状态改变。

这四种动作属于同一个插件，没有新增四种插件分类。一个未来插件也能选择其他组合与自己的强调色；本会话不会因此制作它的私有按钮或图标。

## 5. 工具与插件边界

当前继续使用本地固定 Motion 14.0.0 和唯一 adapter。官方当前文档列出的时间线、SVG、颜色、遮罩等能力说明引擎能覆盖更多创作方向，不证明本地固定版本、已构建 bundle 或当前端口已经开放全部能力。需要逐项核对版本和产物；不自动升级或安装新库。

未来能力设计建议：

- 插件内部定义它贡献什么局部动画、哪些局部对象可被作用、触发/轨道/编排、默认节奏与回退；基础身份与版本仍是共同必填。
- 宿主校验目标、属性、时长/重复/并发与生命周期，提供统一的减少/关闭、冲突和取消策略；作者定义通过校验后才取得局部执行许可。
- 同一意图可以有多种作者定义的获准表现；不同插件不必消费同一表现，也不持有引擎实例。通用参考模板可自愿复用，公共策略不改变组件的作者归属。
- 动画样式和主题色是两项可选能力，不要求它们互相依赖。没有贡献时保持合法静态结果；已提供但非法时拒绝，不能静默吞成 null。
- 颜色贡献不是全局任意 CSS 授权；不在本轮擅自规定新的正式 SDK 字段。
- 内容布局和业务结果先接受，动画中断、缺失、失败和卸载不影响已接受结果。

这份文档仅提供未来视觉消费需求。正式动画/主题贡献协议、提供者装配与预算仍交工程会话；当前 `motion-review/1` 只允许 x/y/opacity 等既有受限字段。

具体创作流程：先由布局插件自己的视觉样稿定义一组可区分的局部动作，再由组合根绑定其定义与获准目标，最后消费共同执行服务。该流程的正式贡献格式由工程定版；本视觉会话只负责布局自有动作和可审阅样稿。框架自有侧栏/焦点等动作仍由其明确所有者定义，普通插件不因为贡献局部动画取得外壳控制权。

## 6. 下一轮原页面试验建议

先在原 `animation-review.html` 对比三个**不同动作**：分组遮罩揭示、缩略图几何形变、一次分层呈现。动作使用相同内容，局部强调色独立切换，避免把“色彩更亮”误认为“动画更丰富”。当前连接选择和排序保留。

界面只保留识别动作及色板所需的关键标签；不把研究说明放进布局组件。新动作先评审局部目标、程度、输入与取消路径，再实施审阅夹具；不同时向正式框架入口启用。

验收必须包含：正常速度能辨别差异；快速反向/取消接续；键盘与减少/关闭有合理静态结果；颜色与图形时间一致；没有文字重影、白边或滚动条；三个目标窗口无溢出；谱面位置与大小固定；释放恢复局部样式；越界请求失败而不改变业务结果。

## 7. 官方资料与判断范围

查阅日期：2026-10-07。下列资料用于核对机制和工具能力，具体组合与色板均为本项目建议。

- Microsoft Fluent 2 / Motion：`https://fluent2.microsoft.design/motion`。说明进入退出、层次、容器变化与编排；建议依据距离和对象调整节奏，并限定动作到当前关注对象。
- Microsoft Fluent 2 / Color：`https://fluent2.microsoft.design/color`。区分中性色、共享色、品牌色和语义状态色；支持局部特色与统一信息含义并存。
- Motion / animate：`https://motion.dev/docs/animate`。当前文档列出 mini/hybrid 能力差异、颜色、SVG 绘制、时间线和物理弹簧。SVG 路径绘制不等于任意图标形变。
- Motion / stagger：`https://motion.dev/docs/stagger`。提供群组起始时序；本项目只在有意义的一次分层呈现中使用。
- MDN / clip-path：`https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/clip-path`。说明 CSS/SVG 裁剪区域和动画值类型，供局部揭示方案核对；不能由此推断任意裁剪形状或引用都可直接插值。
