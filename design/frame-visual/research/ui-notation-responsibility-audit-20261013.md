## 已核实的基线差异

当前工作区为 `E:/desktop/brilliant_ideas/brilliant_guitar`；美术工作树为
`C:/Users/ATOM/.codex/worktrees/7b1c/brilliant_guitar`。限定比较19处源文件：
17处内容不同、1处相同、1处仅当前工作区存在。这是基线差异，
不表示这些变化全部由美术会话制作。

- 当前吉他领域为 schema 2、`fretCount: null`；美术工作树仍为 schema 1、`fretCount: 24`。
- 当前 Tab 模型允许物理品数为空且不以物理末品挡记谱；美术工作树仍按物理品数校验位置。
- 当前核心包通过 `definePlugin` 登记 `apiVersion: "4.0"`，绑定已注册 staff/Tab 策略；
  美术候选核心入口仍直接返回旧 `defineUiPlugin` 声明，其工作树缺共享 Tab interaction 源文件。
- 美术候选已连接 Tab 显示，输入命令对非 staff 明确返回 `score.input.not-ready`。
  因而其视觉预览不是实际 Tab 编辑闭环；也不能据此认为本工作区已接入 Tab UI。

不得用视觉工作树整文件替换当前领域、模型、核心包入口或文档会话。
共享绘制样式可移植，但必须以当前兼容、身份、版本和正式平台接线为整合基线。

## 建议分工与本会话约束

| 内容 | 建议主要承担者 | 接口边界 |
| --- | --- | --- |
| 字形、休止、符干、遮线、间距、共同双谱排版、阅读比例及视觉检查 | UI 美术会话 | 输出完整绘制结果和同次几何，保留真实事件身份；使用原视口 |
| 真实文档双谱读取、Tab 输入意图、吉他映射、版本、事务、历史、保存及失败恢复 | 本会话 | 消费共享绘制/策略和已获准窄端口，沿一个作品和历史链 |
| `core-score-view.js`、`core-score-plugin.js`、谱式显示接线及选择联动 | 建议由本会话在当前业务基线上统一整合 | 美术提供显示变更；工程保留正式贡献、工具、生命周期和唯一选择所有者 |
| 选择高亮、光标和反馈的外观 | UI 美术会话 | 读取原选择状态及按谱式区分的几何，不建立选择/事务副本 |
| 生成脚本及候选资产 | 对应候选的整合者 | 从该候选源重新生成，不直接搬另一工作树的 vendor/dist 输出 |

这是建议，尚未向另一会话发送或取得其确认。本会话立即遵守自己的范围：
不另做 Tab 字形、休止定位、双谱排版或视口改造；继续准备真实编辑接缝。
正式修改交界文件前核对视觉补丁与当前基线，由单一整合过程落实，不能称为已协调完成。
