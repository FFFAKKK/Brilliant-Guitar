# 启动中心调研与接入建议

日期：2026-10-08。用户提出：打开应用后先显示小窗口，可管理插件、选择最近文档，再进入完整编辑器。本文件是第一版设计建议；未修改产品页面、窗口、IPC、插件协议或文件格式，未表示启动中心已实现。

## 调研依据与取舍

- [IntelliJ IDEA官方首次运行指南](https://www.jetbrains.com/help/idea/run-for-the-first-time.html)：欢迎页是项目工作的入口，可创建/打开项目，并提供Plugins和Customize。借鉴“项目入口与插件管理在同一欢迎环境”，不复制市场、教学、远程开发和账号流程。
- [PyCharm官方项目指南](https://www.jetbrains.com/help/pycharm/open-projects.html)：欢迎页能选择和搜索最近项目；关闭最后项目后可回到欢迎页。默认自动重开项目可配置。因此是否每次先显示启动中心是产品选择，不应宣称所有成熟软件都强制这个流程。
- [Guitar Pro 8官方首页指南](https://www.guitar-pro.com/docs/gp8/basics/first-steps/welcome-page)：首页组织新建、打开、最近文件、搜索和模板等内容，编辑中也有返回首页入口。借鉴以作品为主的入口；本版不复制mySongBook、作品库、音频预览或在线服务。
- [JetBrains官方插件指南](https://www.jetbrains.com/help/idea/managing-plugins.html)：已安装页管理启停、更新等；安装/更新存在重启生效路径。该资料不证明所有JetBrains插件都不支持动态加载，我们项目继续遵守自己的无热插拔、固定集合限制。

这些公开文档说明用户流程，不说明两家内部初始化/进程架构。下述单窗口和延迟激活为本项目建议，不归因于两家的实现。

## 用户确认的三页结构

用户进一步明确：启动中心包含三个可切换的独立页面，共用窗口与导航。第一页面展示最近文档、新建入口和图片形式的小预览；第二页面为插件管理；第三页面为设置。不是把三类内容同时铺在一个页面。

1. 首页（最近）：默认进入，包含最近作品列表、新建/打开入口，以及紧凑的作品缩略图/选中作品预览区域。预览用于识别作品，不提前进入完整编辑工作区。作品名称是关键文字，辅助时间/目录降低视觉权重；完整路径按需查看。预览的具体摆放由视觉稿确定，不先固定为巨大封面或完整谱面。
2. 插件：完整插件管理内页，复用已接受的紧凑列表、详情、启停/依赖状态和参数编辑。
3. 设置：独立设置内页，仅展示当前已接通的应用设置。

固定短导航为“最近／插件／设置”，配统一图标，切换只改变启动中心当前内页，不创建编辑会话或激活插件。首页使用紧凑的新建、打开和搜索入口；没有第二个巨大“启动软件”按钮，打开最近作品或新建/打开是进入工作区的动作。列表预览选择与真正打开的手势需在视觉/交互稿中明确，避免查看缩略图时误打开文档。

“插件”页复用已接受的紧凑管理布局、启停/依赖状态和参数编辑，不在首页同时塞入完整插件列表；“设置”只放已有或本切片明确接通的项。关键导航、作品/插件名称和必要错误使用文字，其余按钮优先图标、tooltip和aria-label。空状态简洁，不填假作品或无实现插件。

桌面初始为居中的紧凑可调整窗口，尺寸待独立视觉/DPI验收，不先把某个像素值写死成公共合同。进入编辑后恢复编辑器的窗口位置/尺寸。推荐第一版同一原生窗口切换内容与尺寸，仍为一个进程、一个WebView和一个正式插件平台；如果后续确有多窗口需求再定义所有者，不在当前引入双进程launcher。

## 启动流程与所有者

```text
打开应用
  → 宿主取得配置单写者租约、准备基础服务
  → 显示启动中心，读取插件目录/已存计划/最近文档元数据
  → 用户配置插件，选择最近作品或新建/打开
  → 验证并确认已保存的固定插件计划
  → 宿主接受目标文档，保护现有恢复/未保存内容
  → 确定并冻结本进程插件集合、恢复设置、唯一平台激活
  → 在可见且尺寸正确的工作区挂载，开始真实谱面绘制
```

“选择后正式启动”指开始完整工作区会话；应用进程和可运行欢迎页的基础服务已经启动。现有Rust AppState在创建WebView前就包含ScoreSessionService，不能声称目前整个内核完全延迟加载。可以明确延迟的是工作区插件激活、组件挂载和谱面绘制；实际启动成本另测。

启动中心是宿主内建入口，不依赖用户可关闭的插件才能显示。其插件页消费现有纯目录、计划控制器与存储；不能先启动全部插件再显示开关，也不为欢迎页创建第二个平台。视图仍按模块复用，平台注册和编辑器实例只在原组合根创建。

首次进入前，可调整尚未激活的计划；仍需沿原机制成功保存，失败保留草稿/当前窗口。运行后返回启动中心可查看作品和配置，但启停/参数变更仅供下次应用进程。当前会话返回编辑器复用原实例，不销毁再启动插件，不形成热插拔。

新建、系统打开、最近打开均使用同一宿主文档权威和原校验/版本/未保存保护。不得为启动中心另建谱面状态、调用第二个命令router，或先偷偷创建/覆盖空谱再换成用户选择文件。

## 当前代码已具备与真实缺口

| 范围 | 当前代码 | 后续接线 |
| --- | --- | --- |
| 插件配置先于工作区 | plugin-startup-preview在onStart后才创建documentSession/runtime；process模式返回管理保持同一runtime | 保留目录/控制器/保存链，将管理页作为启动中心内页 |
| 平台与计划 | 单正式4.0平台，设置首挂载前恢复，运行集合固定 | 不增加平台；引入统一启动状态与作品选择意图，防重复启动 |
| 原生窗口 | backup覆盖配置继承1440×900、最小960×640，Rust用原WindowConfig创建 | 只在备份入口定义欢迎/编辑阶段尺寸；先完成转换与回滚合同，避免影响废弃产品和正常配置租约 |
| 最近文档 | 本次检索的备份入口/工作台服务/桌面路径没有可复用的最近作品目录；现openNativeDocument只走文件选择器 | 新增宿主拥有的持久化元数据目录和按记录打开能力，先审查公开合同；复用原read_document、codec和接受保护 |
| 首次作品选择 | 原readonly session的ensureLoaded会readOrCreateInitialScore；open/new要求已接受初始状态 | 明确恢复已有作品、直接选择文件和显式新建的先后；不能简单在现onStart后多调用一次open来假装完成 |

最近目录仅存名称、宿主定位信息和打开时间等元数据，不存谱面正文/第二份作品状态。UI通过记录ID请求宿主打开，实际路径由宿主管理；不以任意UI字符串绕过文件入口。仅在作品成功打开并接受后登记，取消/坏文件不增加。去重、数量上限、丢失文件、只移除记录不删除作品，以及未来格式安全拒绝需在实施合同中确定。

文档已接受但最近记录写入失败，不能把作品打开伪装成失败或清空作品；保留文档并报告记录失败。插件计划保存失败则阻止首次启动，二者不是一个跨文件原子事务。

## 实施次序与验收

1. 先做独立视觉草案：最近（含新建/打开和小预览）、插件、设置三个可切换页面，复用现有管理视觉；静态示例明确标注为预览，不宣称最近文件真实可用。真实缩略图后续复用原绘制结果或缓存，不另写记谱算法，也不为预览创建第二份文档会话。
2. 冻结统一启动状态/意图、恢复保护、最近目录和宿主打开合同；处理重复点击、取消、失败重试、释放与晚到结果。
3. 实现最窄真实闭环：最近条目持久化→按ID打开→原文档接受→唯一固定平台→编辑器；新建/打开走同一协调链。
4. 加入欢迎尺寸/编辑尺寸切换，失败停留欢迎中心；真实WebView、系统缩放/键盘焦点/进程重启分别验收。返回后固定集合和原会话保持。

关键断言：选择前平台未激活、工作区未挂载；同时点击只启动一次；配置/文件失败不进入假工作区；文件不存在仍可重新定位或只移除记录；恢复内容不被覆盖；元数据不会变成谱面权威；进入/返回没有第二平台/重复订阅；工作区几何在可见正确尺寸时初始化。

现有独立作者、真实绘制/4核8GB设备和原生剩余资格继续pending；本提案不是这些验收的替代。不扩大674项历史测试为新启动中心的验证。
