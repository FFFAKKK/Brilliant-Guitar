# 框架动效市场调研与方向报告（2026-10-06）

2026-10-07 当前进展：用户采纳 Motion 并批准试点；旧五类不同动作示意已由同一内容切换／真实拖动的三种候选表现替代，仍沿用原 animation-review.html。详情和当前验收见 [motion-pilot-contract.md](../motion-pilot-contract.md)。正式框架默认无动画、风格尚未批准；下文未实施状态与旧样稿说明保留为历史调研。

状态：设计阶段，尚未启用运行时动画。

范围：只讨论备份视觉框架拥有的外壳、布局、焦点和临时承载；插件内部动画由插件会话负责。本文不发布 SDK，也不改变正式插件协议。

## 调研目的与口径

用户要求先研究成熟软件的动画风格、效果类型和适用方式，再形成报告；本报告是调研与设计建议，不是已经批准的实现规范。参考对象以 Apple HIG/WWDC、Google Material Motion、Microsoft Fluent/Windows Motion、Adobe Spectrum 为主，全部引用官方设计系统或开发者文档。它们提供的是设计语言与控件模式，不等于逐帧观察所有具体产品，也不代表每个产品在所有平台都表现一致。

区分两层结论：**资料事实**是来源明确描述的模式、原则和数值；**本项目判断**是结合谱面稳定、侧栏不遮挡工作台、插件内部自主等约束做的适配建议。

## 我们要的视觉目标

| 中文目标 | English | 具体含义 |
| --- | --- | --- |
| 动态优雅 | Dynamic Elegance | 动画有节奏、有层次，但不炫技、不喧宾夺主；结束时界面保持安静和稳定。 |
| 空间连续 | Spatial Continuity | 用户能看懂内容从哪里来、到哪里去，切换前后对象关系不会突然断掉。 |
| 克制高级 | Restrained Sophistication | 高频操作几乎即时，低频场景才给足表现；动画服务于理解，而不是制造忙碌感。 |

后续讨论动画时，优先使用这三个中文目标；英文名称只作为设计资料和开发接口的对照。

## 基础语法与视觉风格不是一回事

Fade、Shared Axis、Container Transform 等是成熟设计系统的基础语法，类似排版里的字号、网格和间距。它们解决“内容之间的关系怎么被看懂”，本身不会自动产生独特的美术气质。真正的高级感来自下面几层组合：

| 风格方向 | English | 视觉特征 | 适合的框架场景 | 当前判断 |
| --- | --- | --- | --- | --- |
| 流体空间连续 | Fluid Spatial Continuity | 状态一提交，内容沿真实来源和去向连续变化；转向、速度和停顿都跟对象关系有关；不依赖夸张弹跳 | 固定栏内容切换、布局页面的层级切换 | **首选研究方向** |
| 层次纵深 | Layered Depth | 通过透明度、轻微缩放、前后层关系和对比度制造空间，不做大幅视差 | 详情页、临时工具、局部聚焦 | 可作为第二方向；不能让谱面产生漂浮感 |
| 编辑节奏 | Editorial Kinetics | 快速、清楚、像专业编辑器；小组内容有节奏地重排，动作完成后立即稳定 | 低频排序、拖放预览、首次进入布局编辑 | 适合工作台，但必须克制交错 |
| 柔性响应 | Soft Physics | 只在直接操控时使用轻微吸附、惯性和回弹，让对象有重量 | 拖动、松手吸附、可逆调整 | 只作为局部反馈，不作为全局皮肤 |
| 环境过渡 | Ambient Transition | 通过极轻的色调、亮度和焦点变化让界面状态连续 | 选中、完成、等待和错误状态 | 可研究，但不能使用发光、闪烁和自动消失提示 |

因此，“现代感”不是让每个元素都动，而是让不同动作使用不同层级：空间关系用流体连续，内容层级用纵深，编辑操作用节奏，直接操控才用柔性响应。基础转场只是工具，不能直接当成最终风格。

## 市场常见动画类型清单（中英文对照）

下面按视觉机制整理，而非把厂商名称误当成风格本身。前四项来自 Material/Windows/Spectrum 的明确模式；“建议用途”是本项目判断。

| 动画类型 | 画面如何变化 | 成熟系统的典型语义 | 适配本框架 | 风险/避用边界 |
| --- | --- | --- | --- | --- |
| Fade / Crossfade | 透明度变化；旧内容与新内容短暂叠化 | 短暂内容替换、轻量出现 | 中高：右侧固定栏换页可试；空容器出现内容可试 | 单独淡入缺少空间解释；高频切页时可能变成拖沓 |
| Fade Through | 旧内容先淡走，新内容随后淡入，重叠较少 | 两个没有直接共享对象的目的地切换 | 高：布局页中切换互不相关的属性区 | 必须只影响固定内容视口，不能覆盖/淡化谱面 |
| Shared Axis | 前后内容沿X/Y/Z方向小幅同步移动并淡入淡出 | 有顺序、层级或导航关联的目的地 | 高：同一布局组件内“区域→尺寸→排布”这类有逻辑顺序的视图 | 方向不能暗示不存在的层级；往返切换需反向一致；不用大距离全屏推拉 |
| Container Transform / Shared Element | 同一个对象/容器从源矩形展开成目标视图 | 从列表卡片进入对应详情、同一实体跨页面保持身份 | 有条件：布局页入口和详情如果确有同一锚点可试 | 目前框架页面没有合适的稳定共享对象，不应为了炫技伪造圆点/卡片变大 |
| Edge / Drawer Entrance | 从所属边缘进入并淡化/移动 | 边缘面板、临时工具或系统层 | 低到中：框架将来若有真正临时面板，可在预留槽内演示内容进入 | 侧栏是常驻分区，动画不能改变边界、挤动左右栏高度或遮住谱面 |
| Reposition / List Reorder | 已存在项目平滑移到新位置 | 插入、排序、重新分组，保留对象身份 | 高但仅限布局编辑预览的低频拖放结果 | 不可以排序按钮每击一下就全组跳舞；不改变内容状态、只呈现已经提交的目标顺序 |
| Scale / Zoom / Morph | 元素缩放或形状尺寸转变 | 强调源目标身份、重要对象进入焦点、系统级焦点变化 | 低：谱面纸张、宿主区域禁用；可作为孤立的低频演示研究 | 极易造成谱面尺寸/位置误解，放大还可能显得臃肿；禁止 scale(0) 式出现 |
| Spring / Overshoot | 越过目标后回弹或带物理弹性 | 拖拽、直接操控、表现性反馈 | 低到中：未来只考虑可拖动对象松手后的微小吸附 | 不用于普通按钮、切页和布局尺寸；回弹会让专业编辑器显得玩具化 |
| Color / Fill / Focus / Press | 颜色、填充、焦点或按压状态短暂变化 | 轻量操作反馈、当前状态强调 | 中：编辑态进入可用轻微颜色/填充反馈；高频动作优先即时 | 不额外添加发光描边或装饰白框；状态必须不依赖颜色单独表达 |
| Animated Icon / Symbol | 符号笔画、形态或方向变化 | 提示状态切换、引导注意某个动作 | 低：由插件自有图标体系负责，框架只提供边界 | 框架不规定插件图标与品牌动效，也不使用持续旋转制造活动感 |
| Stagger / Choreography | 一组元素按顺序延迟出现或移动 | 初次加载、分批强调的相关内容 | 低：不作为侧栏常态进入效果 | 成组密集内容会产生“AI味/演示页感”，高频打开很慢；只允许少量 onboarding 研究 |
| Parallax / Blur / Z-depth | 层次以不同速度移动、模糊或透视变化 | 沉浸式空间、背景深度、焦点强调 | 极低：不进入谱面编辑工作区 | 分散阅读、易晕动、占资源、破坏专业静态底板；reduced-motion需显著简化 |
| Indeterminate Loop / Pulse | 无限循环的转动、脉冲或呼吸 | 真实未知时长的等待、持续待处理状态 | 有条件：仅真实异步等待可用静态/低运动指示，且必须配文字状态 | 不装饰性循环；重要错误/结果不可自动淡走；不可捏造忙碌状态 |

### 术语速查

| English | 中文 | 直观理解 |
| --- | --- | --- |
| Fade | 淡入 / 淡出 | 内容透明度变大或变小，位置基本不动。 |
| Crossfade | 交叉淡化 | 旧内容淡出时新内容同时淡入。 |
| Fade Through | 淡出穿越 | 旧内容先淡走，短暂留出呼吸，再让新内容出现；适合没有直接空间关系的页面切换。 |
| Shared Axis | 共享轴转场 | 前后内容沿同一横向或纵向方向移动，表示它们存在顺序或层级关系。 |
| Container Transform | 容器变形转场 | 同一个容器从原来的小区域连续变成新的大区域，表示“这个对象打开后就是那个详情”。 |
| Shared Element / Connected Animation | 共享元素 / 连接动画 | 同一个对象在两个页面之间保持身份和视觉连续。 |
| Edge Entrance | 边缘进入 | 内容从它所属的边缘进入或离开，适合临时工具或浮层。 |
| Reposition | 位置重排 | 已存在的内容移动到新位置，适合低频排序和拖放结果。 |
| Spring / Overshoot | 弹簧 / 轻微回弹 | 内容到达目标后有轻微弹性，适合直接拖拽，不适合普通按钮。 |
| Scale / Morph | 缩放 / 形变 | 对象大小或形状发生变化，强调焦点或对象身份。 |
| Stagger / Choreography | 交错进入 / 编排 | 一组内容按照很短的间隔依次出现，适合首次引导，不适合常态侧栏。 |
| Parallax / Z-depth | 视差 / 纵深 | 不同层以不同速度或深度移动，制造空间感；本工作区原则上排除。 |
| Microinteraction | 微交互 | 按压、聚焦、选中、状态变化等极短反馈。 |
| Reduced Motion | 减少动态效果 | 保留必要的透明度和状态变化，移除位移、缩放等运动。 |
| Motion Off / None | 关闭动效 | 直接呈现最终状态，不等待过渡。 |

## 视觉丰富度不等于风格区别

此前样稿只让同一列表做小位移、透明度和微缩放，三种预设的变化过于细小；内容也只有一处替换，因此用户难以看出材料转场与空间转场的差异。这种表现不能代表本报告所列出的成熟动画类型，也不能支持风格选型。应撤销“已有三风格对比可供决策”的结论。

下一阶段如果要制作视觉演示，需要由用户确认报告方向后另开样稿阶段。演示应对同一个具体动作展示明确可辨的候选，例如：固定栏内 Fade Through、低幅 Shared Axis、符合条件时的 Container Transform、低频 Reposition、边缘临时工具进入、轻量反馈/图标状态、低频 Spring/Expressive。每段同时展示正常速度与慢放，标注进入/退出路径和实际使用语义；默认总览则将适配范围标为“推荐、谨慎、排除”。这是一份研究建议，当前不实施动画。

## 市场动画谱系与取舍

把成熟软件的动效拆成“它在解释什么”，比照搬某个软件的曲线更稳定：

| 谱系 | 常见做法 | 我们借鉴的部分 | 我们明确不借鉴的部分 |
| --- | --- | --- | --- |
| 系统级空间动效（Apple） | 用来源、去向和层级变化解释界面关系；动效短、可取消、可关闭 | 只在内容关系发生变化时动；动效策略可切换 | 不把侧栏开合做成推动谱面的系统转场 |
| 标准/表现双轨（Material） | 用标准节奏处理日常操作，用表现节奏处理少量重点场景 | 用 `quiet / spatial / expressive` 形成风格层；不同频率使用不同预算 | 不把表现性节奏用于滑条、键盘、高频布局操作 |
| 功能连续性（Fluent） | 强调功能性、自然感、一致性和减少动效 | 让动效只解释状态和空间，不承担业务结果；保留 `reduced` | 不做连续装饰、无限循环和“看起来很忙”的背景运动 |
| 主题化过渡（Spectrum） | 通过统一 token 控制时长、缓动和可访问策略 | 把动效参数放在宿主 token 层，组件只声明语义动作 | 不让插件写全局动画或绕过宿主策略 |

这四类成熟方向最后收敛成三个可审阅风格：`quiet` 是专业工作区的候选默认，`spatial` 用于需要解释来源和去向的内容切换，`expressive` 只给首次引导、主动预览或插件私有的低频反馈。它们共享同一份布局快照，不共享业务状态。

本阶段的“炫酷”定义为层次、来源和节奏清楚，而不是增加弹跳、闪烁、旋转或大幅缩放。对谱面软件来说，动效越能让用户感觉工作台稳定，越接近高级软件的质感。

## 当前基线

框架当前以即时状态为基线：`styles/base.css` 对框架节点统一关闭 `transition` 和 `animation`。这是为了先保证谱面位置、区域几何、焦点和滚动行为可验证，不代表以后永远禁止所有动效。

动画引入前必须回答三个问题：是否真的需要动、动效是否解释空间关系、动效是否会延迟用户已经完成的操作。布局开合、滑条和键盘高频操作不适合加入等待式动画。

## 建议保留的三种风格

| 风格 | 视觉气质 | 适用场景 | 基础参数 | 不适用场景 |
| --- | --- | --- | --- | --- |
| `quiet` 克制 | 几乎静默、专业、编辑器感 | 默认工作区、谱面阅读、键盘操作 | 0–140ms；只淡入和极小位移 | 不做强调性展示 |
| `spatial` 空间 | 清楚表达来源和去向，轻微滑入/淡入 | 菜单、临时详情、侧栏内部内容 | 120–200ms；ease-out；位移 4–10px | 不改变外壳几何 |
| `expressive` 风格化 | 更有辨识度，带轻微层次和状态强调 | 首次引导、插件自己的特殊反馈、用户主动预览 | 140–240ms；可使用极轻微 scale/blur | 不作为默认工作区动效，不用于高频操作 |

默认建议使用 `quiet`。用户可以在动画审阅页切换 `quiet / spatial / expressive`，但风格切换只影响样稿表现，不改变正式框架状态。

## 风格层的技术边界

- 风格层只提供 token：`duration`、`easing`、`distance`、`opacity`、`scale` 和是否启用。
- 组件只声明语义动作，例如 `enter-content`、`open-detail`、`feedback-pulse`，不能直接写全局动画规则。
- 宿主统一决定 `motion: full / reduced / none`；插件不能绕过宿主设置。
- `none` 必须是即时最终状态；`reduced` 只保留必要淡入，移除位移和缩放。
- 风格层不拥有业务状态，不拥有布局状态，也不决定动画何时提交。

## 动画候选矩阵

| 场景 | 当前建议 | 候选节奏 | 必须保持 |
| --- | --- | --- | --- |
| 左右侧栏内容出现/隐藏 | 可以考虑内部内容淡入和极小位移 | 120–180ms，ease-out | 外壳宽度立即确定，谱面不移动，侧栏不覆盖谱面 |
| 上下栏内容出现/隐藏 | 谨慎考虑内容淡入 | 120–160ms，ease-out | 横带总高度和工作台矩形不通过动画改变 |
| 菜单/临时详情 | 可以考虑定位后淡入 | 120–180ms，触发点为 transform-origin | 先完成定位，动画不能重新定位或改变焦点顺序 |
| 布局组件区域选中 | 保持即时蓝色状态 | 0ms | 不做弹跳、缩放和延迟选中 |
| 滑条、数字输入、尺寸调整 | 保持即时 | 0ms | 输入值、thumb、填充和宿主几何始终同步 |
| 谱面缩放和谱面重排 | 保持即时 | 0ms | 不制造追赶动画或虚假的可拖区域 |
| 反馈状态变化 | 只考虑原位短暂淡入 | 100–140ms | 不自动隐藏重要错误，不影响业务结果 |
| 插件私有内容 | 由插件会话决定 | 不由框架预设 | 不得访问或改变宿主几何 |

## 视觉原则

| Before | After | Why |
| --- | --- | --- |
| 通过 `width` / `height` 动画打开侧栏 | 先提交几何，再只动画内部 `opacity` / `transform` | 避免谱面和其他区域跟着移动 |
| 所有按钮都加入过渡 | 高频布局按钮保持即时，偶发临时层才考虑动效 | 高频操作需要立即响应 |
| `transition: all` | 只允许明确的 `opacity`、`transform` 属性 | 防止边框、尺寸和布局被隐式动画化 |
| 从 `scale(0)` 出现 | 使用接近 1 的起始比例或只淡入 | 避免界面像凭空生成 |
| `ease-in` 进入界面 | 使用短时 ease-out | 进入反馈要先快后稳 |
| 业务失败后自动淡出 | 保留原位状态和主动查看入口 | 重要反馈不能因为动画丢失 |

## 动画硬限制

- 不动画化外壳宽度、高度、谱面纸页位置、谱面缩放和工作台边界。
- 不使用动画改变页面级滚动策略，不产生浏览器式滚动条。
- 不用动画代替文字、图标、焦点轮廓或错误说明。
- 关闭区域、卸载组件、切换页面时必须取消未完成动画并清理监听。
- 宿主关闭动效或 `prefers-reduced-motion` 时立即呈现最终状态。
- 动画只能消费权威快照，不能用动画结束时点决定提交、成功或失败。

## 推荐的第一份样稿

只做一个框架样稿：在固定宽度的右侧布局页中，切换一个已经存在的内容页时，让页内内容在原位短暂淡入；右栏宽度、谱面矩形、滚动位置、焦点和外壳变量保持不变。

这个样稿可以验证动效是否真的增加空间连续性，同时不会把侧栏开合、尺寸调整和谱面定位混在一起。通过后再考虑左右侧栏内部内容的出现/隐藏；滑条、区域图标和布局选中态暂时不动。

## 第一阶段建议做的风格审阅

动画审阅页可以提供三个并列样稿：

1. 同一内容页切换的 `quiet`：只做 100–140ms 淡入。
2. 同一内容页切换的 `spatial`：从内容自身方向 6px 淡入，120–180ms。
3. 同一内容页切换的 `expressive`：轻微 `scale(0.985)` 加淡入，140–220ms；不使用弹跳。

三种样稿必须使用同一份布局快照和同一谱面工作台。比较时只看动效气质，不重新设计按钮、图标或插件内容。

审阅顺序固定为：先看 `none` 确认几何基线，再看 `quiet` 判断是否已经足够，再看 `spatial` 判断方向信息是否有价值，最后看 `expressive` 判断额外层次是否值得它的视觉成本。若 `quiet` 已经能解释变化，就不升级为更强风格。

## 验收门槛

1. 默认无动画入口和动画样稿入口必须隔离。
2. 动画样稿必须通过谱面矩形、无页面滚动、焦点恢复和节点身份回归。
3. 快速重复触发时不能堆积旧动画，也不能让旧回调覆盖新状态。
4. reduced-motion、宿主关闭动效和组件卸载都必须即时结束。
5. 用户批准样稿后，才把有限动效写入共享框架样式；未批准前不改变默认入口。

## 演示页进展（2026-10-06）

用户审阅报告后批准制作测试页，并明确要求沿用既有页面。首轮五种方向演示被反馈为常规、无聊；第二轮仍在 `animation-review.html` 内增强每种动作的轨迹与编排：流体连续用新旧内容遮罩接力，层次纵深用3D层片错拍展开，编辑节奏以42ms间隔保留身份并重排，柔性响应从原位沿弧线越过目标后稳定，环境过渡由状态锚点向外扩散柔和色层。名称与用途提供中英文；播放策略提供完整、慢放、减少和关闭。此测试页仍是独立视觉样稿，不能据此视为风格已经选定或默认框架已经启用动画；实际浏览器像素复核仍待完成。
