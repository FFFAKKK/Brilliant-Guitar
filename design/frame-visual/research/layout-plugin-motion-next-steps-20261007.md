# 布局插件现状与自有动画下一步 · 2026-10-07

## 1. 当前是否独立

**已经独立登记为备份 UI 包中的内置小插件，但尚未完成下一版公共 SDK 和完整动画贡献接口。** 这两个状态要分别汇报。

| 项目 | 当前事实 | 依据 |
| --- | --- | --- |
| 独立身份与入口 | `frame.layout`，由 `createWorkspaceLayoutPlugin()` 定义 | `src/features/workspace-layout-plugin.js` |
| 自己的页面贡献 | `frame.layout.page`，右侧“工作区布局”页面 | 同一 factory 的 ui 声明 |
| 同一平台独立装配 | 组合根让 builtin 使用 `includeLayout: false`，再将布局插件作为另一份声明交给同一 platform.register/start | `src/host/workspace-runtime.js` |
| 受限协作 | 页面消费 layout/contents/actions/view 只读端口，经 ctx.execute 请求获准命令；订阅和视图有释放路径 | `src/features/workspace-layout-page.js` |
| 共享视觉实现 | 页面复用 `src/shell/workspace-layout-visual.js` 和布局样式；共享实现不等于另一份插件登记或状态所有权 | 当前页面的 import/mount 链 |
| 新版共同声明与动画贡献 | 普通作者接口尚不接收 animations 等根字段；不能以独立登记宣称这些已完成 | `plugin-authoring.md`、`src/runtime/ui-plugin-contract.js` |
| 当前动画样稿 | `layout-pilot.js` 是动画页的局部视觉夹具，用布局示例身份绑定动画端口；没有通过当前插件平台登记，也不是正式布局页面实例 | `src/fixtures/animation-review.js` 与 `src/fixtures/motion-pilot/layout-pilot.js` |

宿主持有四区域状态与编辑事务仍然合理。布局插件负责设置页面与命令请求，不应为了“独立”复制宿主状态、取得其他插件实例或创建另一套命令总线。

## 2. 是否定义自己的动画

**需要由布局插件作者定义其自有动画。** 动画并非所有插件的必填能力；这里是已有布局功能选择贡献的表现。

首批先整理已经认可的三项，不改变现有外观和节奏：

| 自有动作 | 作者定义什么 | 公共执行规则 |
| --- | --- | --- |
| 页签连接选择 | 蓝色窗口与同步亮字、局部目标、移动轨道及默认节奏 | 从实际位置接续；系统减少/关闭与键盘立即完成 |
| 内容切换 | 位移方向、入场/退场轨道、默认时长与曲线、静态终态 | 新业务视图先接受；旧内容不可交互；快速反向和失败不覆盖结果 |
| 排序让位与落位 | 局部排序对象、弹簧表现与默认参数，受约束后释放速度 | 预览不提交，释放提交；取消清除预览；不得越出边界或影响谱面 |

布局默认配色继续由作者使用当前批准的蓝色、灰色和浅灰工作区，不以添加动画为理由更换全局主题。后续可为布局自有图形配置局部色彩；其他插件由其作者决定私有配色。

## 3. 实施顺序

1. **先整理作者归属。** 为动画审阅样稿建立布局自有定义模块，描述现有三项动作的触发、局部目标、轨道/默认节奏、静态回退与停止/释放。现有 coordinator 中为布局写死的具体美术参数迁入作者定义；共同执行策略、许可和检查仍在协调器。文件分离只是第一步，必须证明执行链实际消费作者定义，不能只移动常量后声称贡献已实现。
2. **原页验证运行试点。** 在原 `animation-review.html` 消费布局自有定义，验证相同效果、局部许可、定义校验、快速中断、释放、减少/关闭和固定谱面。仍是 review-only 绑定，当前 defineUiPlugin 根字段不增加未支持的 animations。
3. **再增丰富动作。** 以同一作者定义方式制作布局缩略图的局部几何变化、设置分组的揭示、一次分层呈现。逐项声明必要目标和属性许可；新图形轨道不能从现有 x/y/opacity 权限中暗自扩大。不同动作与色彩分别对比，避免用更亮配色代替动作差异。
4. **最后按工程接口迁移。** 工程定版正式动画贡献与绑定/预算合同后，把已验证的布局作者定义映射到 frame.layout；再验证真实页面。该步才是动画进入现有布局插件，不把试验身份或候选格式冒充正式 SDK。

本视觉会话负责布局的表现、定义样稿和原页视觉试验；正式协议、平台装配与真实业务接线交工程会话。美术样稿先收敛，工程接入再联合验收，不同时重写既有正式承载结构。

## 4. 必须保留的限制

- 公共协调器执行作者的获准定义，不替所有组件选择动作或配色；作者默认参数也需要通过范围与程度校验。
- 基础声明合法而动画为空时使用静态表现，已提供但非法的定义明确拒绝。
- 侧栏外壳开合是其明确所有者的表现；布局插件调整区域状态仍走宿主命令，不因为贡献动画获得外壳任意节点控制权。
- 输入、业务提交、权威状态和动画完成保持独立；减少/关闭、失败、隐藏与卸载不破坏结果。
- 同一作者可以定义多个动作，不新增动画插件分类或第二个注册器；共享引擎实例不进入普通作者的上下文。

## 6. 低复杂度、低耦合的接入约束（用户要求）

该形式适合项目：插件内部保持较高内聚，外部通过少量稳定接口协作。但“插件自定义一切”本身不保证低耦合；仍须限制哪些信息进入公共协议、谁持有状态以及谁装配依赖。

### 6.1 留在插件内部，还是向宿主声明

| 内容 | 放在哪里 | 什么时候才进入公共协议 |
| --- | --- | --- |
| 私有按钮、图标、排版、局部配色、辅助函数 | 插件普通内部模块，由作者组织 | 提供宿主入口、跨插件主题能力或公共承载需求时，只公开相应必要描述 |
| 局部动画的具体轨道、默认参数与回退 | 插件自有定义/模块 | 为取得受限执行许可、遵守减少/关闭策略或供其他插件选择使用时，声明最小必要合同；不把每个内部效果都独立登记 |
| UI 内容入口 | 同一作者声明中的可选贡献 | 告知宿主稳定 ID、允许承载位置、挂载入口与必要权限；不序列化整个内部 UI 树 |
| 需要公开调用的动作与数据 | 稳定版本的命令或只读端口 | 有明确消费者和实际需求时公开；只读与修改分离，私有状态不直接暴露 |
| 依赖和共享服务 | 应用组合根选择、验证并注入 | 仅注入所需能力，不让作者从全局容器自行取得任意服务 |

最低共同声明仍是身份/名称/版本/宿主兼容要求；UI、动画、配色及功能接口按需存在。当前 v1 的字段约束保持，不因这张表自动开放新字段。

### 6.2 一条接入链

```text
插件自己的入口与内部模块
  → 一份作者声明（身份 + 所需可选贡献/权限）
  → 应用组合根选择本次固定集合
  → 既有平台统一校验、登记、启动
  → 宿主选择承载位置并挂载一次
  → 局部实例消费获准接口
  → 所属实例停止并释放资源
```

既有贡献目录与布局读取登记结果，不导入新插件私有文件。添加使用已开放能力的普通插件，应只涉及该插件及启动装配清单，不为它在布局器或宿主增加名称特判。需要全新能力种类时才扩展版本化公共合同，并验证实际宿主消费路径。

### 6.3 必须执行的工程规则

1. **单一状态所有者。** 宿主拥有区域开合、尺寸和承载顺序；领域数据由对应权威模块拥有；插件拥有私有输入和呈现状态。其他消费者通过投影读取、通过受限命令请求修改，不各复制一份可提交的真实状态。
2. **只依赖公开接口。** 作者不持有完整 store/router、其他插件实例或私有 DOM，不引用宿主内部实现路径。接口可以有依赖，依赖的能力/版本/缺失行为须明确；并非要求完全无依赖。
3. **普通代码优先。** 插件内部继续使用普通组件、函数与模块。只声明宿主需要的信息，不建立覆盖全部 UI/动画/配色的庞大 JSON DSL，不为每个内部模块新增登记单元。
4. **共享机制集中，具体表现局部。** 复用现有登记、命令、实例宿主与生命周期。共享动画执行服务处理许可和公共策略；作者定义实际动作。通用模板可自愿使用，不另建每插件管理器或全局服务定位器。
5. **依赖按需注入。** 组合根注入所需只读端口和执行能力；普通插件不能从任意服务查询入口获得更多权力。跨插件协作只在存在实际需求时经过明确端口，不默认经过全局事件总线。
6. **状态先成立，表现消费变化。** 动画完成不提交业务。关闭或移除可选动画后，其余已提供功能按自己的合同继续工作。必需功能/服务依赖缺失应明确不可用，不能假装为空贡献。
7. **生命周期完整且区分隐藏与释放。** 挂载中途失败清理已取得资源；移动位置尽量复用实例；隐藏按合同暂停表现但保留该保留的输入；最终卸载停止动画并清理事件、订阅、任务和局部样式。迟到结果不复活旧实例，重复释放安全。
8. **兼容与空值在边界处理。** 必填无效拒绝，合法可选省略/null规范化为空，已提供但非法明确诊断。0/false 保留；不在每个组件重复规范化逻辑。新版合同需保持既有 v1 兼容或显式迁移，不能暗中放宽字段。

### 6.4 当前真实差距与收敛方式

- 当前统一登记链、持久 ComponentHost、限定 execute 与实例清理已经存在，可继续使用。它们不代表新版本协议全部完成。
- 布局 factory/page 仍从 `host/workspace-commands.js` 和 `host/sidebar-commands.js` 导入命令标识。正式作者入口应从稳定公开合同导出这些符号，具体处理器保留在宿主实现层；可集中兼容旧导入，不增加另一条命令路由。共享包内部的视觉辅助模块与跨插件私有依赖要分别判断，不能仅按目录名称认定耦合。
- 当前普通组件 ctx 主要是 execute/notify/onDispose 等受限能力；完整作者动画定义、新版共同元数据和依赖协商尚未开放。不能虚构 ctx.motion/通用服务获取器已可使用。
- 插件私有颜色无需强制增加单独的主题贡献。只有要被外部选择、覆盖或消费的主题能力才定义公开合同；公开主题与动画仍可分别为空。

### 6.5 判定是否达标

- 新增使用已有能力的内容插件，无须修改布局插件私有代码；目录中的新内容可被现有承载管理。
- 仅调整插件内部按钮、配色和动画，不改变宿主装配/状态合同；新增受限属性权限属于显式合同变化，需要相应验证。
- 更换共享动画引擎，只改适配层及其适配验证，不要求所有作者重写定义；动画引擎类型不成为普通作者接口。
- 关闭/减少可选动画仍能得到正确结果，文本与交互不依赖播放完成。
- 实例移动、隐藏、失败和卸载不会留下资源或写回已失效状态；其他已成立实例不被清理误伤。
- 元数据、版本、可选空值、越权及未开放字段的诊断明确，不以静默忽略掩盖不合法接入。

以上是实现和验收约束，不是本轮新增运行能力。本轮只补接入评审说明；当前代码无修改，也没有新增接口通过数。
