# 外部会话未完成事项交接（2026-10-06）

这份文档只记录**不属于当前备份视觉框架会话职责**的未完成事项，供其他工程或插件会话接手。它不要求本视觉会话继续实现，也不代表这些能力已经进入正式 SDK。

## 当前视觉会话已经交付的前置条件

- 备份框架外壳、四区域布局组件和工作区几何已经稳定。
- `frame.layout` 已作为备份运行时中的独立布局小插件试点存在，但仍是 v1 内部形态。
- 布局组件通过宿主只读投影读取区域、内容目录和动作状态，通过受限命令请求变化。
- 普通插件不进入布局组件内部，也不直接写工作区状态。
- 当前整包视觉测试为 386 项通过；这不等于正式 SDK、真实插件或内核接线完成。

## 需要其他会话接手的事项

### 1. 正式插件共同声明与版本协商

需要定版并实现所有插件都必须具备的共同字段：

- 稳定身份和命名空间。
- 插件名称。
- 插件版本。
- 宿主接口兼容范围。
- 缺失、格式错误和版本不兼容时的拒绝结果。
- 旧 `namespace / ui / commands / menuItems / shortcuts` 字段迁移策略。

验收要求：基础必填为空时拒绝注册；可选贡献全部为空或 `null` 时仍能合法安装；迁移不能静默改变旧插件行为。

### 2. 可选贡献与权限限制

正式协议需要把功能、输入、绘制、动画、设置、菜单、快捷键和反馈等能力作为可组合的可选贡献，而不是互斥插件分类。

每项贡献需要明确：

- 目标范围和可访问对象。
- 权限和替换边界。
- 数量、时长、频率、并发和资源预算。
- `null`、缺失、无效、不可用和执行失败的区别。
- 订阅、取消、卸载和异常清理规则。

### 3. 工作区布局插件正式化

当前 `layout-pilot` 仍是中性视觉夹具。其他会话需要：

- 把布局只读投影和受限命令定为正式稳定合同。
- 定义编辑凭据、修订号、并发修改和陈旧请求处理。
- 明确布局插件的生命周期、实例复用和释放保证。
- 使用真实插件替换中性夹具，验证移动、隐藏、排序、确认/取消和权限拒绝。

### 4. UI、内核和其他插件的结果反馈链路

需要工程会话定义：

- UI 自身错误如何反馈给宿主。
- 内核成功、拒绝、失败和结局待核对如何投影到 UI。
- 其他插件错误如何报告、归属和清理。
- 报告失败不能覆盖业务结果，也不能自动重试业务写入。
- 错误呈现失效时的最小可见回退路径。

### 5. 真实业务接线

以下内容不由本视觉会话实现：

- 内核、IPC、持久化和生产配置。
- 真实谱面编辑、输入、撤销重做和文件恢复闭环。
- 播放、输出、乐器能力和业务历史。
- 正式桌面组合根和真实插件包发布。

### 6. 插件内部视觉

每个插件会话负责自己的：

- 按钮和图标。
- 私有配色和内容排版。
- 私有动画和业务反馈。
- 私有输入控件和内部状态展示。

宿主只负责承载边界、焦点、权限、生命周期、区域几何和统一反馈入口。

插件若提供动画贡献，必须消费宿主公开的动效策略和受限 token；不得绕过 `motion: none/reduced`，不得修改宿主布局几何或使用动画结束时间决定业务结果。

插件若提供动画贡献，必须消费宿主公开的动效策略和受限 token；不得绕过 `motion: none/reduced`，不得修改宿主布局几何或使用动画结束时间决定业务结果。

## 接手顺序

1. 先定版共同声明、版本兼容和可选空值语义。
2. 再定版只读投影、受限命令、权限、预算和生命周期。
3. 用一个真实布局插件和一个普通可移动插件完成端到端试点。
4. 接入内核、持久化和错误反馈链路。
5. 最后回接备份视觉框架，复核容量、焦点、谱面位置和反馈承载。

## 接手时必须保持的边界

- 不修改真实废案 UI 作为视觉参考或实施入口。
- 不把 `design/frame-visual` 中的 fixture、测试夹具或候选 TypeScript 文件直接当成正式 SDK。
- 不让插件获得完整 store、完整 router、谱面私有 DOM 或其他插件实例。
- 不让插件改变谱面绝对位置、外壳几何或滚动策略。
- 不把布局组件重新塞回普通模块库。
