# 布局组件第一个协作试点

日期：2026-10-05。状态：备份视觉框架的显式审阅夹具，不是正式插件 SDK，也不是真实业务组件。

同日补充：承载布局设置的页面已从内置组合拆为 `frame.layout` 独立小插件；中性试点面板仍是显式夹具。当前接口、宿主责任和其他插件接入方式见 [布局小插件说明](./workspace-layout-plugin-interface.md)。

## 这次先验证什么

布局组件已经有稳定的视觉雏形，因此先用它作为第一个跨组件协作试点。试点只验证框架边界：布局组件可以读取宿主提供的内容目录和动作状态，通过受限命令请求移动或隐藏一个面板；宿主负责权限、实例、布局事务、焦点和区域几何。

打开：

```text
layout-collaboration-review.html?fixture=layout-pilot
```

这个入口只在审阅时装配一个名为“布局试点面板”的中性面板。默认入口、结构预览和运行时预览不会加载它。

## 试点中的一个完整流程

1. 试点面板以右侧栏为默认位置，拥有左、右两个允许位置。
2. 布局组件从只读目录读取它的稳定组件 id、当前区域、允许位置和可用状态。
3. 用户进入布局调整后，把面板移动到左侧，宿主重新检查编辑会话、目标区域和权限。
4. 移动成功后复用原面板实例；输入内容、阅读位置和挂载次数不因换栏而重置。
5. 取消只恢复内容配置；期间已经发生的区域开合、尺寸和整体排布保留。
6. 确认只保留当前内存配置；它不模拟持久化，也不声称已经写入真实产品。

## 这个例子说明的接口边界

布局组件需要消费：

- 区域快照和订阅：开合、尺寸、排布、调整状态与限制。
- 内容目录和订阅：稳定 id、允许位置、当前位置、启用状态和拒绝原因。
- 动作状态和订阅：存在、可用、按下状态、快捷键和不可用原因。
- 受限布局命令：进入、确认、取消、区域开合、尺寸、排布、移动、启用和排序。

布局组件不取得：

- 其他插件的私有函数、DOM、store、router 或实例对象。
- 真实业务数据、内核服务、持久化路径或正式错误总线。
- 插件内部按钮、图标、配色、排版和动效实现。

## 验收重点

| 场景 | 要看到的结果 |
| --- | --- |
| 普通模式移动 | 宿主拒绝，不能只依赖按钮禁用 |
| 编辑中移动 | 位置改变，面板实例不重建 |
| 编辑中输入再取消 | 位置恢复，输入和阅读位置保留 |
| 无权限探测 | 返回明确拒绝，不调用插件动作 |
| 隐藏再打开 | 同一实例恢复，不重复挂载 |
| 运行时释放 | 订阅、监听和面板资源释放，不污染下一次会话 |

## 本次不做的内容

布局组件已经使用当前 v1 作者接口独立登记在同一平台。本试点不发布新版共同声明或正式 SDK，不实现真实谱面属性内容；中性面板的真实业务替换仍待对应会话。工程合同定版后，再用同一流程接入真实插件；本视觉会话维护备份框架的承载、容量、焦点、区域和反馈呈现。
