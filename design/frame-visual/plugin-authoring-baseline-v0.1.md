# UI 插件受限试点作者规范 v0.1

日期：2026-10-04。状态：受限试点；三个代表性测试插件已制作，25 项逻辑场景通过。有 UI 的真实浏览器验收尚未完成，当前不具备扩大制作的全部条件。

本文规定从备份框架 `design/frame-visual` 开始试点时可以使用哪些能力、作者怎样交付，以及通过什么验收才能扩大制作范围。适用对象是由项目维护者审阅、在固定启动集合中装配的插件。

`v0.1` 是本文档版本，不是新增的 manifest、SDK 或宿主 API 版本。文档收敛不代表运行能力已经补齐，也不承诺现有原型接口永久稳定。

## 1. 阅读路径与合同归属

1. 用 [设计原则](./plugin-design-v0.1.md) 判断是否独立登记，并确定状态所有者。
2. 用本文确认试点范围、作者约定和验收门槛。
3. 用 [当前作者 API](./plugin-authoring.md) 查精确字段、默认值、空值和完整接入示例。
4. 用 [本产品 UI 接入要求](./plugin-product-ui-profile.md) 检查视觉、焦点和布局。

当前字段的可执行事实以作者 API 和实现核对为准；下一版身份、兼容及授权策略依照 [应用级平台目标](../../docs/plugin-platform-ui-contribution-and-session-freeze-plan-v1.md) 收敛。遇到文档与实现不一致，应记录差异并修正文档或实现，不能靠作者猜测字段。

本规范新增的作者约定会明确标出；尚未由宿主强制校验的约定，需要通过插件交付验证。本规范不向当前 API 添加字段或钩子。

## 2. 首批可以使用的能力

| 能力 | 当前路径 | 试点范围及边界 |
| --- | --- | --- |
| 无公开贡献的声明 | `namespace` 与 `ui: []` | 可验证合法登记及结束运行；不把空声明计为功能完成 |
| 无界面的离散命令 | `commands`，`ui: []` | 可以有私有计算状态；不申请需要插件根级生命周期管理的驻留资源 |
| 左右侧栏内容 | `kind: "panel"` | 允许位置由自己的 `slots` 声明；首批使用持久单实例 |
| 命令入口组合 | 按钮、`menuItems`、`shortcuts` | 引用同一个 handler；核对每个入口的实际反馈和权限 |
| 局部键盘交互 | 本插件组件的局部键位、实例 `handleKeyDown` | 遵循当前同步消费规则、焦点和文本输入保护 |
| 命令确认 | 宿主提供时的 `ctx.confirm` | 可选能力；使用前检查，沿用已有确认合同 |
| 组件内的临时任务及资源 | 同步挂载后启动，`ctx.onDispose` 清理 | 明确隐藏、释放及旧结果处理；不据此取得跨组件或插件级服务能力 |

下列能力暂不作为首批插件的依赖：

| 能力 | 尚缺内容 | 开放前的验证要求 |
| --- | --- | --- |
| 中央 `view`、上下栏 `slotItem` | 当前入口只有声明和目录，缺实际消费 | 完成真实承载、焦点、可见性与释放路径 |
| 谱面工作区中的固定辅助内容 | 目标在工作区内部左右两侧独立占位、不遮挡谱面；首版宿主预设位置，自由放置后续；当前 panel 仅左右侧栏 | 完成位置合同、区域承载、布局配置及输入边界，见 [工作区位置设计](./score-workspace-placement.md) |
| 工作区小面积临时浮层 | 目标允许右键菜单等按触发点或公开锚点显示；现有顶栏菜单不代表通用接口已开放 | 完成面积、边界、锚点失效、命令权限、输入／焦点及清理合同；不保存临时坐标 |
| 放大时原左右侧栏自动收放 | 当前缩放只调整谱页，尚无本项协调 | 宿主统一实施触发、恢复及防振荡；按侧、按属性保留用户期间的手动开关和尺寸调整 |
| 根级名称、版本、兼容要求及统一可选空值 | 当前作者入口没有对应新合同 | 字段映射、协议迁移、校验及旧输入兼容 |
| 无界面的驻留功能 | 无插件根级初始化／释放及独立功能上下文 | 明确受限上下文和生命周期，不借假面板取得清理入口 |
| 共享绘制、跨组件输入、动画或设置扩展 | 公开合同及相应宿主能力尚未开放 | 按设计原则第 11 节逐项完成合同及实际消费 |
| 真实谱面读写 | 新桌面宿主、领域端口及真实投影尚未接通 | 验证真实服务、文档版本、事务、反馈及撤销 |
| 多实例、热插拔及跨重启配置 | 当前没有对应承诺 | 单独设计和验证后再扩大范围 |

前一张表表示可以准备受限试点，不表示已经完成真实浏览器验收。后一张表的能力可以继续设计，不提前写入当前声明。

## 3. 声明、身份与装配规则

### 3.1 当前字段范围

当前作者根字段只有 `namespace/ui/commands/menuItems/shortcuts`。`namespace` 必填；`ui` 必须是数组，可以为 `[]`；其余集合可省略，显式 `null` 会失败。新增作者按 [字段表](./plugin-authoring.md) 填写，不使用旧 `module/page` 形状作为新试点模板。

一份插件可以贡献多个 UI 单元和动作。贡献和动作使用自己命名空间下的稳定 id；标题、位置和图标改变时保持 id。权限引用与贡献所有者由既有宿主核对，作者不自报另一个 owner。

`panel/view/slotItem` 是 UI 条目的种类，不是互斥的插件类型。逻辑功能组写在目录、设计说明或装配清单中，不增加当前根声明的 `group`。菜单项的 `group` 只表达菜单分组。

目标设计中谱面工作区也是正式承载区域，主体视图之外的辅助面板和控件可以选择工作区内部左右固定位置；固定内容不遮挡谱面，小面积菜单采用临时浮层。固定承载配置属于布局编辑，菜单打开／关闭日常可用，临时坐标不保存。工作区位置与原左右侧栏分别表达，自动收放由宿主协调。当前位置校验仍按现有 API 执行；不提前把 stage 写入 panel.slots，也不通过私有 DOM 实现工作区承载。

### 3.2 工厂与固定会话

作者提供创建声明的工厂，每个新运行会话重新调用。模块导入和声明创建不申请 DOM、监听、计时器或其他需要释放的资源。声明复制和冻结不会复制函数闭包；重复使用一份闭包可能把上一会话的私有状态带到下一会话。

可信应用启动代码一次性选择 `plugins` 并调用 `createWorkspaceRuntime`。普通组件只取得受限 `ctx`，不取得运行实例、完整 router 或布局 store。每个 root 同时只有一个活跃运行实例。

启动时发生登记或安装错误，本组合根回滚整个集合；组件首次 mount 失败，宿主局部显示故障并清理已登记资源。首批不承诺可选插件安装失败后继续启动的降级策略。

加入／移出已加载的面板、切页和跨栏移动属于内容配置，不改变当前插件集合。停用一个面板也不自动停用所属插件的所有命令。

## 4. 命令输入与结果约定

以下是**新试点插件的作者约定**，不是现有 router 已经执行的通用结果校验。

### 4.1 单一动作实现

按钮、菜单、快捷键引用同一命令。handler 校验自己的 payload；菜单数据和快捷键映射不会代替领域校验。当前快捷键不携带菜单 payload，需要固定目标时应明确一个无参数动作，不能假定菜单参数会被键位复用。

普通组件通过 `ctx.execute` 执行已获准命令。命令的 `enabled` 必须同步、无副作用地返回 boolean，`checked` 同步返回 boolean 或 `null`。宿主只读动作状态有相应失效隔离，但不能把它当作整个执行层已具备严格结果校验。

### 4.2 显式结果

| 情况 | 新作者约定 | 调用方处理 |
| --- | --- | --- |
| 成功 | 显式返回 `{ ok: true, ... }`；附加字段由动作自己的合同规定 | 校验 `ok === true` 及所需字段，再更新反馈 |
| 可预期拒绝 | 返回 `{ ok: false, code: "命名空间下的原因", ... }`；code 非空且稳定 | 按原因显示可读反馈，不继续当作成功 |
| 意外异常／异步拒绝 | 保留异常；调用方捕获并显示失败 | 恢复忙碌状态，按任务合同清理资源 |
| 空返回或结果形状错误 | 新作者不以 `null/undefined` 表示成功或失败 | 调用方报告无效结果，保留必要诊断 |

成功结果可以使用 `count` 等动作专属字段，不强制重写为一个通用数据袋。拒绝码、输入字段和附加输出字段在该插件的说明中列出；宿主已有的 `permission.denied/command.missing/command.disabled` 等原因继续沿用。

当前 router 会把**同步** handler 的 `null/undefined` 兼容为 `{ ok: true }`；异步 Promise 的完成值没有同样归一化，异常也可能向调用方传播。这是当前事实。只检查 `ok` 无法识别所有旧 handler 的空返回，新动作须在 handler 交付验证中证明显式结果，调用方同时核对所需业务字段。

### 4.3 异步与陈旧结果

调用方使用 `await` 及 `try/catch/finally` 处理可异步动作。重复点击是否合并、拒绝或允许并发，在动作合同中明确；按钮 busy 只约束该按钮，不会自动阻止菜单或快捷键提交。

组件释放后不回写旧 DOM；选择目标变化时按该动作需要使用请求标识或代次判断。隐藏是否暂停由任务约定决定。取消等待、关闭窗口及释放 UI，不等于已经提交的业务事务被撤销。

未来真实编辑由领域端口处理版本、幂等及事务结果；不为首批 UI 试点新增一套通用业务路由器。

## 5. 状态与资源所有权

| 状态／资源 | 负责人 | 首批规则 |
| --- | --- | --- |
| 四栏几何、显示及导航 | 工作区宿主 | 按公开动作使用，不由插件直接写 store |
| 面板位置、启用及顺序 | 编排状态与配置编辑会话 | 组件身份和实例不因移动改变 |
| 私有输入、计算及阅读位置 | 对应组件或插件的明确模块 | 不混入布局取消数据；跨会话重新初始化 |
| 真实文档、版本及业务撤销 | 应用服务／内核 | 当前试点不假装已接入这些能力 |
| 事件、订阅、计时器、样式及任务取消 | 创建资源的所属组件 | 取得后立即通过既有清理机制登记 |

mount 同步返回实例对象或空值，不返回 Promise。异步数据在挂载后的任务中读取；实例钩子的同步及返回约定继续依照作者 API。

一个资源只确定一位最终释放负责人。不要同时在 `ctx.onDispose` 和实例 `dispose` 中重复释放同一资源；需要提前停止时使用幂等清理入口。mount 中途失败也应能清理已取得资源。

不可把跨插件协作建立在对方 DOM、模块私有对象、全局变量或复制的权威状态上。首批共享状态需要实际公开的读取、订阅或命令入口；缺少入口时记录接口需求。

## 6. 依赖与能力可用性

当前作者入口没有通用 `dependencies/services/capabilities` 等根字段，也没有公共服务定位器。首次试点优先使用自有命令和宿主明确提供的动作。

命令引用在登记及实际安装中预检；现有预检不是任意依赖图解析器，不能假定对尚未登记的后续插件引用一定有效。确需跨插件命令时，由可信装配清单说明提供者、登记顺序及缺失行为，并验证双方；插件不通过额外平台自装配依赖。

可选 `ctx.confirm` 以实际端口是否存在判断。没有通用 capability 查询 API 时，由宿主接入说明列出支持能力并进行接入验证；作者不调用未公开的 `hasCapability` 等假接口。

能力未开放、依赖缺失、声明无效和执行失败分别记录。不能把“声明被接受”作为“目标已消费”的证明。

## 7. 限制策略与执行依据

| 限制种类 | 当前依据 | 首批如何验收 |
| --- | --- | --- |
| 身份、引用、允许位置及命令权限 | 现有声明、预检及受限组件入口 | 实际拒绝重复、缺失、错误位置及无权限动作 |
| 键位冲突、焦点及输入保护 | 当前键位映射和宿主键盘入口 | 验证同作用域冲突、当前组件认领及输入法／文本输入 |
| 数量、频率、时长及资源预算 | 当前没有覆盖所有作者代码的通用强制预算 | 试点说明实际规模、并发和清理责任，记录容量表现；不宣传为平台已强制隔离 |
| 产品视觉容量 | 当前呈现与产品 UI 要求 | 使用真实浏览器检验已选窗口及内容规模，记录边界 |

候选接口后续分别区分可执行的硬限制、协作取消／预算及仅用于诊断的观察指标。共享主线程中任意同步 JS 的耗时，不能靠一个计时器承诺强制中断；需要硬隔离的场景由执行环境合同解决。

不预设所有插件共用的任意数量或毫秒阈值。每批试点明确实际测试规模；超过该规模的能力不继承已通过结论。出现冲突或容量问题时，由合同决定拒绝、回退或合并，并给出原因。

## 8. 版本与后续迁移

当前受限试点使用既有作者适配器和内部 v1 登记形状；不向根声明添加名称、版本或兼容字段。试点说明可以记录插件实现版本及所用宿主源码修订／文件哈希，这是接入记录，不是运行时已验证的兼容范围。

后续统一协议按应用级平台身份确定插件 id 与 UI namespace 的映射。名称、插件版本和宿主接口兼容要求由统一协议落地；不要为了当前 UI 试点制造第二份所有者身份。

一次公开合同变更应说明：改动字段及行为、旧输入处理、迁移适配及覆盖的旧用例。不得把文档 v0.1 当成内部 v1 之外的新运行协议，也不通过无版本修改宣称兼容全部旧插件。

当前独立预览内有自己的固定登记集合，应用级身份与受限领域端口的接入仍需在新桌面宿主验证。正式接入继续使用主平台的身份及会话边界，不同时维持两套应用级插件管理机制。

## 9. 从文档收敛到测试插件

按下列门槛推进；每项结论注明适用能力和证据。

| 门槛 | 完成条件 | 当前状态 |
| --- | --- | --- |
| D：文档可用于编写 | 职责、开放范围、精确字段、结果、资源和缺失行为明确；示例可重放；没有需要作者猜测的阻断项 | 文档链接及既有5份示例、13条场景已核验；范围与后续决策仍作为评审稿收敛 |
| H：所选接口可消费 | 当前宿主实际挂载或执行；关键拒绝和释放路径有效 | 命令／左右 panel／菜单／局部键位的新增独立及组合逻辑场景通过；真实浏览器仍待验收 |
| P：代表性插件通过 | 每个测试插件经公开入口接入，同会话组合、失败与新会话清理通过；有 UI 时完成真实浏览器检查 | 三个插件已制作，25 项 DOM 替身逻辑场景通过；有 UI 的浏览器检查未完成，P 整体仍未通过 |
| B：所选范围可以扩大 | D/H/P 均通过；该范围的兼容与迁移、容量及支持边界明确，作者无需新增私有接入 | 尚未达到；通过基础试点不自动开放其他候选接口 |

先完成 D，再选择已达到 H 的能力制作测试插件。无需为了基础试点实现所有候选接口；需要缺失能力的测试插件，要先补对应合同与宿主路径。

第一批已制作以下三个测试插件，说明和公开装配方式见 [夹具 README](./tests/fixtures/representative-plugins/README.md)，实际结果及范围见 [本批审查](./evidence/representative-plugin-trials-20261004/review.md)。它们不安装到默认预览：

1. 无界面离散命令：验证空 UI、显式结果、拒绝及一次执行；不申请驻留资源。
2. 双侧可移动面板：验证私有输入／阅读位置、隐藏／恢复、移动／取消及释放。
3. 组合入口面板：按钮、菜单及局部快捷键引用同一动作，验证权限、冲突、同步异常、异步拒绝与陈旧结果；与前两个插件同会话接入。

下一步完成有 UI 的真实浏览器交互与容量检查，再收敛所选范围的兼容和支持边界。旧键盘异步拒绝可能留在旧 runtime 的诊断记录中；本批证明它不更新旧 DOM 或新会话，不将 UI 释放等同任务取消。真实业务、工作区承载及其他候选能力继续按各自门槛推进。

工作区相应能力达到 H 门槛后，增加两类场景：主体视图与工作区左右固定内容共存，验证独立占位、预设位置、容量、自动收栏／恢复、手动开关和尺寸保留、窗口变化及布局取消；谱面小面积临时菜单，验证触发定位、命令权限、输入不穿透、关闭与焦点返回、旧结果清理及不保存临时坐标。自由放置留后续。当前只纳入计划，不用未开放字段制作样例。

工程接入依据 [宿主合同草案](./workspace-host-contract-v0.1.md)：先收敛正式位置映射与统一编排，再分别接阅读空间／自动收放和受限临时菜单。文档中的语义合同不代替精确字段及运行验收；现有命令和侧栏三例无需等待全部工作区能力。

故障通过测试输入或明确的测试替身触发，不给生产宿主加入仅供样例使用的身份特判。样例置于独立测试宿主，默认产品是否装载另行决定。
