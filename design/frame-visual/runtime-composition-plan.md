# UI 包装配入口收口计划

日期：2026-10-03。用户已授权继续分批实施，不创建 Trellis 任务；主会话实现与检查。

## 目标和边界

将 runtime-preview.js 的现有组合根提取为 createWorkspaceRuntime({ root, plugins? })。默认布局、四栏开关/尺寸、栏内配置编辑、原命令处理函数和受限组件 ctx 保持一致。命令、快捷键、菜单、对话框仍是 UI 包内部模块，不增加平台插件。固定启动集合允许额外声明；运行中安装、正式 SDK、多窗口、持久化、侧栏样式、内核业务接入不在本批。

资源在取得时登记；窗口/键盘/呈现订阅及对话框先释放，然后释放视图、组件和命令。启动失败回滚；重复释放无作用；清理失败继续清理其他所有者并报告异常。单个组件 mount 失败保留现有局部错误隔离。独立插件接入测试使用同一个 router 和持久 cell，跨侧栏移动/取消不重挂载或丢失私有输入。

可信应用入口只返回 execute、workspace 只读端口与 dispose，不把内部 router/store/platform 交给普通组件。入口明确当前浏览器 document 的 root 所有权；同一 root 活跃期间禁止重复启动，释放/失败后可重试。

## 执行顺序

1. 保存新批次源码/原框架/废弃产品基线，执行全目录初始回归（267/267 通过）。
2. 抽取装配入口，收口资源生命周期；Shell 构造资源也登记回滚，避免未返回的视图泄漏。
3. 迁移五个历史测试的源码观察到共享测试工具，保留旧断言；生产 API 不暴露测试内部对象。
4. 专项验证默认新旧 DOM、独立插件链路、启动失败、异常清理、重复释放、pagehide/BFCache 和重启。
5. 写模块职责/状态所有者/依赖图，更新作者指南与后续路线。
6. 全目录回归、相关 JS/CJS 语法检查、新范围审计和 no-index diff。保存同期布局改动，审计旧框架与废弃产品未变，不覆盖历史证据。

## 验收限度

DOM 测试只验证结构、属性、实例和事件模型，不能替代真实浏览器像素、原生焦点、IME 与 dialog 模态验收。既有 file:// 工具拒绝不绕过。本批不宣称 UI 已连接真实内核或全部通用插件能力完成。
