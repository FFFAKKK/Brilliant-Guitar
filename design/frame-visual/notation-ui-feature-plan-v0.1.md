# 打谱产品 UI 功能核对与实施规划 v0.1

日期：2026-10-04。状态：产品功能评审稿。本轮核对备份默认入口的接线并整理规划，未修改运行代码、布局或样式，未制作测试插件。

当前备份已经形成宿主基础交互，但尚未成为可实际打谱的产品。四栏和组件布局能操作，不代表输入、编辑、文件、播放等业务已经完成。下一阶段应尽早形成真实作品编辑闭环，再按用户任务完善功能和细节。

本文补充 [UI 框架路线](./ui-plugin-roadmap.md)，不新增 manifest 字段、接口版本、位置 id 或资源额度。当前作者能力仍以 [受限试点规范](./plugin-authoring-baseline-v0.1.md) 和 [作者 API](./plugin-authoring.md) 为准。功能分组用于确定产品范围，不要求每一组都登记成独立插件。

## 2. 用常见打谱软件核对功能范围

成熟软件可以帮助我们检查遗漏，但功能广度与某一产品的操作体验要分别评价。这里参考官方说明中的三种侧重，不给全部打谱软件作“功能完善”的统一结论，也不要求首版复制其全部功能。

| 参照 | 官方资料表现出的组织方式 | 对本产品的启发 |
| --- | --- | --- |
| MuseScore Studio | 输入模式中选择时值、输入音符和休止；单个、离散多选及范围选择分别表达 | 必须区分“准备输入什么”和“修改已选内容”，先建立清晰的输入／选择模型 |
| Dorico | Setup、Write、Engrave、Play、Print 分工 | 编曲编辑、排版、播放和输出分别定义状态及入口；本产品无需照搬五个顶级模式 |
| Guitar Pro | 标准记谱／六线谱、吉他技巧、调弦、播放调速与循环、指板等工具 | 吉他相关内容是首个可用版本的重点，不能统一降为通用打谱完成后的附加功能 |

官方参考：[MuseScore 输入](https://handbook.musescore.org/basics/entering-notes-and-rests)、[MuseScore 选择](https://handbook.musescore.org/basics/selecting-elements)、[Dorico 模式](https://www.steinberg.help/r/dorico-elements/6.2/en/dorico/topics/program_concepts/program_concepts_modes_c.html)、[Guitar Pro 功能](https://www.guitar-pro.com/c/14-guitar-pro-features)、[Guitar Pro 界面说明](https://www.guitar-pro.com/docs/gp8/basics/first-steps/main-screen)。资料作为产品功能参照，不作为内部接口或当前实现证明。

## 3. 功能职责如何分配

核心谱面先作为一个重要的 UI 内部插件交付，内部统一绘制、命中、选择、光标和输入上下文。它们共享时序和状态，不为了目录整齐拆成一批互相调用的独立插件。

属性面板、符号工具、吉他工具、播放控件等，在具备独立生命周期、清晰依赖和受限端口后，可以成为平级功能插件。共享同一文档及只读编辑上下文；关闭工具面板不销毁作品，也不创建第二份选择或音乐事实。是否独立仍按 [插件设计原则](./plugin-design-v0.1.md) 判断。

宿主持有承载、布局、焦点、快捷键映射、命令路由及临时界面定位。音乐规则、原子编辑和历史属于应用服务／领域插件／内核；文件和播放分别由对应服务拥有。UI 命令只薄绑定这些能力，不另建统一业务命令总线，也不在 UI 里重写音乐校验。

按钮、菜单和快捷键引用相同离散动作；连续谱面输入可调用获准的类型化编辑端口。一次用户操作按业务语义形成预期的事务与历史结果，不因为有两层适配执行两次。布局配置、用户偏好和乐谱文件分开存储。

## 4. 分批范围、依赖与完成标准

下表是实施建议。已有后台记录需要在接入时核对当前真实实现，不能直接转换为 UI 的“已完成”。“首个技术切片”只检验接线，“首个可用版本”还必须满足基础打谱及吉他任务。

| 功能 | 承担者 | 开放前依赖 | 完成标准 | 顺序 |
| --- | --- | --- | --- | --- |
| 中央真实谱面与阅读 | 核心谱面内部模块；宿主分配视口 | 新桌面组合根、只读投影、真实 `view` 承载与资源清理 | 打开真实文档显示真实对象；缩放／滚动不改文档版本；视口和固定区按位置合同分别验收 | 首个技术切片 |
| 定位、单音符输入及删除 | 核心谱面内部控制器；类型化编辑服务 | 真实命中与稳定对象身份、输入上下文、权限、版本和结果反馈 | 明确目标和输入时值／音高；一次动作产生预期事务；拒绝和过期不显示假成功；投影与下一输入位置一致 | 首个技术切片 |
| 撤销、重做 | 核心谱面动作绑定；内核历史 | 真实业务编辑及历史可用性读取 | 撤销恢复音乐数据及相关扩展，重做一致；不回滚四栏布局；无历史时说明不可用 | 首个技术切片 |
| 新建、打开、保存、另存 | 文档入口与受限文件服务 | 文件对话框／IO、文档生命周期、版本化保存检查点 | 保存重开所得作品一致；取消对话框不改文档；写入失败保留未保存状态；保存期间有新编辑时不误标整个作品已保存 | 最小作品闭环 |
| 日常输入和选择编辑 | 核心谱面内部模块 | 已验收的单音符路径、相关领域语义 | 音符／休止、和弦、时值与附点、升降号按批准范围输入；单选／范围／多选及复制粘贴有明确语义；一次编辑的历史边界稳定 | 首个可用版本 |
| 结构和属性 | 属性／结构功能插件；领域服务 | 只读选择上下文及获准编辑端口 | 按对象展示合法属性；多选能表达混合值；小节、谱表、声部及拍号／调号按服务能力接入；无选择和不支持目标有解释 | 首个可用版本 |
| 吉他弦品与调弦 | 核心谱面六线谱模块；吉他工具插件；吉他领域 | 吉他领域当前绑定、六线谱投影／命中、位置与音高原子编辑 | 选弦品或调弦后，五线／六线显示与音乐事实一致；撤销、保存重开保留；不可达位置或弦冲突有明确反馈 | 首个可用版本重点 |
| 吉他基础技巧 | 吉他工具插件；吉他领域 | 对应技巧语义、稳定音符关系与可读绘制 | 已支持的击弦、勾弦、滑音、普通推弦和颤音逐项验收；删除关系音符时原子清理；未支持参数不伪造 | 首个可用版本重点，逐项接入 |
| 基本播放 | 播放控件插件；播放服务；谱面位置呈现 | 已定义的播放投影、音频资源及控制端口 | 播放／停止、速度、节拍器有真实结果；播放位置与谱面一致；切文档／关闭正确停止和释放；不能播放时给出原因 | 首个可用版本，服务就绪后 |
| 循环和声音控制 | 播放／音色功能插件 | 基本播放、范围、声音与资源能力 | 循环边界明确；静音／独奏／音量与实际声音一致；跟随播放可关闭；缺音源或加载失败可见 | 日常打谱完善 |
| 符号、连音与更丰富结构 | 符号工具及相应领域服务 | 对应语义、适用目标、绘制、历史和必要播放支持 | 选择目标后可预览／应用；不合法目标拒绝；连音、力度、表情、反复等逐类声明支持程度 | 日常打谱完善 |
| 多页导航与排版 | 核心谱面／排版内部模块；排版服务 | 真实文档与分页投影 | 按页／小节定位准确；改变纸张或间距有真实重排；选区、光标和阅读位置按明确规则保持 | 日常打谱完善，再扩展精细排版 |
| 打印、PDF、交换格式 | 输出入口；格式／文件服务 | 稳定排版与各格式能力 | 输出文件可重新读取或独立检查；保存作品与导出副本语义清楚；未支持技巧和格式损失逐项告知 | 输出批次 |
| 键位、偏好与布局恢复 | 共享映射和配置模块；设置入口 | 稳定 id、已确认配置及版本化存储 | 改键立刻生效；冲突可解释；重启恢复；缺失插件安全回退并保留配置；损坏配置有明确恢复方式 | 日常使用完善，按稳定合同分批 |
| 工作区辅助内容与临时菜单 | 宿主；实际业务消费者 | 固定区／临时菜单各自承载合同 | 固定内容不遮挡谱面；自动收栏及用户手动调整保留；临时菜单按锚点关闭／定位并复用权限和动作 | 各自门槛满足后，随业务接入 |

首个技术切片不同时扩大到 MIDI、全部技巧、复杂排版或多种谱式。它通过后，六线谱、基础弦品和调弦应进入首个可用版本；这两种范围不能互相替代。

仓库吉他 V1 记录包含六弦调弦预设、弦品位置和上述五类技巧；变调夹编辑命令、泛音、闷音、预推弦／释放等仍各有后续边界。技巧的领域支持也不等于真实播放已支持。接入依据见 [吉他领域 V1](../../docs/guitar-domain-plugin-v1.md) 与 [第一方吉他范围](../../docs/guitar-first-party-plugin-research-v1.md)。

## 5. 每项功能还要补哪些交互细节

能完成正常流程，只算功能接通。是否可日常使用，还要覆盖以下与该功能有关的情形，不把所有候选功能一次性塞入同一批次：

- **入口与状态**：按钮、菜单、快捷键使用同一动作；当前模式、有效键位、选中和禁用原因可读。不支持的操作不呈现可点击的虚假成功入口。
- **输入语义**：清楚区分浏览、选择、音符输入与布局配置；时值选择对下一次输入的影响明确。中文输入法、文本输入及焦点切换不误触音乐命令。
- **选择与属性**：对象消失后不保留可写的失效目标；多选显示混合属性；范围边界可辨认；取消临时菜单不取消组件布局会话。
- **等待与失败**：加载／计算／保存有状态；结果过期不覆盖新文档或新选区；提交结局未知先核对，不自动重发可能已执行的编辑。错误反馈不改变原业务结果。
- **文档保护**：有改动时关闭／切文档的选择明确；保存取消和写入失败不丢工作；自动保存、崩溃恢复及损坏文件处理作为文件服务的独立验收，不用保存标记替代。
- **阅读与空间**：长谱、长面板、空文档、小窗口和不同缩放均有可读表现；固定工具不覆盖谱面，不擅自改变用户缩放；自动收放不反复振荡。
- **焦点与可访问性**：常用流程能用键盘操作，焦点与控件名称清楚；对话框关闭恢复触发点，浮层点击不穿透。涉及系统输入和原生焦点时补真实环境证据。
- **资源与规模**：切文档、隐藏、释放后不遗留监听、旧请求或音频；记录实际文档规模和响应耗时，再确定产品支持范围，不从静态图或单音符测试推导大谱性能。

完成状态分别记录为“仅设计”“代码接通”“实际端到端通过”“真实交互验收通过”。本轮是代码接线核对和规划；不增加业务端到端或真实浏览器通过记录。

## 6. 接下来具体怎样推进

1. **完成有限试点核验。** 文档评审收敛后，在当前已开放范围验证无界面命令、双侧可移动面板、组合入口面板三个样例及同会话组合。只检查当前合同和失败清理，不因此扩张全部候选接口。尚未开始制作。
2. **建立新框架中的真实谱面入口。** 从备份构建最小新桌面组合根，复用可信宿主；明确只读投影与类型化编辑服务边界。中央承载先验证真实文档，工作区固定区与小菜单按 [宿主合同](./workspace-host-contract-v0.1.md) 分项实施和验收。
3. **交付最小作品闭环。** 打开真实作品 → 定位 → 输入／删除一个音符 → 撤销／重做 → 保存 → 新会话重开。每一步使用真实服务；端口替身只用于故障测试。闭环还要有拒绝、过期、取消和写入失败的可见结果。
4. **形成吉他首个可用版本。** 完善日常选择／输入，接六线谱、弦品、调弦、基础技巧与属性；播放按真实服务就绪程度推进。以几段真实吉他练习和完整编辑任务验收，而不是只数按钮或插件数量。
5. **再扩展完整工作流。** 按使用证据完善播放练习、复杂符号、精细排版、打印／交换格式、设置恢复和侧栏样式。自由放置、热插拔、多实例及更多谱式继续单独评估。

基础样例验证作者合同，真实作品闭环验证架构是否服务于产品，吉他任务验证本软件的重点是否可用。三者分别验收；没有任一份结果可以证明其余范围已经完善。

## 7. 对现有界面和插件设计的影响

本轮只增加功能规划与文档导航，备份的已接受画面保持当前运行实现。后续真实内容填入已约定的宿主区域；每次新增按钮、属性、固定区或样式都列出具体视觉变化并独立验收，不以“功能完善”为由整体重做布局。

新增功能优先消费共同命令、快捷键、编辑上下文、反馈和受限服务端口。职责紧密的谱面子功能保留内部模块，独立工具按生命周期和依赖条件拆出；不新增命令平台插件，不让所有小功能互相访问私有状态。

文档与源码检查证据见 [本轮核验记录](./evidence/notation-ui-feature-plan-docs-20261004/review.md)。后续实施前按所选范围补足实际合同和验收，本文不会自动开放当前尚未消费的接口。
