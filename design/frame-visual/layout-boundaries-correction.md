# 侧栏使用与组件布局配置的边界修正

2026-10-02。用户明确：上／下／左／右四个栏是通用承载区域，开关随时可用；栏内组件的添加、移出、移动、排序与样式配置才受布局编辑模式约束。下侧栏不使用声部、正文等业务名字。沿用不建任务的选择，只在 design/frame-visual 修正，保留同期视觉组件，不改原 frame 或废弃 workbench。

本轮会让共享布局页的四个区域开关与标题栏／栏头入口使用同一普通操作。普通收放不记为组件布局修改，取消组件编辑不恢复旧的开关状态；确认不要求全部侧栏保持展开。临时显示编辑操作条不能覆盖上侧栏的真实开关选择。

用户已明确选择“开关和尺寸都随时可用，编辑模式只管栏内组件配置”。手柄、尺寸输入、单项恢复和几何排布均为日常操作，不进入组件回滚基线。组件编辑差异列表不统计四栏开关、尺寸和几何排布；区域名称统一为上／下／左／右侧栏，内部 voice 标识保留兼容。

上侧栏按真实 topOpen 收放，进入组件编辑不强制展示它。布局页内增加同一会话的确认／取消入口，上侧栏关闭后仍可结束编辑；原上侧栏动作保留为同一命令的入口。原界面结构、CSS 和尺寸常量保留，新增动作复用已有控件样式。

验证：普通模式和编辑模式均能实际收放四栏；所有开关入口同政策；开关与输入、选择、阅读状态不随组件取消回滚；组件配置仍有模式与权限检查；现有视觉组件身份与尺寸约束保留；运行与视觉样稿名称一致。保存新基线、差异和当前回归，不覆盖前批证据。DOM 替身不代表真实浏览器视觉验收，现有 file:// 工具拒绝不绕过。

## 命令与取消合同

region.toggle、region.configure（显式设置兼容）、region.resize、workspace.arrange 在所有模式可用。只有 sidebar.panel.move/enabled/reorder 需要活动组件编辑会话，后续组件添加/移出、占宽、图标与承载样式接相同入口。取消恢复组件配置并结束 adjusting，保留当前四栏显隐、尺寸、arrangement、视口、导航和业务状态。每个命令继续使用原同一 router，没有新增平台插件。

无组件编辑时：有效四栏操作成功；有效组件配置经 router 返回 command.disabled，直接 handler 返回 layout.edit-required。编辑中：组件变更预览，确认保留，取消恢复组件基线；日常四栏操作始终保留。非法参数和作者不允许的位置继续拒绝；组件恢复或模式退出失败仍原子恢复操作前快照，允许重试。

错误做法：把组件编辑当成整个工作区的冻结模式，取消时还原所有显隐和尺寸。正确做法：把日常工作区使用与组件配置分开，使用 adjusting 作为唯一组件编辑模式。

本次没有实现新的内容管理或侧栏样式选择，也没有扩大旧作者 slots。当前实际编排仍为左右侧栏的已登记内容，上／下侧栏的真实内容管理须在后续接入时归入同一配置入口；占位内容不能算实际插件接入。
