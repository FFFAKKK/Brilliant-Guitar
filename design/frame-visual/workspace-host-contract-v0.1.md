# 谱面工作区宿主接入合同草案 v0.1

日期：2026-10-04。状态：新增工作区位置、自动收栏及临时菜单仍为工程接入草案；单一中央 view 与宿主阅读缩放已实现，当前差距见第 9 节。`v0.1` 是文档版本，不是新增的 manifest、Facet 或 SDK 版本。

[工作区位置设计](./score-workspace-placement.md) 维护用户要求和交互边界；本文收敛声明语义、状态所有权、实际消费路径及兼容门槛。以下“区域”“区域内位置”等是数据语义，不是可以直接写入当前 `defineUiPlugin` 的新字段。正式键名、位置 id 及协议版本由统一作者合同映射确定。

## 1. 延伸现有装配，不增加插件平台

```text
作者声明 → 原登记与校验 → 原只读贡献目录
                              ↓
                    固定内容编排的唯一所有者
                              ↓
                  区域呈现 → 原组件宿主与实例

原工作区状态 → 区域实际几何 → 主体阅读视口
阅读操作意图 ────────→ 宿主自动收栏策略

菜单贡献／获准请求 → 宿主临时菜单呈现 → 原受限执行入口 → 原 UI router
```

工作区承载、空间协调和临时菜单是 UI 包内部职责，由原组合根装配。主谱面和辅助插件仍平级登记；没有“谱面父插件平台”，也不把每个宿主模块再注册为插件。几何更新和浮层打开不必全部登记为业务命令，配置动作及菜单动作继续使用已有执行链。

## 2. 位置声明采用区域与位置的有效组合

首版预设位置的语义如下。表中位置名称用于评审，正式 id 尚未发布。

| 区域 | 区域内位置 | 承载语义 |
| --- | --- | --- |
| 原左侧栏／原右侧栏 | 各栏当前承载位置 | 保留既有侧栏能力，不转成工作区位置 |
| 中央区域，沿用 `stage` 身份 | 主体位置 | 一个被明确选择的活跃主体视图 |
| 同一 `stage` 区域 | 左侧固定位置／右侧固定位置 | 按宿主公开布局承载辅助内容，独立占位 |

允许位置表示为**有效组合的集合**，不能把允许区域和位置分别列出后直接做笛卡尔积。允许进入原右侧栏和工作区左侧，不意味着同时允许原左侧栏和工作区右侧。

| 作者需要表达的语义 | 规则 |
| --- | --- |
| 稳定贡献及组件身份 | 沿用当前身份映射；位置变化不改变所有者或命令目标 |
| UI 内容形态 | 沿用 `panel/view/slotItem`；实际承载能力另行核对，不新增左右插件等 kind |
| 允许位置组合 | 对所用贡献非空、合法且无重复；宿主核对区域、局部位置和内容适配 |
| 默认位置意图 | 必须在允许组合内；只用于初次配置，不覆盖已有用户选择；旧输入的默认行为保留 |
| 尺寸与溢出需求 | 所提供尺寸必须有限、合法，下限／期望／上限关系一致；只提出需求，不决定全局实际几何 |
| 动作及领域权限 | 沿用明确授予的入口；不能从位置、内容大小或可见性推导权限 |

新增组合的缺省选择规则需要在正式字段合同中明确。旧 `slots/defaultSlot` 的省略与空值规则继续按当前作者 API 执行，不通过本文改成另一种默认行为。临时菜单请求不放进固定位置集合，也不把任意 x/y 当作固定组件的默认位置。

## 3. 四类数据分别管理

| 数据 | 唯一负责人 | 保存及取消边界 |
| --- | --- | --- |
| 贡献能力与默认意图 | 原登记与只读贡献目录 | 固定会话内的声明事实，不由布局页修改 |
| 固定组件实际区域／位置、加入状态、顺序及尺寸配置 | 内容编排所有者，由原布局编辑会话协调 | 确认／取消处理这份配置；跨重启保存另依配置合同实现 |
| 四栏用户开关／尺寸意图，以及自动原因与实际呈现 | 原工作区状态所有者 | 日常手动结果不随布局取消回滚；自动原因属于本次运行的临时状态 |
| 阅读缩放／平移、浮层锚点与打开会话 | 阅读模块及宿主临时界面的各自所有者 | 不混入固定内容配置，也不交给谱面业务撤销 |

同一组件的实际位置在所有承载区域中只有一位写入负责人。工程实现应推广现有编排的适用范围或使用统一编排后投影给侧栏；不能让侧栏 store 和工作区 store 各保存一份同组件位置，再靠双向订阅修补。

公开读取继续是数据快照和订阅，不暴露状态写方法、完整 router、私有 DOM 或其他插件实例。新增描述必须能区分声明支持、用户配置、实际可见及暂时不可展示的原因，不能用一个布尔值同时表示这些含义。

## 4. 固定内容的实际消费与移动

宿主公开预设位置的支持形态、容量、尺寸边界、排列及溢出规则。数量及尺寸边界由宿主产品配置和实际容量验收给出；插件不声明一个更高预算就取得额外空间。

移动或加入时依次核对：固定会话中的贡献及所有者、允许组合、宿主承载能力、目标容量、布局编辑政策及必要权限。无法承载则给出原因并保留原配置；不会先删除原位置再发现目标失败。

成功移动沿用原组件宿主的持久 cell 与实例；首次真正可见时挂载，隐藏不释放，最终释放按原资源规则清理。跨区域移动不能让两个呈现适配器都成为该实例的最终释放负责人。配置更新后由宿主协调一致的可见性与焦点；布局取消恢复配置，不重新创建组件或回滚其私有输入。

主位置的活跃提供者由可信宿主明确选择。不能取加载顺序中的第一项，也不能让一个辅助内容的加入自动替换主谱面。产品必需主视图的移出保护需在宿主配置政策中明确，不用插件名称猜测。

## 5. 空间计算与阅读视口

以原四栏和宿主外壳之后的工作区可用宽度为 A，工作区固定区实际占宽为 L、R，宿主间距为 G，则主体可用宽度由 A − L − R − G 得出。原侧栏占宽已经反映在 A 中，不能再次扣除。没有启用内容的固定区按位置合同释放空占位。

固定区尺寸和主体可读下限共同参与预算；谱纸在当前缩放下的完整宽度不等于主体的最低可用宽度，超过视口仍可以滚动／平移。配置接受前验证预算；窗口随后缩小时保留已确认配置，并按公开的压缩与溢出策略呈现，不静默删配置、迁移组件或改用户缩放。

预算确实不足时，推荐保留不重叠的内层布局，通过宿主限定的溢出浏览方式访问内容；具体外层滚动表现和可读下限由视觉合同及真实窗口验收确定。此项定版前不把任意最小窗口宣传为可完整同时展示所有内容。

主视图消费宿主分配的阅读视口；居中及 `fit` 依据该视口，不能继续用整个窗口中心推导新工作区中的位置。测量及坐标转换由宿主和阅读模块的公开接口协调，辅助插件不通过主谱面私有 DOM 重算视口。

现有宿主的侧栏位置补偿使用原生滚动保留阅读位置；滚动回到起点必须能访问纸张左边缘和上边缘，不能把负平移当作无法返回的裁切。纸张与 SVG 同比例缩放，谱面内部不增加滚动容器。

## 6. 自动收栏的事件与状态合同

用户意图与实际可见必须分开。原读取端口中的 `leftOpen/rightOpen` 等供现有控件使用的字段继续表达对应的实际呈现；新增的意图与自动原因由原所有者管理，具体公开形状随协议定版，不暗中把原字段改成用户偏好。

| 宿主接到的事件 | 状态处理要求 |
| --- | --- |
| 开始本次放大让空间过程 | 记录当前原因并派生实际收起；不将用户开关偏好改为关闭 |
| 同一原因重复到达或测量更新 | 更新必要几何，不反复建立旧快照或重新覆盖手动操作 |
| 用户明确设置开关／执行切换 | 更新该侧意图，优先于本次自动策略；切换以用户看见的实际开关为操作参照 |
| 用户设置已被自动隐藏侧栏为关闭 | 即使实际值相同，也记录明确关闭意图；不能被通用 no-change 分支丢弃 |
| 用户修改尺寸 | 保留动作实际接受的合法尺寸；后续空间造成的临时压缩不反写用户偏好 |
| 某个自动原因结束 | 移除该原因，再按剩余原因与最新用户意图计算；不恢复整份原快照 |

用户选择页面、打开布局配置或执行明确的区域排布，如果同时要求打开或调整某侧栏，也要经过同一意图入口；否则只处理开关按钮会遗漏现有导航的开栏行为。窗口测量、容量夹取等自动更新不能冒充用户调整。纯阅读测量不改变贡献编排。

首版推荐由阅读控制器报告“用户主动放大”的语义事件，宿主据此开始让空间过程，并用空间预算核对恢复条件。窗口大小、纸张像素宽度和 `fit` 重算本身不创造用户放大意图。退出条件推荐覆盖返回 `fit`、主动缩小回本次进入前的缩放参照、明确结束放大及空间满足恢复条件；该参照只用于判定阶段，不用于回滚用户阅读结果。确切事件与条件仍需阅读接口及产品配置定版，不能用某个固定百分比替代。

空间恢复按拟恢复侧栏后的预算核对；条件须避免反复收放。手动展开在本次让空间过程内有效，不能被紧接着的测量再次关闭；预算不足时使用已约定的溢出方式。整个过程由宿主协调，不让每个辅助插件订阅窗口后自行操作侧栏。

## 7. 小面积临时菜单采用受限请求

首版优先收敛右键菜单这一具体形态，不一次开放任意浮层渲染、父级 DOM 或绘制权限。菜单项继续引用已登记命令；位置请求不携带可执行 handler。

请求语义包括：已获准菜单来源、触发点或公开锚点、该动作需要的只读目标上下文，以及焦点返回依据。来源与实例寿命由宿主绑定，不接受作者自报另一个组件 owner。空间坐标只用于定位，不能替代音符／小节身份或文档版本。

执行入口分两种，权限不会因显示在谱面上而扩大：

- 组件发起的菜单：按该真实组件已有的命令权限过滤和执行，复用受限入口。
- 可信宿主装配的工作区场景菜单：按实际贡献、来源和宿主允许的动作集合绑定，复用原 router；普通组件不能取得这一宿主执行能力。

后续聚合其他插件菜单项时，不要求主谱面插件在源码中硬编码每个提供者；由可信宿主按已发布贡献合同装配。普通组件请求不能仅凭一个菜单 id 调用任意聚合集合。跨来源授权及目标上下文合同未完成前，不将这种聚合宣传为当前可用。

静态菜单 payload 与触发上下文不做无规则的对象合并；动作作者明确接受的目标字段及冲突行为。执行时重新核对实例、贡献、权限、动作可用性及业务目标版本。文本反馈、禁用状态和键位提示沿用已有动作读取；参数化菜单项不冒用无 payload 的快捷键提示。

宿主规定菜单面积、内容容量、边界、键盘和输入法规则。触发区域变化时重新定位或按合同关闭；组件隐藏、锚点失效和释放时清理。菜单切换需明确所有权，旧关闭或异步结果不能影响新菜单。Escape 只关闭当前菜单，焦点返回有效入口或宿主回退，不穿透输入音符或取消底层布局编辑。

## 8. 拒绝、失败与暂时不可展示

| 情况 | 处理语义 |
| --- | --- |
| 声明非法、组合重复或默认位置不在允许集合 | 定位到声明条目的诊断；不安装成半有效声明 |
| 宿主没有该位置或消费能力 | 明确能力不支持；保留当前 API 的限制，不接受后默默不显示 |
| 当前配置动作超出容量、布局模式或权限 | 显式拒绝，不提交部分配置；通过原反馈路径表达 |
| 窗口变化使已确认配置暂时受限 | 保留配置并报告当前呈现限制，按溢出合同处理，不当成插件被卸载 |
| 组件挂载失败 | 沿用实例局部故障及已取得资源清理，不改写成另一位置或假成功 |
| 菜单来源失效、命令拒绝、异常或旧结果 | 分别处理关闭／反馈／失效，不能以浮层已关闭宣称业务已撤销 |

正式错误码、结果形状和可选能力查询随公开接口定版。本文不向当前 SDK 添加未实现的错误码或查询方法。已有拒绝码和显式结果约定继续以 [受限试点作者规范](./plugin-authoring-baseline-v0.1.md) 为准。

## 9. 当前实现差距及兼容落点

| 现有落点 | 当前事实 | 工程需要补齐的内容 |
| --- | --- | --- |
| 作者适配器、组件校验、UI Facet | panel 仅左右，view 仅 stage；Facet 清单含 overlay，但组件校验及实际宿主未开放它 | 作者位置组合与规范化、跨层一致校验及版本兼容；不能只放宽 panel 校验 |
| 贡献目录及侧栏编排 | 目录保留身份；左右 panel 与唯一中央 view 已由宿主实际消费，工作区内部两侧固定位置尚未开放 | 有效位置能力投影、跨区域统一位置所有权与更多主体的选择政策 |
| 工作区状态及布局编辑会话 | 开关和尺寸日常使用；会话只取消组件配置；同值 publish 会返回无变化 | 用户意图入口、自动原因与实际呈现分离；把新增固定配置接入原会话，保留日常状态 |
| 几何与 StageViewport | 居中及 fit 使用实际 stage 视口；显式缩放保持比例，侧栏补偿通过宿主原生滚动保留完整纸张访问；缩放不自动收栏 | 工作区固定区预算、放大语义及自动收栏的稳定恢复；保留阅读与业务状态边界 |
| 菜单、动作读取、组件受限上下文 | 当前有顶栏菜单及可选确认，没有通用工作区菜单请求 | 来源绑定、锚点、目标上下文与小面积呈现；沿用命令、权限、焦点及清理 |

当前默认运行以 [workspace-runtime.js](./src/host/workspace-runtime.js) 装配 `workspace-state` 和 `sidebar-composition-state`；另一条使用 `layout-model/layout-store` 的壳路径不能被当作默认预览已经具备的新承载。工程改动按实际组合根接线验证。

旧声明和 UI Facet v1 保持其既有含义。新位置能力的版本协商、适配及“不支持”诊断要一起交付；旧作者适配器不能丢掉新位置元数据后仍报告接入成功。位置迁移沿用稳定贡献／组件身份，不重命名作者插件或无版本重写用户配置。

新增能力由匹配的宿主入口显式接入，和启用新的默认产品编排分开验证。发布位置合同不自动替换默认静态谱面或安装样例；新的阅读视口规则在实际接入中央承载时验收，旧入口继续对照其已接受的画面及交互基线。

## 10. 分批接入与验收

| 顺序 | 范围 | 决定性验收 |
| --- | --- | --- |
| 先核验现有开放范围 | 无界面命令、侧栏面板、菜单／键位的基础试点 | 无私有接入；一次动作、拒绝与清理有效；有 UI 时补真实浏览器检查 |
| 位置合同与主体承载 | 正式字段映射、支持能力、统一编排、主视图及工作区两侧固定内容 | 非法组合／独占／容量拒绝；跨区域单实例；配置确认／取消；默认画面兼容 |
| 空间及自动收放 | 阅读视口、放大意图、原侧栏自动原因与手动优先 | 不遮挡；原开关组合、同值关闭、导航开栏、尺寸保留、窗口变化、防振荡及释放 |
| 小面积临时菜单 | 具体受限请求与宿主呈现 | 来源与权限、目标版本、一次执行、边界／焦点／IME、失效及旧结果隔离 |

新位置与菜单的拒绝／状态逻辑需要可重放的确定性场景；不重叠、居中、容量、滚动、焦点及系统输入需要真实浏览器验收。真实谱面读写另以真实投影和内核事务证明，静态谱面或模拟目标不代替业务验收。

现有开放范围的试点不必等待全部工作区能力；需要新位置的插件必须等相应合同、校验、消费及验证完成。自由放置、多主体、多实例、用户可选侧栏样式和跨重启配置继续按原后续路线推进。
