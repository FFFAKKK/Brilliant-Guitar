# 视图菜单：第 5 批第二步实现与验收

日期：2026-10-03。用户确认菜单映射复用 UI 命令路由器并授权开始。本步只修改 design/frame-visual 备份副本，延续不建 Trellis 任务的选择。计划为 command-menu-plan.md，证据保存 evidence/command-menu/；原型合同同步到作者文档与路线图，正式 frontend spec 仍为 reserved。

## 用户操作与影响

刷新 runtime-preview.html，顶部“视图”可展开。菜单提供上侧栏、左侧栏、右侧栏、下侧栏的开关和“工作区布局…”。七个顶部名称与位置保留；文件/编辑/谱面/播放/插件/帮助保持未接入业务的占位入口。新视觉集中于视图入口启用和展开后的浮层，不重新排布侧栏、谱面或原顶栏。

四栏开关随时可用，勾选分别反映当前区域的展开状态。点击与已有标题栏按钮执行同一 C.region 命令及区域参数，原工作区状态和呈现更新。打开工作区布局使用原 C.page({ id: LAYOUT_PAGE_ID, toggle: false })，打开右侧设置页，不自动开始组件编辑；重复选择也不会收起右侧栏。栏内组件配置仍需要原编辑模式，取消仍只恢复组件配置。

菜单打开期间同步命令可用性、勾选与有效全局键位；四栏勾选不共用一个无参数 checked。界面更新保留仍有效的行节点和焦点，焦点对应项失效时移到可用项或菜单容器。执行前再读取状态与登记身份，失败保留菜单并显示反馈，成功关闭返回触发入口。异步命令执行期间防止重复认领，旧请求完成不会关闭后来打开的另一个浮层。

当前快捷键执行不携带 payload，无法用一个通用 region.toggle 绑定表示四个不同目标。因此带参数菜单项隐藏通用键位提示，无参数菜单动作显示真实有效全局键位；组件局部键位不混入全局菜单。默认入口没有分配新快捷键。四栏独立快捷键可在后续明确目标动作合同后接入。

## 内部结构

```text
原菜单位置定义 + 原 menuItems 贡献
  → 原 menu-registry
  → host/workspace-menus（登记默认项、受限读取与项身份执行）
  → 原 action-state-read-port / workspace.read
  → shell/command-menu-bar（菜单显示与交互）

选择菜单项 → 再读实际状态与当前登记项身份
  → 原唯一 UI router → 原 C.region/C.page handler
  → 原工作区/呈现/持久组件宿主
```

两个新增内部 JS 模块不是平台插件。全局读取名单来自启动时实际菜单贡献，使用全局快捷键上下文；不借用布局组件的权限作为全应用许可。菜单执行只接受原登记项对象，克隆/伪造/已释放项返回 menu.missing；未在当前固定会话名单中的新命令不能隐式取得菜单执行许可。渲染模块只拿数据与受限执行入口，不拿 router、编排写方法或编辑会话。普通组件 ctx 仍为 execute/notify/onDispose。

业务插件沿用原根 menuItems 字段指定 menu/command/label/payload/group/order，平台仍预检位置和命令；默认产品不添加示例插件。新菜单复用原弹出层所有权、控件状态呈现和资源清理，旧 menubar 保留兼容，旧 Shell 省略 menuBinding 时保持原占位结构。原菜单登记、作者协议、原 router/快捷键/handler 和工作区状态不由本步重写。

弹出层外部使用 presentation 语义，内部为 menu；顶栏使用 menubar 并维护一个 Tab 入口。方向键/Home/End 选择，Enter/Space 执行，左右键或悬停切换有贡献的菜单，Escape 关闭菜单，Tab 离开。输入法和修饰键保留，已有宿主键盘保护阻止菜单输入穿透到全局动作。Escape 不取消底层布局编辑。外部点击/焦点离开/窗口尺寸变化、贡献释放与卸载清理监听；旧浮层事件不能影响新浮层所有者。

新增 command-menu.css 只作用于新菜单弹出层，复用主题与原控件皮肤，HTML 增加独立样式链接；本批没有修改已有 CSS，Shell 中菜单接线以外的源码与本批基线一致。同期内容承载设计修改了 content-hosting 样稿状态、视图、结构样稿入口及其 CSS，另有 content-hosting.md；这些修改单独留存，不归入菜单批次，也不回滚。弹出层按实际测量约束位置/尺寸，DOM 替身的几何测试不构成真实像素验收。

## 验证与证据

20 项专项测试通过，原有 213 项与新增测试合计 233 项通过、0 失败。测试装配实际 registry、平台、router、工作区、动作读取、键盘与默认运行入口，覆盖单次四栏参数执行、设置页打开、独立勾选、插件贡献、改键/取消/恢复、全局与局部作用域、参数键位边界、缺失/非法状态/权限/身份、陈旧显示重读、失败反馈/重试、焦点模型与节点保留、导航/输入法保护、浮层所有权、异步一次执行、订阅回滚/重复释放及 pagehide。

7 个涉及 JS/CJS 文件的语法检查与新源码审计见 verification.json、source-audit.json；输出为 specialized-test-output.txt、full-test-output.txt。fresh 基线与原稿为 before-source-hashes.json、before-source/，审阅差异为 review.diff。本步声明 6 个既有文件和 7 个新增文件，证据另存。原审计中的注释误匹配与同期保护范围变动保留为 source-audit-initial.json，随后发现的样稿状态更新保留为 source-audit-followup.json；同期源码副本为 concurrent-source/，记录为 concurrent-work.json。基线没有重写，已登记的保护范围变化逐项核对保存副本，未知变化仍导致审计失败。副本未配置 lint/typecheck，不宣称通过这些工具。

测试证明真实模块装配与提供的 DOM/几何模型，不证明真实计算样式、原生键盘焦点、指针或 IME。既有 file:// 访问拒绝仍有效，本步没有更换协议或浏览器绕过；菜单实际定位、窄视口、键盘与视觉仍待可用且获准的浏览器环境验收。历史 204 项以及其他批次证据保留原含义，不重跑旧审计来覆盖结果。
