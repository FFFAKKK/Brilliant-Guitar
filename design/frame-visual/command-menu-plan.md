# 视图菜单：第 5 批第二步

日期：2026-10-03。用户确认菜单与原 UI 命令路由器结合，授权开始接入。延续不建 Trellis 任务的选择，主会话直接实施/检查，范围限定 design/frame-visual 备份副本。

需求：保留顶部七个菜单的位置/名称，先启用“视图”，提供上/下/左/右四栏开关及打开工作区布局页。开关随时可用；打开设置页不自动进入组件编辑。执行复用原 C.region/C.page，不新增路由器、处理函数、平台插件或状态 store。未来业务插件沿用现有 menuItems 贡献机制。

设计：host/workspace-menus 声明菜单位置、向现有菜单登记贡献默认项，从实际登记的命令集合建立独立的全局动作只读端口，执行只接受当前登记的项身份。四栏 checked 读取各自工作区字段，其他动作使用原 command.checked。shell/command-menu-bar 消费受限数据和执行入口；旧独立 Shell 缺少菜单绑定时保持原占位结构。复用现有 popover 打开/关闭所有权、action-presentation、焦点/键盘保护和 disposal scope；旧 menubar 保留兼容。

菜单打开期间订阅动作与菜单贡献，原地同步禁用、勾选和有效全局键位，保留当前有效焦点。点击前重新读取状态与项身份，命令至多执行一次；失败在菜单内显示反馈并通知宿主。方向键/Home/End/Enter/Space/Escape/Tab、输入法与修饰键保护、外部点击/焦点离开/窗口尺寸变化、关闭/卸载与失败打开清理均纳入验证。弹出层使用菜单语义，不套用模态对话框语义，不阻挡四栏日常操作。

新增样式只作用于新菜单弹出层，复用当前主题与控件皮肤；运行 HTML 加入新样式链接，不改已有 CSS、几何或内容承载。需要真实浏览器检查定位、窄视口与键盘焦点；本会话既有 file:// 拒绝不绕过，DOM 替身只证明实际模块装配与行为。

检查：保存 fresh 哈希/原稿；专项测试真实 registry/router/工作区/菜单/权限范围/插件贡献与默认入口；原副本回归；相关 JS/CJS 语法；审阅 diff 和源码范围/保护审计；作者合同与路线图归档。每批证据独立，旧 action-state 等审计不重新运行覆盖历史结果；同期变化单列，不回滚。

本步不接入文件/编辑/谱面/播放等业务占位功能，不新增默认快捷键、右键菜单、快捷键编辑器、受限对话框能力、持久化或内核编辑。第 5 批仍有对话框及真实原生行为验收待后续。
