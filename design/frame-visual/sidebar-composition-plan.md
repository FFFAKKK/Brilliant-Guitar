# 统一侧栏内容与区域编排：下一批计划

2026-10-02。状态：统一内容合同与独立侧栏编排已实施，58 项相关测试通过。默认入口、外壳、CSS、现有布局状态和视觉 fixture 没有本批迁移；设计侧并发改动保留并单列。

后续进展：呈现接入批次已连接默认入口与 Shell，当前 70 项测试通过，具体范围和限制见 `sidebar-integration.md`。本文件上述状态及历史范围指合同基础批次，不代表当前入口仍未接入。

## 已明确的方向

- 左侧栏、右侧栏是承载区域，其名称不由插件内容或当前展示方式决定。
- 侧栏中的插件内容使用统一抽象，拟采用 `panel` 表示侧栏内容单元。名称、图标、权限和 mount 属于内容单元。
- 页签、网格、列表等属于侧栏呈现样式，不能作为内容单元的长期身份或固定类型。
- 后续预制几种样式，用户通过布局插件选择；这会涉及真实布局样式变化，本批留到后面。
- 保持备份视觉副本为实现位置，保留原件与设计侧并发更新。

## 所有权

| 层 | 管理的内容 |
| --- | --- |
| 内容声明 | 稳定 id、标题、图标、允许区域、权限、挂载实现 |
| 区域编排状态 | 实际所在侧栏、启用状态、顺序 |
| 区域呈现样式 | 页签、网格、列表等渲染规则与样式专属参数 |

侧栏的物理宽度与几何仍由现有布局服务拥有。通用编排不复制区域尺寸，不保存数组索引作为内容身份，也不持有 DOM 或插件实现。`full/half` 是网格样式的规则，不能直接成为所有侧栏样式共用的编排字段。组件内容自身的底部输入区可以继续由其实现拥有；当前外壳消费的 footerHeight 等历史提示需显式兼容，不能被默认为所有侧栏的结构。

## 下一批最小实施范围

1. 调整刚增加的作者适配器和贡献目录，侧栏内容统一为 panel；旧 module/page 记录进入兼容转换，不让新的宿主按左右位置猜内容类型。中央 view 和宿主槽位控件保留其独立职责。
2. 新增独立、可测试的侧栏编排状态，使用稳定贡献 id 表达归属、启用与顺序。允许位置仍来自内容声明，状态变更验证位置合法性。
3. 验证侧栏归属调整和启用变更不会改变内容身份；已有实例的复用、输入保留与最终资源释放沿用现有组件宿主。
4. 保留旧 v1 安装入口、单个前端命令路由及现有默认画面。新编排基础先以独立测试验证，不直接替换设计侧正在维护的容器。

## 验收重点

- 左右侧栏都能承载声明允许进入该区域的统一内容单元。
- 当前所在区域和启用状态属于宿主状态，不修改作者声明。
- 稳定 id 不受名称、侧栏位置或呈现样式影响；移动保留实例私有状态。
- 非法位置、重复身份和无效编排操作有明确结果，失败不修改已接受状态。
- 不引入第二套贡献注册表或命令转发链；兼容入口与此前可靠性合同继续通过回归。
- 源码与证据范围单列，原件保持完整，设计侧并发变化保留。

## 留待后续

预制样式、布局插件提供/选择样式、样式切换的视觉呈现和参数适配，均在后续单独实施和验证。具体页签导航、多列网格、拖拽占宽、样式持久化、布局预设以及真实内核接入不计入上述下一批基础工作。

## 本批合同决策

- 新作者 kind 为 `panel/slotItem/view`；新 panel 只声明左右侧栏，默认启用为 false。旧 `module/page` 输入仍生成原来的 v1 线格式与旧样式提示，目录将内容统一呈现为 panel，不按左右位置猜内容类型。
- 旧顶部、底部内容的允许位置仍在目录中；编排只投影左右侧栏能力。没有侧栏能力的记录不进入本状态，默认位于顶部/底部的混合记录不会自动启用到侧栏。
- 编排使用固定启动集合；快照只有 `id/componentId/slot/enabled/order`。默认 order 仅用于初始化，运行时顺序为区域内连续整数，包含未启用内容，因此隐藏和恢复不会丢失排序。
- 单组件单实例约束保持：重复 panel id 或同一 componentId 的重复编排拒绝创建。以后支持多实例需要单独设计 instanceId，不能用别名隐式开启。
- 操作通过现有 router 的 handler 调用状态方法即可；状态本身没有命令总线。快照冻结，非法操作与无变化操作不通知；观察者异常隔离，重入变更按快照队列依次送达。
- 组件宿主增加可选实例 `setVisible(boolean)` 通知，初始可见为 true，仅在变化时调用。呈现层负责判断实际可见和处理 DOM；通知不等于销毁，也不修改几何或样式。

验证记录与当前限制见 `sidebar-composition.md`。样式选择与默认 UI 迁移仍在后续实施。
