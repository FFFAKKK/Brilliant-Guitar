# 第八批交接索引：布局协作与 UI 插件边界

本索引把当前视觉副本能证明的内容、上一轮候选合同和后续工程门槛放在同一处。它不发布新的 SDK，也不把中性审阅工厂当成正式业务插件。

## 当前已经可以复用的视觉框架

| 能力 | 当前落点 | 责任边界 |
| --- | --- | --- |
| 四区域开合、尺寸和整体排布 | `workspace-runtime.js`、布局页面和视觉副本 | 工作区状态所有者；日常操作立即生效 |
| 栏内内容配置 | 布局编辑会话、现有侧栏编排和 `layout-collaboration-review.html?fixture=movable` | 单一配置事务；确认保留、取消撤回内容配置；无参数入口保持纯视觉 |
| 插件实例保持 | 现有组件宿主与中性 `movable-panel-plugin` | 宿主持有实例；隐藏/移动不重复挂载 |
| 权限拒绝 | 现有受限布局命令 | 命令路由和权限所有者；UI 只呈现结果 |
| 视觉承载 | `structure-preview.html`、`runtime-preview.html` 与共享 tokens | 本视觉会话；透明常态边缘、蓝色选择/焦点、无动画、隐藏滚动条 |

## 当前作者合同与候选合同

当前 `defineUiPlugin` 仍以 `namespace/ui/commands/menuItems/shortcuts` 为作者字段；当前内置布局通过宿主闭包读取内部投影。`layout-plugin-contract-candidate-20261004.md/.ts` 仅是评审稿，不能直接传给当前作者入口。

候选稿提出的共同基础声明包括稳定身份、名称、插件版本和宿主接口兼容要求；贡献与消费分离；读取端口、受限管理命令、编辑凭据/修订号和自身绑定导航均需要正式工程合同后才能开放。可选动画、设置、快捷键、菜单、浮层和功能贡献不要求每个插件填满，空值要被规范化；共同必填项为空则拒绝注册。

## 工程接入顺序

1. 统一字段：确定身份映射、版本规范、宿主兼容范围、缺失/无效/执行失败结果和空值语义。
2. 收敛读取端口：公开布局快照、内容目录、动作可用性和实例状态，只读端口不能暴露 store、完整 router、私有 DOM 或其他插件实例。
3. 保持单一写入者：侧栏编排、布局编辑会话、工作区开关/尺寸、业务状态分别明确负责人；不要为 UI 包再造第二个全局总线。
4. 落地权限与预算：移动、加入、替换提供者、菜单和动画分别检查目标、范围、数量、尺寸、频率、并发、时长和资源清理。
5. 迁移旧入口：兼容现有 `namespace/ui/commands/menuItems/shortcuts`，再发布新字段；旧路由、命令和确认取消语义不能被静默替换。
6. 用真实组件联合验收：验证实例不重建、取消保留私有输入、权限失败可达、陈旧请求不覆盖新状态、最终释放唯一且可重放。
7. 视觉回接：工程合同稳定后才由本视觉会话适配真实组件的承载、容量、焦点、区域和错误呈现；插件内部图标、按钮和动画仍由插件自己的会话设计。

## 本视觉会话仍不承担的内容

- 正式 UI 插件 SDK、版本协商、权限实现、持久化和内核/IPC 接线。
- 具体业务插件和插件内部按钮、图标、配色、内容排版、动画实现。
- 真实 Windows 系统缩放、读屏器、IME 和生产数据闭环。
- 新批准快照的发布；当前任务继续 `in_progress`，等待用户审阅。
