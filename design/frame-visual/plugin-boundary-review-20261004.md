# UI 框架插件边界与耦合复核

日期：2026-10-04。范围为备份视觉框架；本次只修正框架内部焦点依赖并整理交接，不制作具体功能插件、不发布新 SDK、不接内核。

2026-10-05 修订：布局页已以 `frame.layout` 平级登记，按当前 v1 接入宿主受限端口。表中布局页独立登记的设计方向已经落实；共同声明、正式 SDK 和真实业务接线仍未完成。

## 1. 采用哪份规则

[插件设计主稿](./plugin-design-v0.1.md)是后续框架工作的设计约束，当前可执行字段仍以[作者 API](./plugin-authoring.md)和[受限试点规范](./plugin-authoring-baseline-v0.1.md)为准。

- §2、§4：先按职责拆模块；有实际独立装配或替换需求、清晰协作接口和可分开的生命周期时，登记为小插件。一个按钮、文件或 UI 贡献不自动对应一个插件。
- §3、§5：独立插件在同一平台平级登记；消费者使用受限接口，不能导入他人的私有对象、DOM 或内部函数。每份共享状态只有一个写入负责人。
- §7：所有插件共同的基础声明与按需可选扩展分开；同一插件可以同时贡献功能、动画、设置、命令及界面，不按功能给整个插件分类。
- §8、§11：目标能力要同时具备公开合同和宿主实际消费，才可以交给作者使用。视觉样稿和声明被接受都不能代替运行验收。

本复核不新增插件类型、manifest 字段或管理平台。以下清单表达当前责任和接入状态。

## 2. 当前框架的责任清单

| 内容 | 当前责任与实现 | 独立插件及后续边界 |
| --- | --- | --- |
| 登记、所有者绑定、权限、固定启动集合和实例释放 | 同一宿主与组合根装配 | 不再创建子插件平台；普通插件取得受限上下文 |
| 命令、菜单、快捷键、宿主确认及焦点分配 | 包内基础模块，由组合根统一装配 | 功能插件贡献自己的条目并复用原执行链；基础模块暂不分别登记 |
| 四栏开关、尺寸、整体排布及栏内配置事务 | 宿主状态负责人；布局页面通过只读快照和获准命令协作 | `frame.layout` 已独立登记，仅消费这些宿主能力；不能取得布局 store 写权限或保存另一份权威布局 |
| 框架阅读、重绘焦点及承载几何 | 框架内部工具，只操作显式拥有的节点 | 组件本地声明自己的焦点接续和固定头部；不识别具体插件名字，不递归管理私有内容 |
| 框架控件、主题角色和基础皮肤 | 框架自有 UI 及自愿采用的样式 | 插件内部图标、按钮、配色和排版继续自主；承载、焦点与产品几何要求共同遵守 |
| 内置页面 | 副本运行时 `frame.builtin` 提供三个普通内容，`frame.layout` 提供唯一布局页；旧四页组合只服务兼容夹具 | 布局页是独立登记单元；三个普通内容仍属同一 builtin 声明，共同新版声明未完成 |
| 内容、槽位、反馈和方案审阅样稿 | 视觉 fixture 与内存交互 | 用于说明容量、状态和交互，不能作为正式插件接入模板或业务状态所有者 |
| 反馈报告、记录及呈现 | 已有文本 notify；新版本仍是目标合同 | 按[反馈扩展边界](./feedback-extension-boundary.md)分开报告与只读消费。存在独立替换需求的实现可以平级登记；默认实现同样遵守这些接口 |
| 真实谱面、编辑、选择及光标 | 本副本仍是静态谱面 | 由对应会话实现；首版可以先在核心谱面插件内部按职责拆分，符合主稿 §4 时再提取平级插件 |

当前组合根为 [workspace-runtime.js](./src/host/workspace-runtime.js)，内置声明为 [builtin-pages.js](./src/features/builtin-pages.js)。本轮只读核对，未修改这两份工程实现。

同期工程会话已制作三个代表性试点插件；当前[作者规范](./plugin-authoring-baseline-v0.1.md)记录25项逻辑场景通过，有UI的实际浏览器验收仍待。它们使用已开放的命令／panel合同，不代表本表中的未来扩展全部开放。本轮保留其实现、测试和作者规范更新，未制作或修改这些具体插件。

## 3. 本轮发现并修正的具体耦合

公共 [frame-accessibility.js](./src/shell/frame-accessibility.js) 原先写死布局按钮的 ID 对应关系，并用 `.v-composer-header` 识别固定头部。这样其他框架组件要复用它时，必须改公共工具或沿用布局组件的私有命名。

现改为组件自己声明：

```text
data-frame-focus-fallback="目标控件ID"  // 原目标失效时的框架内部接续
data-frame-focus-inset                  // 所属阅读容器内的框架固定头部
```

[布局组件](./src/shell/workspace-layout-visual.js)声明编辑入口到取消、确认／取消到编辑入口的接续，并标记自己的固定头部。公共工具不再知道这三个布局 ID 或布局头部 class。

回退候选必须在当前 root 内且带框架所有权标记；私有或 root 外目标不被认领。缺少声明时继续使用原宿主区域开关／舞台回退。阅读避让只调整所属框架阅读容器，谱页和整页不随焦点移动。具体条件、失效行为与验证点集中维护于[键盘视觉合同](./accessibility-visual.md)。

这是框架内部协作约定，不是给插件发布任意 DOM 目标的 SDK。正式插件仍使用当前宿主焦点和生命周期合同。

## 4. 仍未实现的目标接口

| 目标 | 当前事实 | 后续交付要求 |
| --- | --- | --- |
| 共同身份、名称、插件版本和宿主兼容要求 | 当前作者根字段为 `namespace/ui/commands/menuItems/shortcuts`，缺新根级元数据 | 工程定版字段映射、兼容与逐项拒绝行为；内置插件同样适配 |
| 可选贡献的空值规范化 | `ui` 必须是数组；其余集合可省略，显式 `null` 当前仍失败 | 新版在边界规范化可选空值，保留合法 `false/0`；必填空值和无效条目明确拒绝 |
| 无 UI 的驻留能力及资源 | 纯离散命令可登记；没有新的插件根级生命周期合同 | 开放受限功能上下文和释放路径，不借假面板取得生命周期 |
| 动画、共享绘制、跨组件输入、设置和服务提供 | 设计已列能力范围，当前统一作者接口尚未开放 | 各接口落实目标、权限、预算、冲突、缺失、失败和清理后再开放 |
| 反馈可替换实现 | fixture 直接共享预览内存状态，当前 notify 没有新报告／消费合同 | 默认和独立实现消费相同报告／投影边界，替换不要求功能插件改调用者 |
| 中央视图、上下槽位和工作区固定辅助内容 | 有目标设计及视觉样稿，正式入口尚缺相应实际承载 | 按已规划的宿主位置合同接入，证明真实消费、焦点、实例与释放 |

共同基础声明合法、所有可选扩展为空，在目标合同中应合法且不产生虚假占位。必需依赖缺失、提供了非法条目或执行失败必须单独处理，不能用空值吞掉。上述目标不因为本次视觉复测而变成已实现。

## 5. 后续每项框架工作需要通过的检查

1. 写清职责、输入输出、实际独立需求和生命周期，确定是内部模块、UI 贡献还是独立登记单元。
2. 指出真实状态所有者、只读投影、允许写入的命令及权限；其他插件不导入该实现的私有对象或 DOM。
3. 可选无贡献、必需缺失、无效输入、运行失败分别验证；固定集合、版本和提供者冲突显式处理。
4. 初始化中途失败、隐藏、取消、旧请求完成和重复释放不遗留资源、不更新新会话。
5. 新增插件 A／B 和下一固定会话替换提供者时，既有消费者不改实现、不新增名称特判；当前试点和目标新接口分开验收。
6. 默认内置实现遵守同一协作边界；框架不依赖默认提供者的内部类名、按钮 ID 或错误枚举。
7. 保留已确认的产品视觉要求：普通操作谱页稳定、resize 居中、区域不相交、常态透明边缘、蓝色键盘反馈、无可见滚动条和默认无动画。

新增能力超出已发布合同，仍需版本化扩展宿主；低耦合不等于承诺任何未来功能都无需修改框架。

## 6. 对既有成果和下一阶段的影响

第一至第七批已交付的视觉继续沿用。本轮修复公共工具对布局组件的具体依赖，不重做外壳，也不拆分具体插件。第六批反馈样稿仍仅证明视觉，正式迁移集中在组合根和受限边界，不让功能插件依赖呈现实现。

第八批交接先加入插件合规复核：逐项列责任、登记关系、公开依赖、状态所有者、已实现／未开放能力及替换验收，再汇总视觉规格和状态索引。共同新版声明、null 规范化及正式服务接线交工程；具体插件继续由对应会话制作。整个视觉任务保持 `in_progress`，新批准快照等待用户审阅认可。
