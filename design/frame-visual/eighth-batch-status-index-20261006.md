# 第八批状态索引：视觉框架与插件边界（2026-10-06）

这份索引只描述备份视觉框架当前已经实现或可验证的承载能力，不发布 SDK，不把视觉夹具当成正式业务插件。

## 当前入口

| 入口 | 用途 | 默认是否装入中性夹具 | 当前验证 |
| --- | --- | --- | --- |
| `runtime-preview.html` | 可复用运行时外壳、核心谱面 view、布局页面 | 否 | 运行时组合与生命周期测试 |
| `structure-preview.html` | 完整八区域、布局状态和视觉场景 | 否；仅显式查询参数启用样稿 | 结构场景、几何和无滚动合同 |

三个入口都属于 `design/frame-visual`。`apps/workbench` 是废弃产品 UI，本任务不读取、不参考、不修改。

## 已稳定的视觉承载合同

| 能力 | 唯一状态所有者 | 视觉责任 | 当前状态 |
| --- | --- | --- | --- |
| 四区域开合、尺寸和排布 | 工作区状态 | 标题开关、把手、布局页控件共用同一快照 | 已实现 |
| 左右侧栏与上下横带 | 外壳几何 | 对称最小/最大值、下栏标题扣除、区域不遮挡工作台 | 已实现 |
| 谱面工作台 | 阅读视口/宿主 | 居中、固定谱面矩形、侧栏不覆盖、页面级滚动隐藏 | 已实现并有逻辑回归 |
| 工作区布局页面 | `frame.layout` 视觉页面 | 只呈现宿主只读投影，内容编排通过受限命令协作 | 已实现为当前 v1 运行形态 |
| 内容编排 | 侧栏编排与布局编辑会话 | 加入/移出/排序/占宽统一确认取消，实例复用 | 已有逻辑与中性审阅 |
| 插件私有内容 | 插件自身 | 插件按钮、图标、颜色、排版和动画自主 | 边界已定义，具体插件交其他会话 |

结构夹具和运行时外壳现在都通过 `src/shell/workspace-shell-geometry.js` 投影区域 CSS 变量，避免入口之间重新出现滑条、横带或谱面位置漂移。

## 2026-10-06：职责盘点与动画闸门

当前视觉职责的主要实现已经收敛；仍未完成的是真实浏览器像素验收、Windows 系统缩放和用户批准快照。正式插件声明、布局插件真实接入、内核/错误反馈链路和具体插件内部视觉交给其他工程会话。

动画可以进入规范和样稿阶段，但当前默认无动画基线继续保持。候选动画只能发生在已确定的区域内部，不能动画化外壳尺寸、谱面位置、谱面缩放或跨插件布局。动画必须支持宿主关闭、reduced-motion、取消、卸载清理和权威状态驱动。完整交接清单见 `handoff-20261006.md`。

## 当前最小协作面

当前运行时仍使用既有 v1 作者字段：`namespace`、`ui`、`commands`、`menuItems`、`shortcuts` 和受限 `mount` 上下文。工作区布局页面以 `frame.layout` 平级登记，读取宿主提供的 `layout`、`contents`、`actions` 投影；其他插件只声明自己的 UI 贡献，不调用布局页面 DOM，也不写布局状态。

规划中的共同身份、插件版本、宿主兼容字段以及功能、输入、绘制、动画、设置、菜单和快捷键等可选贡献仍是工程候选能力。可选贡献为空或 `null` 时应被规范化；共同必填声明为空时应拒绝安装。此规则目前是设计合同，不应被写成已发布运行 API。

## 交接前必须保持的边界

1. 框架只拥有外壳、区域、布局入口、焦点、滚动和受限命令呈现。
2. 布局页面不进入普通模块库，也不承载普通插件组合内容。
3. 插件内容不接收完整 store、router、谱面私有 DOM 或其他插件实例。
4. 工作区开合/尺寸/排布是日常操作；栏内内容配置才进入布局编辑事务。
5. 取消布局编辑只撤回内容编排，不回滚用户期间的区域调整、谱面输入或阅读位置。
6. 外部插件内部视觉、动画和业务错误呈现不在本会话实施。

## 验证状态

- `npm test --prefix design/frame-visual`：当前 386 项通过。
- 布局组件局部不再声明过渡动画；四行区域控件合同已固定为图标开关、滑条、数值输入、`px` 和恢复按钮，区域关闭时尺寸控件真实禁用。
- 共享几何投影、三个入口样式加载和页面级滚动合同已加入测试。
- 工作台视口回归覆盖四类区域几何变化，并验证内部原生滚动补偿不会改变谱面屏幕矩形。
- 1440×900、1280×720、922×720、800×600 等逻辑窗口范围已有几何覆盖。
- 真实 Windows 100/125/150/200% 系统缩放、真实读屏器、IME、高对比度和最终视觉批准快照仍未完成。
- 浏览器自动化环境本轮无法写入 kernel assets，因此不把真实像素检查标为通过。

## 下一道工程闸门

正式插件工程需要先定版共同声明、版本迁移、只读端口、权限/预算、生命周期和替换规则；再用真实插件替换中性试点，最后回接当前美术并复验容量、焦点、谱面位置和错误反馈。没有完成这些步骤前，不新增默认业务插件、不发布 SDK、不修改废弃产品 UI。
