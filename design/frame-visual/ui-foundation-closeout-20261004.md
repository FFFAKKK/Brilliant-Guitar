## 2. 保留的用户决定与状态所有权

- 实施以备份框架为基础，原 `design/frame` 与准备废弃的 `apps/workbench` 不作为新 UI 实施入口。
- 上／下／左／右四栏使用通用名称；开关、尺寸及几何操作日常可用。布局编辑只管理约定的固定组件配置，取消保留四栏日常调整、私有输入及音乐编辑。
- 命令、快捷键、菜单、焦点、布局会话属于 UI 包内部模块，由同一组合根装配。功能插件可以贡献自己的动作；不将路由器另注册为平台插件。
- 离散入口引用同一动作；连续谱面输入可经获准的类型化编辑端口。适配层不会成为第二份业务命令实现或第二套音乐历史。
- 核心谱面先统一绘制、命中、选择、光标与输入；符合独立生命周期和依赖条件的辅助功能再拆为平级插件，不新增父插件管理层。
- 谱面工作区内部左右固定区与原左右侧栏分别占位。后续放大由宿主协调原侧栏收起，恢复保留用户期间的手动开关及尺寸；小面积临时菜单日常可用，位置不落入持久布局。
- 首版采用宿主预设位置。侧栏样式选择、自由放置、热插拔、多实例及更多谱式继续分批，不扩大当前作者可用字段。
- 音乐事实与历史归领域／内核，文件和播放归相应服务；布局、偏好、乐谱分别存储。功能插件不访问其他插件私有状态，也不自行修改全局几何。

这些是后续接入应保持的设计边界，不表示表中所有未来能力已经实现。

## 5. 下一步的限定交付

下一批只做当前已消费能力的三个测试插件：无界面离散命令、双侧可移动面板、组合入口面板。详细场景与 D／H／P／B 门槛集中维护在 [试点规范第 9 节](./plugin-authoring-baseline-v0.1.md)，不复制第二份完整合同。

它们使用独立测试宿主和公开作者入口，默认产品不安装这些样例；没有新增中央位置字段、反馈协议或驻留能力的前置依赖。分别验证正常、拒绝、异常、移动／取消、隐藏／恢复、释放、旧异步完成和新会话，再做同会话组合；有 UI 的范围补真实浏览器记录。

通过后才扩大相同接口范围。下一条产品主线是从备份构建新桌面组合根，接真实只读谱面，然后完成“打开 → 定位 → 输入／删除 → 撤销重做 → 保存 → 重开”的作品闭环。基础插件试点不替代这一业务验收。
