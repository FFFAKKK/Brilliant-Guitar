## 已实现的边界

```text
页面 / 外壳按钮 ──→ 原有 command-router（同一个实例）
                         │
                         ├─→ 工作区 handler → 布局状态
                         └─→ 视图 handler   → 谱页视图控制器

布局状态 → 只读快照 / 订阅 → 页面内容与外壳
单份内置组件声明 → 原插件平台 / UI host → 注册表 → 页面本
组件宿主 → 每个稳定 id 一个持久 DOM cell
```

前端路由是操作入口；内核 CommandBus 是谱面语义写入、事务、版本和撤销的执行边界。将来谱面操作采用 `UI → 同一前端 router → 应用服务 → CorePort.submit（一次）`。布局命令只影响前端状态，不能进入谱面撤销栈。无需再加一套前端总线来转发同一事件。

本批没有内核调用。测试中的文档 handler 是计数替身，只证明前端布局处理不会顺带执行文档操作，不能代表真实 CorePort 集成完成。保存、播放和业务菜单仍未接通。

## 几何与事务规则

初次进入和主动缩放才计算纸宽；布局操作保留谱页的屏幕 XY 和宽高；窗口变化重新水平居中，保留纸宽和屏幕 Y。舞台与侧栏独立分区，空间不足时在舞台内部裁切和滚动。1024px 画布下双侧栏总宽约束为460px，留出44px图标栏、40px页签条和480px舞台。

工作区调整开始时保存显隐、尺寸和排布基线；重复开始不会覆盖基线。取消还原，确认保留，结束时恢复进入前的顶部状态；当前页面保持布局页。取消/确认后的焦点返回当前页签。窗口变化后还原事务仍受当前可用空间约束。

实际检查发现浏览器在窗口增高时先自动钳制滚动，随后才触发 resize。新视图控制器记录同一窗口内的主动滚动基线，窗口尺寸变化时使用前一屏幕位置补偿，避免滚动钳制造成纵向跳动。新增回归测试覆盖这一顺序。
