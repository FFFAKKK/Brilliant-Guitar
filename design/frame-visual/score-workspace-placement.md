# 谱面工作区中的插件位置与承载

日期：2026-10-04。状态：目标设计草案；当前作者 API 和运行宿主尚未开放本文新增的位置能力。

用户已确认实施顺序：第一版先提供宿主预设位置，之后增加自由放置。首版辅助内容采用工作区内部左右两侧的固定承载，以及右键菜单等小面积临时浮层。放大时原左右侧栏收起让空间；退出放大或空间恢复后恢复原状态，并保留用户期间的手动调整。以下能力仍需工程实现；本次只完善合同设计。

工程接入的声明语义、统一位置所有权、空间预算、用户意图入口、菜单来源及兼容落点集中在 [宿主接入合同草案](./workspace-host-contract-v0.1.md)。本文维护用户要求，不复制另一份作者字段表；合同草案也尚未向当前 API 添加字段。

本产品的中央工作区目前用于谱面，因此本文称为谱面工作区。它是宿主承载区域，主谱面视图是区域中的一项内容；其他插件可以在获准位置提供固定工具、辅助面板或小面积临时浮层。固定辅助内容与谱面阅读视口分别占位，保持谱面可读。

## 1. 区域、内容和位置分别表达

```text
工作台宿主
  ├─ 上／下／左／右侧栏
  └─ 谱面工作区
       ├─ 左侧固定插件区 ─┐
       ├─ 主体阅读视口   ─┼─ 分别占用布局空间；固定插件不遮挡谱面
       ├─ 右侧固定插件区 ─┘
       └─ 临时浮层：右键菜单等小面积内容，可局部覆盖谱面
```

上图表示承载关系，不是父插件管理子插件。所有独立插件仍由同一平台登记，组件由同一宿主管理。

横向关系为“原左侧栏｜工作区左侧固定插件区｜谱面阅读视口｜工作区右侧固定插件区｜原右侧栏”。原侧栏收起会增加工作区可用宽度；工作区插件不接替原侧栏的区域身份，也不因自动收栏把原栏内组件搬入工作区。

| 概念 | 回答的问题 | 设计要求 |
| --- | --- | --- |
| 内容身份及形态 | 是哪个贡献，提供视图、面板还是控件？ | 身份稳定；不因位置改变而变成另一插件 |
| 允许区域 | 可以放在左右侧栏、谱面工作区等哪些区域？ | 作者声明可适配区域，宿主核对真实承载能力 |
| 区域内位置 | 放在该区域中的哪个位置，采用什么位置参照？ | 宿主持有实际配置；作者提供能力和默认意图 |
| 权限及领域能力 | 可以读取或修改什么？ | 由已授予端口和动作决定，不从所在区域推导 |

主谱面之外的内容不必一律声明成主体 `view`。目标合同允许适配工作区的面板或控件选择该区域，也允许适配多个区域的同一内容跨区域放置。内容类型、允许区域和承载方式分开校验；并不要求所有内容都能进入所有区域。

当前内部 `stage` 已表示中央区域。后续合同优先沿用或明确映射这一身份，不因为产品显示名称为“谱面工作区”再制造重复区域。正式字段及位置 id 需要协议评审；本文不用伪造的可执行声明提前确定它们。

## 2. 位置的目标表达

作者说明至少包含：允许区域、可适配的位置方式、默认位置意图，以及需要的尺寸和溢出能力。宿主配置保存用户实际选择；作者默认值不覆盖用户已确认选择。

| 位置方式 | 含义 | 需要固定的合同 |
| --- | --- | --- |
| 宿主预设位置 | 使用稳定的位置 id，例如工作区中的工具位置或边缘承载位置 | 位置容量、排序、尺寸、溢出、缺失位置和回退规则 |
| 临时锚定浮层 | 按触发点或公开锚点临时显示，例如谱面右键菜单 | 面积与内容容量、边界、焦点、关闭、锚点失效及清理规则；不保存持久布局坐标 |
| 用户自由位置 | 在允许范围内拖动或设置位置 | 坐标参照、尺寸与边界、遮挡、窗口变化、确认／取消和保存规则 |

第一版的持久布局只使用宿主预设位置；用户自由放置是后续扩展。第一版不让作者用任意 x/y 或私有 CSS 绕过位置规则。位置清单由宿主公开，作者声明允许位置与默认意图，用户实际选择由布局配置管理；不以加载顺序决定覆盖关系。临时浮层的触发坐标属于日常交互输入，不是自由拖放或持久布局配置。

首版预设位置采用主体位置、工作区左侧固定插件区和工作区右侧固定插件区。主体位置供主谱面等主体内容使用，两侧固定位置供适配的工具和辅助面板使用；两侧内容与主体视口分别分配空间，不作为覆盖谱面的固定层。正式位置 id、容量、排列、尺寸与溢出策略在公开合同中一起确定。

固定位置参照工作区可用布局空间，内容不随谱页缩放。窗口变化时宿主重新计算两侧占位和剩余主体视口；空间不足时按公开容量及溢出规则处理，谱面在自己的视口内滚动／平移，不让固定插件压在谱面上，也不擅自缩回用户的谱面缩放值。

右键菜单等临时浮层可以小面积覆盖谱面，由宿主依据触发点或公开锚点定位并约束在可用范围。内容过长时按合同限制尺寸并提供浏览方式，不自动扩展为覆盖整个谱面的固定面板。浮层面积、容量及关闭条件须在开放接口前明确，本文不提前指定数值。获准的谱面元素装饰另用投影及绘制合同，不作为普通固定插件区或临时菜单的实现替代。

后续自由放置继续沿用区域及贡献身份，扩展实际位置配置与约束，不要求用户重新安装插件或改变插件类别。不同内容是否允许自由放置，仍由内容能力与宿主合同决定。

位置不存在、宿主没有对应能力或位置冲突时，给出明确不可用原因；只有合同事先规定时才回退，不静默改放到别的区域。

## 3. 工作区控件与谱面附着内容

位置必须明确参照，避免把工作区控件与谱页坐标混用。

| 内容 | 位置参照 | 滚动／缩放时的行为 |
| --- | --- | --- |
| 工作区两侧固定工具或辅助面板 | 宿主定义的工作区可布局空间 | 按固定区占位，不随谱页滚动／缩放；工作区变化时宿主重新安排 |
| 主谱面视图 | 宿主视口与主体视图的阅读坐标 | 继续由宿主和视图的明确接口协调平移、缩放及阅读位置 |
| 小面积临时浮层 | 触发点或公开锚点，经宿主转换到浮层承载坐标 | 视口变化时按合同重新定位或关闭；锚点失效后不保留过期位置 |
| 附着音符、小节等元素的标注／装饰 | 受限谱面投影提供的元素锚点及坐标转换 | 随对应元素更新；元素消失、版本变化或投影不可用时按合同隐藏或报告 |

附着内容依赖公开投影及绘制接口，不通过查询主谱面私有 DOM 猜坐标。能放入谱面工作区的普通面板，不因此获得音符锚点、共享图层或文档写入权限。

## 4. 宿主、主视图和辅助插件的责任

宿主负责区域内承载位置、实际几何、层次、可见性、焦点和组件生命周期。主谱面视图提供其公开阅读／投影能力并消费真实文档；辅助插件只持有自身内容及获准端口。

首版主体位置使用明确选择的一个活跃主体视图；后续多主体视图另行设计。多个插件申请主体位置时显式选择提供者或报冲突；辅助位置可按公开容量承载贡献，并明确多项的排列与溢出。辅助内容加入工作区不等于替换或停用主谱面。

跨区域移动沿用贡献和组件身份；支持哪些区域由声明及实际适配共同决定。首版继续保留单组件单实例，不因在工作区显示就自动再创建一个侧栏实例。获准的绘制扩展使用相应接口，其承载可以是宿主图层，不强制等同普通面板 cell。

点击辅助控件或在其文本框输入时，不穿透触发谱面输入。快捷键按实际焦点、所属组件和权限执行；位于谱面工作区不自动取得 `score` 作用域，也不能接管另一插件视图的按键。

### 4.1 原左右侧栏的自动收起与恢复

进入宿主合同定义的放大状态时，由宿主统一协调原左右侧栏临时收起，让空间给工作区中的谱面与固定插件。退出放大或满足约定的空间恢复条件时，解除本次自动收起。插件只说明自己的承载需求，不自行写全局 sidebar/store，也不各自注册自动收栏监听或命令链。

用户意图、自动收起原因与当前呈现由已有侧栏状态所有者统一管理；自动收起是临时呈现策略，不改写用户原有的开关与尺寸偏好，也不卸载原栏内组件。恢复按侧、按属性处理，不整份回写旧快照。手动调整开关时保留该侧最新开关意图；手动调整尺寸时保留最新尺寸，未被手动调整的开关仍按原意图恢复。

| 本次自动收起期间的操作 | 退出放大或空间恢复后的结果 |
| --- | --- |
| 原左栏打开、原右栏关闭，期间未手动调整 | 左栏恢复打开，右栏仍关闭；各自尺寸保留 |
| 用户手动打开某侧栏 | 保留打开；本次让空间过程不立即反复自动收起该侧 |
| 用户明确要求某侧栏关闭，即使它已被自动隐藏 | 记录用户关闭意图，恢复时仍关闭；不能把同值操作当作没有手动调整 |
| 用户只修改某侧栏尺寸 | 保留新尺寸；该侧开关按未被手动改变的意图恢复 |

左右两侧分别核对，手动操作一侧不阻止另一侧正常恢复。四栏日常开关、尺寸操作在自动收起期间仍可用；手动调整优先于本次自动策略。自动原因只在相应条件解除后清除；多个有效原因不能因其中一个结束就错误恢复。

“放大状态”的确切定义、空间检测时机和收起／恢复阈值由工程合同及实际容量验证确定。恢复需核对拟恢复后的空间，避免把收栏自身新增的宽度当作恢复依据；配合稳定的进入／退出条件，避免窗口变化或尺寸测量引起收起与恢复振荡。本文不假定某个缩放百分比必然触发收栏。

### 4.2 临时浮层的动作与输入

临时浮层沿用已有命令、权限及动作状态。右键菜单只是动作入口；实际目标与需要的文档版本按原动作合同核对，不把屏幕位置当作编辑目标，也不复制命令实现或建立第二个路由器。

宿主协调指针命中、键盘、输入法、浮层关闭与焦点返回；控件输入和关闭动作不穿透到谱面输入。Escape 关闭当前获准浮层，不取消底层布局编辑会话；无效触发节点由宿主选择有效焦点回退。触发组件隐藏／释放、锚点失效及异步旧结果按合同清理，旧请求不能操作后来打开的浮层。

## 5. 布局配置与日常谱面交互

目标设计将工作区中固定组件的加入／移出、位置、顺序及相关尺寸配置纳入布局编辑，沿用共同确认／取消。主谱面视图是否为产品必需入口及其保护规则要明确，不能默认把移出辅助面板等同移出主谱面。

四栏开关、尺寸和几何排布仍随时可用。谱面浏览的平移／缩放、选择、输入、插件业务操作及临时菜单打开／关闭也继续按日常交互合同执行，不要求先进入布局编辑。两侧固定插件的承载配置属于布局编辑，其内部业务交互不因此被锁定。

布局取消恢复约定的位置及内容配置，不回滚真实谱面事务、插件业务数据、阅读状态或期间的四栏手动调整。第一版选择预设位置属于布局配置；临时浮层的运行位置不写入持久布局坐标，也不形成待确认的配置差异。后续自由拖动如果用于调整布局，其位置变更属于布局草稿；如果用于业务操作，则由相应业务合同处理，不能混用一套撤销含义。

## 6. 当前事实与接入门槛

当前 `defineUiPlugin` 中新 `panel` 只允许 `left/right`，`view` 只允许 `stage`，`slotItem` 不允许 `stage`。默认入口仍未实际消费中央 `view`。这些是现有实现限制，不是目标设计要求所有辅助插件都只能放侧栏。

本文不使 `slots: ["stage"]` 的面板变成合法当前输入，也不开放坐标、层次或位置字段。后续同时完成作者合同、区域承载和配置路径，再开放工作区能力；只放宽校验不算完成。

当前 `StageViewport.zoom()` 更新纸张尺寸、位置与滚动补偿，尚不自动收放侧栏；中央固定插件区及通用临时浮层也未实现。现有顶栏菜单和命令确认的局部能力，不代表本节工作区承载接口已经开放。

接入前至少验证：

1. 主谱面和辅助内容能够同时承载，贡献身份与权限保持；非法区域／位置、独占冲突及缺失能力有诊断。
2. 移动、隐藏、恢复和布局取消保持实例与私有状态，最终释放清理资源及旧结果。
3. 控件点击、文本输入、输入法与局部快捷键不穿透；业务交互不被布局模式误禁用。
4. 两侧固定内容与谱面视口不重叠；窗口变化、谱页平移／缩放、边界和长内容在真实浏览器中验收，记录坐标参照及实际容量，空间不足不擅自改变用户缩放。
5. 放大自动收栏、退出及空间恢复覆盖原开关组合、两侧独立恢复、手动开关／尺寸与同值关闭意图；连续窗口变化及多重自动原因不引起振荡或错误恢复。
6. 临时浮层的小面积限制、触发定位、边界、键盘／输入法、关闭和焦点返回有效；Escape 不取消布局会话，旧结果及失效锚点不操作新浮层，不保存临时坐标。
7. 需要元素锚点的内容，验证真实投影、元素移除、版本变化及不可用行为；模拟锚点不代表真实谱面已接通。

除原计划中的侧栏／命令样例，后续增加“主体视图与工作区左右固定辅助内容共存”及“谱面小面积临时菜单”两类测试场景，分别检验固定占位与自动收放、手动调整保留，以及临时定位、命令复用与输入边界。它们依赖上述宿主能力，暂不提前实现为默认产品插件；自由放置不纳入首版验收。
